# 需求：上游同步

## 背景与目标

将官方仓库 `upstream/dev` 的最新变更同步到 fork 的长期分支 `win-adapt`，在保留 Windows 适配改造的前提下保持与上游一致，并将验证通过的结果推送到 `origin/win-adapt`。

## 功能描述

### 核心功能

- 拉取 `upstream` 的最新分支与标签。
- 评估 `win-adapt` 与 `upstream/dev` 的提交及文件差异。
- 在合并前审查待引入代码的安全风险并输出变更说明。
- 经用户确认后，以 merge 方式将 `upstream/dev` 合入 `win-adapt`。
- 按“保留 fork 的 Windows 适配并吸收上游变更”原则处理冲突。
- 完成类型检查后，将 `win-adapt` 推送到 fork 的 `origin`。

### 边界与约束

- 不修改 Git remote 配置。
- 不向 `upstream` 推送。
- 不使用 rebase、force push 或破坏性 Git 命令。
- 工作区必须在合并前保持干净。
- 发现可疑代码时，未经用户判定不得合并。
- 合并前必须取得用户对变更说明的明确确认。
- 类型检查失败时不得推送。

## 输入输出

- 输入：本地 `win-adapt`、远端 `upstream/dev`、fork 现有 Windows 适配提交。
- 输出：合并并验证后的 `win-adapt`、推送到 `origin/win-adapt` 的同步结果，以及测试和代码审查结论。

## 非功能需求（性能/安全/兼容性）

- 安全：检查隐私外传、凭据泄露、破坏性文件操作、混淆执行、远程下载执行和敏感认证文件变更。
- 兼容性：保留 fork 已有 Windows 适配行为，不盲目采用任一冲突侧。
- 可追溯性：保留 merge 提交及上游提交历史，不改写分支历史。

## 依赖

- Git 远端 `upstream` 指向 `https://github.com/anomalyco/opencode.git`。
- Git 远端 `origin` 指向 `https://github.com/lshdq/opencode.git`。
- 本地安装 Bun，以便执行仓库类型检查。
- GitHub 网络连接可用。

## 验收标准

- `upstream/dev` 已完整合入 `win-adapt`，且不存在未解决冲突。
- 安全审查未发现未经确认的危险代码。
- fork 的 Windows 适配改造得到保留。
- `bun turbo typecheck` 执行成功。
- 推送目标经确认为 `origin/win-adapt`，且推送成功。
- 独立测试与代码审查已执行并形成结论。
