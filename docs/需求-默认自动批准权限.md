# 需求：默认自动批准权限

## 背景与目标

opencode 上游提供 `--auto` CLI 参数（隐藏别名 `--yolo` / `--dangerously-skip-permissions`），启动 TUI 或 `opencode run` 时自动批准所有未被显式 deny 的权限请求（收到 `permission.asked` 事件时直接回复 "once"，不弹确认）。

目前该行为只能通过每次启动时显式传 `--auto` 开启，没有对应的配置项。目标：新增一个顶层布尔配置项 `auto_approve`（类似 `default_agent`），写入 `opencode.jsonc`（全局或项目级）后，不加 `--auto` 参数启动也默认进入 auto 模式。

## 功能描述

### 核心功能

- 配置 schema（`ConfigV1.Info`）新增可选布尔字段 `auto_approve`，默认缺省（等价 false）。
- TUI 启动（`opencode` / `opencode [project]`）：读取合并后的配置，`auto` 计算变为 `args.auto || args.yolo || args["dangerously-skip-permissions"] || config.auto_approve === true`。
- headless 运行（`opencode run`）：`auto` 计算同样 OR 上配置值。
- 配置开启后，TUI 启动即处于 auto 权限模式（命令面板 `permission.mode` 显示为可 "Disable auto-approve permissions"），运行中仍可手动切换。
- 项目级配置可用 `"auto_approve": false` 覆盖全局的 `true`（配置深合并天然支持）。

### 边界与约束

- CLI 显式参数与配置为 **OR 关系**：任一开启即 auto；不提供 `--no-auto` 式的命令行反向关闭（yargs 无法区分"未传"与"传了 false"）。
- 显式 `deny` 规则（如 `git reset *`、plan agent 的 edit deny）不受任何影响，依然拦截。
- 与 `--auto` 语义完全一致：用户显式配置的 ask 规则（如 `git push *: ask`）也会被自动批准。
- mini 模式（`--mini`）为纯交互界面，权限确认走交互式回复，不读取 `auto_approve`（与 `--auto` 在 mini 下无效的现状一致）；本配置仅作用于完整 TUI 与 headless `opencode run`。
- 仅影响 TUI / run 两个 CLI 入口；`serve` / `web` / `acp` 等不在本次范围。

## 输入输出

- 输入：`opencode.jsonc`（全局 `~/.config/opencode/opencode.jsonc` 或项目级）中的 `"auto_approve": true | false`。
- 输出：启动后权限模式默认为 auto（true 时）或维持现状（缺省/false 时）。

## 非功能需求（性能/安全/兼容性）

- 性能：TUI 启动增加一次进程内 `config.get` 调用（worker 内 fetch，毫秒级），可忽略。
- 安全：配置项等价于长期开启 `--auto`（官方标注 dangerous）；显式 deny 规则仍然兜底。用户全局配置中已配 `git reset *: deny`、`D:/Documents/**: deny` 等规则保持有效。
- 兼容性：本配置项为本 fork 私有扩展，上游不存在；合并上游时需注意保留（win-adapt 文档登记）。不影响既有配置项的解析。

## 依赖

- 修改公开 HttpApi 的 Config schema 后，需按仓库规范在 `packages/client` 执行 `bun run generate` 重新生成 SDK 类型（`src/generated` / `src/generated-effect` 不手改）。
- 用户全局配置 `~/.config/opencode/opencode.jsonc` 增加 `"auto_approve": true`。

## 验收标准

1. 全局配置 `"auto_approve": true` 后，不带 `--auto` 启动 TUI，权限请求自动批准、不弹确认；命令面板中 `permission.mode` 项显示 "Disable auto-approve permissions"（即当前已处于 auto）。
2. 不带配置、不带 `--auto` 启动，行为与现状一致（正常弹权限确认）。
3. 显式 `--auto` / `--yolo` / `--dangerously-skip-permissions` 传参行为不变。
4. 显式 deny 规则（plan agent 的 edit deny、用户配置的 deny 项）在 auto 模式下依然拦截。
5. `opencode run`（headless）在配置开启时自动批准权限请求而非 auto-reject。
6. `bun typecheck`（packages/core、packages/opencode、packages/client）通过；相关单元测试通过。
