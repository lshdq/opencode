# 测试用例：默认自动批准权限

## 测试范围

- `packages/core/src/v1/config/config.ts`：`auto_approve` 字段的 schema 解析。
- `packages/opencode/src/cli/cmd/tui.ts`：TUI 启动时配置读取与 `auto` 计算。
- `packages/opencode/src/cli/cmd/run.ts`：headless 模式 `auto` 计算。
- `packages/client`：生成代码与上游 schema 一致性（`bun run generate` 可重复、无手工改动）。

## 用例列表

### TC-001: 配置 schema 解析 auto_approve

- 前置条件：已完成开发。
- 操作步骤：编写/执行单元测试，分别用 `{"auto_approve": true}`、`{"auto_approve": false}`、缺省三种输入解析 `ConfigV1.Info`。
- 预期结果：三种输入均解析成功；true/false 原样保留；缺省为 undefined。非法值（如字符串）解析失败。
- 优先级：P0

### TC-002: tui.ts auto 计算逻辑

- 前置条件：已完成开发。
- 操作步骤：静态检查 `tui.ts` 中 `run({...})` 调用的 `args.auto` 表达式：确认为 CLI 三参数与 `cfg?.auto_approve === true` 的 OR；确认 config 通过 `createOpencodeClient(...).config.get()` 获取且失败时回退 undefined（不影响启动）。
- 预期结果：表达式与需求一致；失败回退存在。
- 优先级：P0

### TC-003: run.ts auto 计算逻辑

- 前置条件：已完成开发。
- 操作步骤：静态检查 `run.ts` 中非交互分支的 `auto` 计算（`loop()` 内），确认 OR 上 `client.config.get()` 返回的 `auto_approve` 且失败回退 undefined；确认 mini/交互分支不经过该计算（与 `--auto` 在 mini 下无效的现状一致）。
- 预期结果：headless run 遵循配置；mini 不受配置影响。
- 优先级：P0

### TC-007: /config 端点 round-trip

- 前置条件：已完成开发。
- 操作步骤：单元测试：`tmpdir({ config: { auto_approve: true } })` 后 GET `/config` 返回体包含 `auto_approve: true`。
- 预期结果：断言通过。
- 优先级：P0

### TC-004: typecheck

- 前置条件：已完成开发并执行 `bun run generate`。
- 操作步骤：在 `packages/core`、`packages/opencode`、`packages/client` 分别执行 `bun typecheck`。
- 预期结果：全部通过，无类型错误。
- 优先级：P0

### TC-005: 既有测试回归

- 前置条件：已完成开发。
- 操作步骤：在 `packages/core` 执行配置相关测试（`bun test test/config`）；在 `packages/opencode` 执行与 CLI/权限相关测试（按测试命令节）。
- 预期结果：全部通过，无回归。
- 优先级：P1

### TC-006: 显式 deny 不受配置影响

- 前置条件：已完成开发。
- 操作步骤：单元测试或静态验证：`auto_approve: true` 只影响 CLI 传入 TUI/run 的 `auto` 标志位，不改动 `Permission.fromConfig` / 规则评估逻辑（deny 优先级由既有代码保证，无需新代码）。
- 预期结果：确认未触碰权限评估核心逻辑。
- 优先级：P0

## 测试命令

```bash

cd packages/client && bun typecheck

cd packages/client && bun run generate

# 单元测试（不能在仓库根目录执行）
cd packages/core && bun test test/config
cd packages/opencode && bun test test/config
```
