## 决策列表

### DEC-001: 扩大扫描范围
- 阶段：阶段 1 需求澄清
- 背景：用户要求从单个 Windows MCP 类型错误扩大到仓库内相关 `effect/unstable/*` 混用检查。
- 可选方案：仅修复 `mcp-windows.ts`；检查所有相关进程/HTTP 导入；机械迁移全仓库所有 unstable 导入。
- 最终选择：检查所有相关进程/HTTP 导入，并逐模块确认稳定等价物。
- 选择理由：覆盖同类兼容问题，同时避免将仍属实验 API 的模块强行迁移。
- 影响：可能涉及 `packages/core` 的生产代码、测试和 fixture；变更范围仍限制在模块导入与类型兼容。

### DEC-002: 统一类型来源
- 阶段：阶段 2 方案设计
- 背景：稳定 `effect/process` 与旧版 `effect/unstable/process` 的类型包含不同内部符号，不能互相传递。
- 可选方案：增加类型断言；保留两套类型并转换；统一到 `effect/process`。
- 最终选择：统一到 `effect/process` 及其 `ChildProcessSpawner` 子模块。
- 选择理由：消除类型边界，保留类型安全，不改变运行时实现。
- 影响：Windows MCP 适配与直接调用方共享同一 `StandardCommand` 类型。

### DEC-003: 处理无稳定等价物的模块
- 阶段：阶段 2 方案设计
- 背景：`effect/unstable/sql` 等模块可能仍没有可替代的稳定入口。
- 可选方案：强行迁移；保留并记录；删除相关测试。
- 最终选择：无稳定等价物时保留并记录理由。
- 选择理由：避免因路径替换引入 API 或运行行为变化。
- 影响：扫描结果可能仍包含少量有意保留的 unstable 导入。

### DEC-004: 收敛指令发现审查项
- 阶段：阶段 7 后返回阶段 5。
- 背景：独立审查在受影响的 instruction.ts 发现既存文件类型过滤遗漏，instruction-discovery 测试 23 通过、1 失败；与导入迁移无因果关系。
- 可选方案：单独记录后续修复；本轮在同一文件最小补齐文件过滤。
- 最终选择：本轮补齐 fs.up 的文件类型过滤并验证实际目录场景。
- 选择理由：修复位置局部、已有断言明确，消除当前审查应改项和确定的测试失败。
- 影响：非文件 AGENTS.md 路径将被忽略，正常指令文件发现维持原有行为；除此之外不扩展功能。
