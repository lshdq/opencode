## 决策列表

### DEC-001: 来源解析复用 V1 语义，指令状态沿用 V2
- 阶段：方案设计
- 背景：V1 在 `dev:packages/opencode/src/session/instruction.ts` 已支持相对/绝对 glob、`~/`、HTTP(S)，但它依赖 V1 的 InstanceState 和每次请求重拼 system prompt。
- 可选方案：直接迁移整份 V1 服务；通过外部 hook 继续补丁；在 V2 Config/InstructionDiscovery 中引入 V1 来源解析语义。
- 最终选择：在 V2 来源边界实现路径、glob、URL 解析，复用 V2 的 InstructionDiscovery/InstructionState 状态链路。
- 选择理由：避免重复注入和跳过会话移动、压缩、回退的持久化机制，保留 V1 配置兼容性。
- 影响：需要测试来源解析以及持续会话的更新语义，移除外部兼容桥。

### DEC-002: 暂时不可用保留已持久化指令
- 阶段：方案设计
- 背景：V1 将读取或 URL 失败当成空内容跳过，V2 已支持 instruction 来源 unavailable、历史值保留。
- 可选方案：逐字采用 V1 错误跳过；在 V2 链路区分确认删除和暂时不可读。
- 最终选择：沿用 V2 的暂时不可用状态，确认消失后才撤销来源。
- 选择理由：避免一次网络或磁盘故障使活动会话无提示失去规则。
- 影响：错误处理与 V1 不完全一致，需覆盖恢复测试。

### DEC-003: URL 来源在现有发现状态中使用字符串键
- 阶段：生产实现
- 背景：现有 `InstructionDiscovery.File.path` 在 Core 被标为绝对路径，但 V1 的 URL 来源同样需要在这条持久化链路里保有稳定标识及变更历史。
- 可选方案：把 URL 伪装成本地路径（类型含义错误）；新增独立 URL 指令状态及事件（使顺序、去重和移动复杂化）；将 Core 发现文件键改为来源字符串，保留已有 `path` JSON 字段及本地路径值。
- 最终选择：仅在 Core 将发现来源键改为字符串，URL 以完整原始 URL 为键，不修改 Schema 或持久化字段。
- 选择理由：兼容历史状态、沿用现有 diff/恢复机制，同时避免 URL 冒充文件系统路径；HTTP 来源在读取时按需刷新，避免纯轮询滞后。
- 影响：`File.path` 的 Core 类型不再保证本地绝对路径；对外持久化格式不变。HTTP 请求失败时整个发现批次标为 unavailable，恢复后重新比对。

### DEC-004: 对 glob 静默扫描失败保守判定
- 阶段：审查修复
- 背景：npm `glob` 遇目录遍历错误会返回空匹配，与确认删除无法直接区分；V2 已承诺暂时不可用不误撤销已有指令。
- 可选方案：更换 glob 库并引入全量错误感知遍历；只检查以前已匹配但本轮消失的文件及其目录是否仍可访问；接受误撤销。
- 最终选择：在现有扫描边界对历史匹配来源做最小存在性/遍历能力校验，无法确认删除时将发现批次标为 unavailable；保留正常文件删除的撤销行为。
- 选择理由：直接覆盖有状态会话的可证实故障，复用现有来源状态和 `FSUtil`，避免重写 glob 语义。
- 影响：此前已加载的某来源所在目录发生暂时故障时，整批发现暂不可用，恢复后重试；需要模拟扫描静默返回空的测试。

### DEC-005: 配置来源 watcher 按当前来源集合协调
- 阶段：审查修复
- 背景：Location/plugin scope 长驻；配置多次改动会累计不同路径的原生 watcher。
- 可选方案：只在插件销毁时释放；每次配置变更重建整套插件；保留自动 AGENTS watcher、动态配置 watcher 按当前集合订阅和退订。
- 最终选择：按当前有效配置来源协调动态订阅，移除旧 watcher 时关闭其订阅；自动 AGENTS 的固有 watcher 保持独立。
- 选择理由：配置长期编辑是真实场景，订阅/句柄无界增长会影响服务；局部协调能维持原有通知语义且不重启 Location。
- 影响：需要核对旧路径停止产生刷新、新路径继续更新与切换后的资源数有界。

### DEC-006: URL 内部身份与外部显示分离
- 阶段：审查修复
- 背景：`https://...?...token=...` 一类签名 URL 是常见输入；失败日志及模型上下文显示原始 URL，持久化值也含原始凭据。仅修复日志不足以消除真实请求路径中的泄漏。
- 可选方案：沿用 V1 全 URL 可见语义并明确提示使用者；仅去掉日志参数；以不含凭据的显示名和稳定的不透明身份分别处理外部呈现与来源去重，网络请求仍用原始 URL。
- 最终选择：分离外部显示与来源内部身份：对 URL 使用稳定的不透明键，外部显示去除 URL 凭据与查询参数，失败日志不附原始 URL 或可能带 URL 的错误详情。
- 选择理由：避免同路径不同签名的来源错误合并，也不把常见签名参数写入模型消息、日志或可读持久化来源字段；变更集中于 URL 来源边界和发现渲染。相比 V1 原文显示 URL，仅改变 URL 的来源说明文本，不改变实际远端内容、顺序和刷新。
- 影响：URL 来源标签将不包含认证参数；内部来源键需要保持稳定以便更新/移除，并增加签名 URL 回归测试。DEC-003 的“完整原始 URL 为键”由本决策替代；仍保持字符串键与已有本地路径格式不变。

### DEC-007: URL userinfo 不自动转换为 HTTP Basic 认证
- 阶段：独立测试失败处置
- 背景：独立测试给带 `username:password@host` 的 URL 增加了“必须发送 Basic Authorization”断言，真实当前工作区 HTTP 客户端并未发送；V1 `dev:packages/opencode/src/session/instruction.ts` 同样仅调用 `HttpClientRequest.get(url)`，没有编码/设置 Basic 头。既定需求要求迁移 V1 的 URL 行为和保护可见凭据，而未要求增加远端认证能力。
- 可选方案：新实现自动从 userinfo 生成 Basic 头（新增认证语义，需处理重定向凭据转发边界）；拒绝一切带 userinfo 的 URL（额外兼容行为变化）；保持 V1 的 HTTP 客户端请求语义，只验证 URL 不泄漏凭据、不错误暴露 Authorization。
- 最终选择：保持 V1 语义，不根据 userinfo 额外构造 Basic 头；修正超出需求的测试预期，并明确签名查询参数的来源仍可正常加载、显示/持久化来源仍脱敏。
- 选择理由：避免引入未经批准的认证功能和跨域重定向凭据传播风险；现有测试已证实 URL 实际被请求且 query 抵达提供者，唯一失败是测试对 Basic 的扩展预期。
- 影响：需要 HTTP Basic 的规则 URL 不在本次 `instructions` 兼容范围内；不将此类 URL 当作支持鉴权的配置契约。最终独立测试报告须说明此边界。

### DEC-008: glob 遍历错误在来源边界显式上报
- 阶段：二次审查修复
- 背景：热实例的旧匹配核实在重启后失去内存记录；npm `glob` 会吞掉目录 readdir 错误并返回空匹配，从而误撤销持久化规则。
- 可选方案：在 Session 持久化观察中反查上一轮文件列表（跨越 Session/Location 责任边界）；从 glob 字面前缀独立递归遍历目录（每次加载增加第二遍树遍历）；在现有 glob 实现中记录并向调用方上报非 NotFound 的目录读取错误，保持原匹配结果语义。
- 最终选择：优先在 glob/FSUtil 来源边界引入可报告遍历故障的扫描路径，只将真正不可读取的目录标为 unavailable，正常不存在目录与匹配为空仍判定为无规则；保持 V1 的 glob 匹配器。具体挂钩需以当前 glob/path-scurry 可用 API 为准，若不可可靠实现则改用等价的最小错误感知方案并补录取舍。
- 选择理由：冷启动也能知道扫描失败，无需持久化每个位置的已匹配文件，不污染 SessionState/Location 责任，避免为每次模型请求额外遍历完整目录树。
- 影响：可能涉及 `packages/util` 的现有 Glob/FSUtil 边界，应补目录 readdir 失败、冷启动已有会话与真实删除的回归测试；正常匹配和排序不变。

### DEC-009: 读取失败前协调配置 watcher
- 阶段：二次审查修复
- 背景：配置切换到本地新来源+失败 URL 或扫描失败时，当前单遍加载提前返回 unavailable，旧 watcher 不退订、新 watcher 未订阅。
- 可选方案：故障时保留旧 watcher 等成功后恢复；仅协调已扫描到的部分来源；从当前配置先独立计算完整 watcher 计划并协调，再读取内容与远端 URL。
- 最终选择：按当前配置先建立完整计划并协调动态订阅，后续本地扫描/URL 返回 unavailable 不改变来源历史值，但也不继续监听已移除的配置路径。
- 选择理由：保持 watcher 资源与当前有效配置一致，故障期不会因旧路径变化反复抓取失败远端来源；避免部分计划漏订阅后续配置项。
- 影响：需要失败 URL 与旧/新本地配置并存的 watcher 生命周期测试；不会改变已持久化指令的失败保留语义。
