## 决策列表

### DEC-001: 使用三个固定子智能体而非动态模型 Hook
- 阶段：阶段 2 方案设计
- 背景：OpenCode Task 调用不支持动态传入 model 和 variant，需要稳定地按复杂度切换模型。
- 可选方案：新增 Router Agent；实现插件或核心 Hook；使用三个固定模型子智能体并由 Skill 路由。
- 最终选择：使用三个固定模型子智能体并由 `dev-workflow` 路由。
- 选择理由：完全复用现有 Agent 和 Task 能力，不修改核心代码，也符合不新增 Router、不修改 plan 的要求。
- 影响：模型切换由提示词驱动，必须在 Skill 中定义清晰分级和强制委派规则。

### DEC-002: 当前通过 plan 的 task 权限实现 build 专用
- 阶段：阶段 2 方案设计
- 背景：Agent 配置没有声明允许调用者的字段。
- 可选方案：插件校验所有调用者；修改核心权限模型；在当前 `plan` 中拒绝并在 `build` 中允许。
- 最终选择：在当前 `plan` 中拒绝并在 `build` 中允许。
- 选择理由：满足用户确认的当前范围，改动最小且由运行时权限强制执行。
- 影响：未来新增其他主 Agent 时，需要同步配置其 Task 权限。

### DEC-003: 自动选择本机可用的三档模型
- 阶段：阶段 3 文档生成
- 背景：方案阶段暂用模型占位符，但实际配置不能保留无效占位符。
- 可选方案：等待用户提供模型；保留占位符导致配置不可用；从本机已配置模型中选择三档模型。
- 最终选择：简单档使用 `openai/gpt-5.4-mini-fast:low`，中等档使用 `openai/gpt-5.5:medium`，复杂档使用 `openai/gpt-5.6-sol:high`。
- 选择理由：三个模型均已在本机可用并明确支持目标 variant，能力和推理投入逐档提升。
- 影响：后续可只修改 `opencode.jsonc` 调整模型，无需修改 Agent 文件或开发流程。
