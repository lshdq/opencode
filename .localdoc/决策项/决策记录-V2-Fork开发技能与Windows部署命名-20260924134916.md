## 决策列表

### DEC-001: 修正 Windows 包装脚本的默认 Bun 路径
- 阶段：执行开发
- 背景：原默认 `D:\Program\bun-v2\...\bun.exe` 在本机不存在，实际 Bun 1.4.2 安装在 `D:\Program\bun\...\bun.exe`。
- 可选方案：仅在文档示例中传 `-Bun`；同步更新包装脚本默认路径及文档示例。
- 最终选择：同步更新脚本默认路径并保留 `-Bun` 显式覆盖能力。
- 选择理由：默认构建入口应在当前维护环境可直接运行，且仍可用现有参数切换其他合规安装位置。
- 影响：触及 `packages/cli/script/build-win.ps1` 及相关说明；不改变 Bun 1.4.2 的版本要求。

### DEC-002: 在 CI 构建前准备上游 V2 引用
- 阶段：执行开发
- 背景：Windows CI `actions/checkout` 没有官方 `upstream/v2` 引用，动态版本解析要求该引用存在。
- 可选方案：CI 跳过构建或退回固定版本；在 CI 预检中获取官方上游 V2 引用后保持构建脚本无网络操作。
- 最终选择：CI 预检显式准备 `upstream/v2`，再执行现有测试与构建。
- 选择理由：不削弱用户确定的版本来源，也不在构建脚本中隐式更新上游；CI 保留可运行性。
- 影响：增加一次 CI 对官方上游的读取，网络失败会导致 CI 失败；本地构建仍要求预先存在引用。

### DEC-003: 让 fork 专用技能随仓库正常交付
- 阶段：代码审查后的修复
- 背景：`D:\works\git\.gitignore` 的 `**/.opencode/` 使新技能及 V2 合并技能在本仓库中均被忽略，不会随常规提交交付。
- 可选方案：仅记录人工 `git add -f` 步骤；在本仓库 `.gitignore` 精确放行两个技能目录与 SKILL.md，继续忽略其他本地 `.opencode` 内容。
- 最终选择：仓库级 `.gitignore` 精确放行两个技能文件，不改变上级忽略规则或 Git 暂存区。
- 选择理由：新检出可获得 fork 开发指南，且避免要求每次提交手动强制暂存或暴露本地私有配置。
- 影响：`.gitignore` 产生新变更、两份项目技能在 `git status` 中变为可见的未跟踪文件；本任务不自动暂存或提交。

### DEC-004: 使用临时真实可执行文件补部署验证回归
- 阶段：代码审查后的修复
- 背景：独立审查指出目前仅测试复制辅助函数，未覆盖改名后运行与失败清理；正式产品构建/部署不在用户批准的本次范围。
- 可选方案：直接执行正式产品构建及部署；仅保留静态证明并记录缺口；将最终单 exe 部署与验证收敛为可测路径，在临时目录用已有 Bun 可执行文件作运行时夹具。
- 最终选择：委派开发子任务评估并采用最小的可测部署验证路径，用现有真实可执行文件在临时目录覆盖改名运行及失败清理，继续不执行正式产品构建/日常目录部署。
- 选择理由：真实运行的夹具能验证 Windows 可执行文件改名与错误清理，缩小新增编排的回归缺口，同时遵守已批准的构建边界。
- 影响：可能调整 `packages/cli/script/windows-build.ts`、`windows-runtime.ts` 的最终部署边界并增补测试；正式产品级编排仍需后续实际构建验收。
