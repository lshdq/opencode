## 决策列表
### DEC-001: 将 UI 启动屏障与业务初始化屏障分离
- 阶段：方案设计
- 背景：安装已异步，但 CLI 配置请求和整页 ready 渲染条件仍等待插件。
- 可选方案：直接去掉服务端插件等待；或让 UI 提前渲染并保留业务初始化屏障。
- 最终选择：UI 提前渲染，提交等待准备完成。
- 选择理由：满足用户目标，保留认证、工具和配置钩子一致性。
- 影响：调整 CLI/TUI 协作与提交状态；服务端初始化顺序保持。

### DEC-002: 使用现有同步请求作为服务端准备屏障
- 阶段：开发
- 可选方案：CLI 新增配置 promise 再传给 TUI；或复用 Sync 的 config/providers/agents 请求。
- 选择：删除 CLI 重复配置请求，在 Sync 成功更新配置时应用权限，并纳入共享准备任务；会话校验以回调移至渲染后执行。
- 理由：避免双配置源和静默忽略权限配置失败；保留服务端完整 bootstrap，不新增公共 API。

### DEC-003: 取消属于提交，安装属于共享生命周期
- 阶段：开发
- 选择：共享准备任务记录失败，提交拥有独立 AbortController；Escape、编辑、清空、导航、卸载取消等待。失败保留草稿和可见提示，不自动退出。
- 理由：取消单条消息不应杀掉其他使用者的依赖安装；不能提交用户后来编辑的内容。不可恢复失败需要重新启动，不盲目重复安装。
- 扩展：识别 SyncProvider、Slot fallback、Session 数据 Show 的额外首屏屏障；插件注册仍顺序执行。退出不再等待无界插件 init，主动 abort 已建立的 scope，后续加载阶段检查 disposed。

### DEC-004: 恢复、插件替换与明确权限选择
- 阶段：开发验证
- 选择：CLI 自动消息立即进入与手动消息相同的可取消等待；启动恢复内部导航转移尚未取消的草稿和提交，用户导航则抑制恢复。插件替换输入框只在同一路由 revision 内转移提交。
- 理由：测试验证发现，单纯在自动发送前等待 ready 会使恢复前的 Escape 无法取消；直接卸载默认输入框则会丢失待发送消息。
- 权限：未指定 auto 时由后台配置补齐；显式 `--auto` / `--auto=false` / `--no-auto` 优先于配置，运行中用户主动切换优先于迟到配置。旧别名显式开启仍有效。
- 故障：初始服务端配置失败由可见状态和提示反馈，保留编辑界面/草稿；原“配置失败立即退出”测试按新验收标准更新。没有自动重试安装或配置，避免无界重试和半初始化运行。

### DEC-005: 扩展测试暴露的既有 Windows 路径断言
- 阶段：独立测试
- 背景：扩展运行 runtime.test.tsx 发现 ~/project 与 ~\project 断言差异；独立测试已单独复现并确认相关实现及测试与基线相同。
- 可选方案：扩大本次范围修正既有路径问题；或记录基线失败，完成当前启动需求验证和审查。
- 最终选择：记录基线失败，不扩大生产变更范围；交独立审查复核关联性。
- 理由：本次针对性与新增测试通过，路径断言不涉及启动依赖准备，额外修正会混入无关行为。
- 影响：报告如实列出 1 项基线失败，不声明所有扩展测试全绿。

### DEC-006: 审查修复——完整提交意图与显式取消优先
- 阶段：阶段 7 返回阶段 5 修复；Auto 模式直接执行，不递归流程。
- 来源：R-001/R-002 的真实 shell Escape、插件替换复现。
- 可选方案：等待时禁止 shell 模式/插件替换；或保留编辑与替换，传递完整意图并使模式编辑取消原提交。
- 最终选择：PromptRef.current/set 同步 input、parts、实际 mode；暂存草稿也保留 mode；插件与 continue/fork 共用完整快照。只有确实恢复了旧草稿才恢复 pending，不把旧 pending 应用到插件预置的新内容。
- Escape：等待中的 shell 第一次 Escape 仅取消提交，保留 shell 草稿模式；非等待时保留退出 shell 语义。Backspace/进入 shell/历史切换/ref.set 显式取消旧提交；submit 在等待前捕获 mode。
- 理由：避免本地命令被错误发给模型；未提交和已取消草稿转移同样保留模式，但不自动提交。

### DEC-007: 审查修复——路由任务拥有可失效的屏障
- 阶段：阶段 7 返回阶段 5 修复；来源 R-003/R-004。
- 可选方案：仅删除 pending 集合元素；统一吞掉所有失败；或将全局准备与路由准备的所有权分离。
- 最终选择：preparation.track 增加可选 AbortSignal，跟踪独立 barrier Promise；owner 失效时完成 barrier，释放已经捕获 Promise.all 快照的 waiter，观察并忽略迟到结果。保留原任务返回值，不取消共享任务。
- 失败策略：有效任务失败仍可见；路由失败仅在 owner 存活时有效，离开路由可清除该失败；失败按任务分别保留，清除路由错误不得抹除真正全局错误。
- App：Sync、初始 agent/model 与插件为全局屏障；CLI/attach session validation 与恢复/fork 为初始路由屏障，导航或销毁使其失效。成功和失败路径使用同一所有权规则。
- Session：每次 sessionID effect 拥有控制器，重新执行/卸载时失效；session.get 尽力中断，所有后续路由动作检查 signal。共享的 session-ID 数据缓存 hydration 仍可完成，不能成为旧路由留下的全局发送屏障。
- 跨模块补充：workspace bootstrap 与 Project 写入接受同一 signal，丢弃失效 workspace 的迟到配置/路径/后台状态；区分 workspace 选择与已应用的配置来源，避免 A 取消后同 workspace 的 B 误用未完成配置。
- 理由：用户放弃局部操作后可继续工作，同时不放松安装、插件、认证/模型/配置的真正全局准备要求。

### DEC-008: 第二轮修复——候选执行上下文完整准备后统一发布
- 阶段：复审返回阶段 5，Auto；来源 R-005/R-006，已读取复审报告中的真实 HTTP 请求证据。
- 比较方案：① path/workspace 先应用，取消时回滚；② 分离候选上下文与已就绪上下文，必要数据完成后统一提交。
- 最终选择：②。回滚需要重建旧目录、项目、配置、agent/provider/command、权限与请求选择，还可能覆盖更晚的切换或用户主动权限选择；暂存候选无需撤销已发布状态，更局部、可验证。
- Project.load 只取候选快照；Sync 同一 batch 发布 workspace/path/project、providers、agent、config、command 和权限。候选 SDK 请求显式传 workspace，列表查询也使用候选 path；不提前改变 SDK 默认选择或项目 current。`workspace: null` 明确回到 local，不能被函数默认参数误解为沿用旧 workspace。
- Sync.bootstrap 自带准备屏障及替换 owner，新 bootstrap 使旧候选失效；路由 signal 只清理自身任务/失败，不能移除新任务。失效 IO 可继续完成，但不能发布；被替换的调用不能被当成准备成功继续发送 warp 提醒。
- 有效会话必要配置失败：留在会话并保留草稿，持续展示 Startup failed，重复 Enter 不重试也不发送；路由离开清除此局部失败。历史读取仍可完成，但不能因此放行执行。重新打开该 workspace 可重新准备；列表刷新移除已缓存会话时不得误用 fullSynced 标记跳过重新读取。
- 初始配置/共享插件失败仍保留全局屏障，取消局部 workspace 不得放松。项目目录列表的 mainDir 为既有可选元数据，保持原降级；path/project.current 及 config/providers/provider/agent/command 为必要请求。

### DEC-009: 第二轮修复——workspace 写入入口及权限回复保持来源一致
- 扫描所有生产 project.workspace.set 调用：Session、warp、删除 workspace 均不再提前发布选择。发现列表刷新也不能隐式清空已提交 workspace，只更新发现数据；明确切换须走完整准备。
- warp/delete 使用同一 bootstrap 入口和路由 signal；Route 每次导航替换 signal，避免未完成操作或失败变成无主全局屏障。删除当前 workspace 导航 Home 后，使用新 Home owner 建立 local 准备，不借用已失效的旧 owner。
- Home 新建默认携带已提交 workspace 和目录；显式选择另一 workspace 时先准备再选 agent/model。已有 Session 发送额外校验 Session workspace 与已提交配置来源相同。
- 自动权限回复只适用于已经初始化且与已提交 workspace 一致的请求；未就绪 workspace 的请求不得继承旧 auto_approve。手动权限回复以请求所属 Session.workspaceID 定位，而非使用仍保留的旧 Project.current。
- CLI/主动权限选择仍由 Permission.configure 原优先级保护，不做权限回滚、不覆盖用户选择。
- SDK/Protocol/Server API、依赖、服务端插件初始化顺序均未改；不需要生成 SDK。本轮无提交、构建、安装或部署。

### DEC-010: 第三轮修复——Home 提交候选同时受提交取消与原路由约束
- 阶段：阶段 5 第三修复轮，复杂 → dev-deep；来源 R-007，沿用父流程 Auto 批准。
- 比较方案：① finally 清除候选错误；② 仅绑定 route；③ 捕获 route signal 并与单次 submission signal 组合。
- 选择③：①会使失败后重复 Enter 绕过持续失败；②不能响应 Escape/编辑取消尚未完成的候选。组合 signal 在提交失败释放 controller 引用后仍随原 route 失效；不修改全局准备或 Session hydration 的屏障。
- 影响：原路由失败持续阻止重提，离开清除局部失败、重入重新准备；不取消共享插件安装。

### DEC-011: 第三轮修复——删除发现刷新与执行上下文恢复分离
- 比较方案：①所有 DELETE 完成均 bootstrap 当前 context；②发起前捕获 route owner 和当前目标，仅有效且确实删除当前目标时导航 Home 并立即建立完整 local 屏障，其他成功只刷新发现信息。
- 选择②：①借用新 route signal 会取消无关候选 C；迟到成功/失败不应获得新 owner。新 Home owner 只能在旧 owner 仍有效、主动执行恢复导航时取得，不可在迟到回调中无条件取得。
- 两个 workspace.remove 入口执行相同约束；恢复对话框不再依赖 workspace.sync 隐式清空选择，不再 refetch 已被替换的 Sessions 组件。必要 local 准备失败继续阻止本路由提交，离开后清除；失败返回 false 防止误显示恢复完成。
- 对话框自身确认去重及卸载后的 onDone 防护一并补齐，避免异步 DELETE 在 Escape 后复活旧窗口。原 session.delete 的迟到失败也不得在新路由打开恢复窗口。
- 保留候选完整准备/batch 发布、CLI/用户权限优先级与 shell 意图；无新公共 API 或大架构。

### DEC-012: 第四轮修复——删除失效独立于候选生命周期，warp 覆盖完整操作链
- 阶段：阶段5第四修复轮，复杂 → dev-deep；父流程 Auto，来源 R-010/R-011。
- 比较：①删除后持续全局恢复屏障；②显式记录已删除 workspace，Home 按当前路由重建完整 local context，执行边界另校验有效性。选择②：不让旧 local IO 阻塞有效 C，也不使取消/失败回退到已经删除的快照；失败同 owner 不自动重试，导航后的新 owner 可重新准备。
- 删除成功无论原 owner 是否存活都记录事实；仅删除目标失效，发现刷新/迟到配置不能复活该 ID。两个删除入口复用 Sync 的 local 恢复；保留旧快照供显示不代表其可执行。提交（含自动/shell/command）、配置发布和权限回复分别检查失效目标。
- warp 采用路由与对话框 generation 的组合 owner；主动的选择/确认窗口转换允许交接到新 generation，用户关闭/替换/导航则取消后续本地副作用。检查创建、warp、bootstrap、reminder、刷新及完成回调的全部 await；已接受的远端操作不撤销。刷新携带 owner，不能晚到覆盖新列表。

### DEC-013: 第五轮修复——实例刷新保留候选目的地与稳定的准备任务
- 阶段：阶段5，复杂 → dev-deep；父Auto流程，来源R-012。
- 比较：①忽略候选期间全部disposed事件；②事件无条件替换候选并吞AbortError；③按workspace/directory定位，保留候选外层任务，在其内部使过期读取失效并合并刷新。选择③：①漏掉仍有效实例的更新，②既可污染目标又会绕过完整配置/失败门禁。
- 显式切换仍可替换旧候选；同候选的disposed只重启完整只读准备，不取消路由任务。按事件ID去重，同一批通知合并；刷新期间真正的新失效事件仍使该轮读取过期，避免永远忽略新失效。失败不自动重试；旧读取可继续但不能发布或覆盖新失败。无参provider后续bootstrap复用在途任务，不重放provider连接或模型操作。
- 旧committed实例事件在新候选期间仅保留刷新需求；候选成功离开旧实例则丢弃，候选失败不被旧刷新覆盖，候选owner取消且仍回退该实例时立即补完整刷新，不等待被放弃的IO。删除事实优先，销毁不再启动刷新。
- 事件同时匹配workspace及已知directory；不同本地directory不是同一实例。候选目录优先使用workspace发现信息，未发现时同workspace通知保守触发刷新，完整/path返回后补足定位。

### DEC-014: 第六轮——认证事实与窗口完成权限分离，接纳局部默认值修复
