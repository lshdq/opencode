## 决策列表

### DEC-001: 将构建契约拆分为独立 Skill
- 阶段：阶段 2：方案设计
- 背景：`fork-development` 同时维护 fork 开发规则和 Windows x64 构建部署规则，职责边界不清。
- 可选方案：继续放在 `fork-development`；拆分为 `windows-build` Skill；仅新增命令而不拆 Skill。
- 最终选择：拆分为 `windows-build` Skill，同时让 `fork-development` 引用它。
- 选择理由：构建规则可独立发现、复用和维护，且不会丢失 fork 开发上下文。
- 影响：需要同步更新原 Skill，并新增独立 Skill 文件。

### DEC-002: 增加 `/build` 作为确定性入口
- 阶段：阶段 2：方案设计
- 背景：Skill 的自然语言发现由模型判断，不能保证每次出现“构建”都严格执行构建契约。
- 可选方案：只依赖 Skill 描述自动发现；新增 `/build` 命令；修改全局代理或权限逻辑。
- 最终选择：新增项目级 `/build` 命令，命令模板明确要求加载 `windows-build`。
- 选择理由：命令可以提供明确、可重复的用户入口，同时不改变全局 OpenCode 行为。
- 影响：新增 `.opencode/commands/build.md`；自然语言请求仍不构成程序级强制钩子。

### DEC-003: 使用 `.opencode/commands` 而非继续使用旧目录
- 阶段：阶段 2：方案设计
- 背景：项目当前存在旧式 `.opencode/command/`，但 V2 文档推荐 `.opencode/commands/`。
- 可选方案：沿用旧目录；使用推荐目录；同时添加两个入口。
- 最终选择：使用 `.opencode/commands/build.md`。
- 选择理由：遵循当前 V2 约定，避免重复注册和旧目录依赖。
- 影响：新增目录，但不修改现有旧命令。
