## 决策列表

### DEC-001: 使用会话 family 状态聚合通知
- 阶段：方案设计
- 背景：主会话成功事件可能早于后台子代理完成事件。
- 可选方案：修改服务端主会话完成语义；在 TUI 中基于 `session.family()` 聚合；仅屏蔽所有子代理声音。
- 最终选择：在 TUI 通知插件中使用现有 family 和 status 信息暂缓主会话通知。
- 选择理由：变更范围最小，不改变服务端事件语义和其他客户端行为，能够直接覆盖任务栏提前闪烁问题。
- 影响：TUI 需要维护待发送主会话通知集合，并在子代理终止时重新评估 family 状态。

### DEC-002: 保留子代理声音提示
- 阶段：方案设计
- 背景：TUI 当前对子代理完成使用 `subagent_done` 声音而不发送系统通知。
- 可选方案：完全抑制子代理提示；保留子代理声音并只延迟主会话系统通知；将子代理声音合并到主会话通知。
- 最终选择：保留子代理声音，仅延迟主会话系统通知。
- 选择理由：保持现有交互和已覆盖测试的行为，避免扩大需求范围。
- 影响：最后一个子代理完成时可能同时产生现有子代理声音和一次主会话通知。

### DEC-003: 使用生命周期事件补足 family 加载竞态
- 阶段：代码审查修复
- 背景：独立审查发现，子代理已经运行但会话信息尚未加载时，`session.family(root)` 可能暂时只包含根会话，导致主会话提前通知。
- 可选方案：增加轮询等待；修改服务端 family 接口；在 TUI 记录 `session.created` 的父子关系和执行中的会话，并与已加载 family 合并判断。
- 最终选择：在 TUI 通知插件内维护轻量的父子关系与 active 会话集合，结合现有 family/status 判断。
- 选择理由：不新增服务端接口、不引入轮询，利用已有有序生命周期事件覆盖异步加载窗口。
- 影响：通知插件增加进程内生命周期状态，插件销毁后状态随之释放；新增嵌套后代和加载竞态回归测试。

### DEC-004: 在通知判定时恢复已加载生命周期状态
- 阶段：第二轮代码审查修复
- 背景：TUI 重连或插件重新初始化后，进程内 active/parents 集合可能缺少此前已发生的生命周期事件；会话删除也需要清理映射。
- 可选方案：依赖重新接收完整事件流；新增服务端状态接口；在通知判定时从现有 `session.list()`/`session.status()` 恢复，并处理 `session.deleted`。
- 最终选择：使用现有 Data 接口恢复已加载会话状态，并在删除事件中清理生命周期集合。
- 选择理由：不新增协议和轮询，覆盖重连/重启后的可见会话状态，同时限制状态集合增长。
- 影响：通知判定会扫描当前已加载会话；删除后的延迟父通知会重新评估一次。

### DEC-005: 仅保留 active/deferred 会话的父链
- 阶段：最终代码审查修复
- 背景：长期运行的 TUI 会收到大量 `session.created` 事件，永久保存所有历史父子关系会造成状态和扫描成本无界增长。
- 可选方案：保留全量父子映射；依赖 session.deleted 清理；仅保留 active/deferred 会话及其必要父链，并从已加载会话列表恢复其他关系。
- 最终选择：采用 active/deferred 会话及其父链的有限缓存，并从 family/list/status 重新发现已加载关系。
- 选择理由：满足异步 family 竞态和嵌套判断，同时不让历史会话数量决定长期内存和扫描成本。
- 影响：生命周期同步逻辑增加父链裁剪；测试夹具需要明确区分会话列表可见性和 family 可见性。

### DEC-006: 按当前 running 状态恢复 terminal 代次
- 阶段：最终复审修复
- 背景：重连后同一会话可能已经开始新执行，但插件仍保留上一次执行的 terminal 标记。
- 可选方案：依赖新的 execution.started 事件；在当前 status 为 running 时清除旧 terminal；引入服务端执行代次。
- 最终选择：在同步当前会话状态时，running 优先代表新执行并清除旧 terminal；同时保证 ended 先同步再写入当前 terminal。
- 选择理由：无需协议变更，兼容重连恢复，且不破坏同一终止事件的重复抑制。
- 影响：新增重连回归测试，并将 terminal 缓存限制为有界集合。

### DEC-007: 保留删除 tombstone 并按已加载状态清理 terminal
- 阶段：最终复审修复
- 背景：删除事件后数据层可能立即移除会话，若同步逻辑同时清除 deleted 标记，迟到执行事件会再次触发通知；简单按数量淘汰 terminal 又可能破坏重复事件抑制。
- 可选方案：立即清除删除标记；永久保留所有删除标记；保留有界删除 tombstone，并仅清理已不在当前数据集中的 terminal 状态。
- 最终选择：删除 tombstone 只在同 ID 新建时清除并采用有界容量；terminal 按当前已加载/活跃/延迟状态保留，避免淘汰仍需去重的会话。
- 选择理由：覆盖删除后的迟到事件，同时在资源占用和生命周期幂等之间取得可控折中。
- 影响：增加删除后迟到事件回归测试；极老且已从客户端数据集中淘汰的会话不再承担本地通知去重责任。

### DEC-008: 删除 tombstone 使用有界容量
- 阶段：最终复审修复
- 背景：永久保留已删除会话 ID 会使长期运行的 TUI 状态持续增长。
- 可选方案：永久保留；按时间清理；使用固定容量保留最近删除会话。
- 最终选择：保留最近 256 个删除会话 tombstone，同 ID 新建时立即清除。
- 选择理由：删除后的迟到事件通常紧随删除发生，固定容量可控制内存；同 ID 新建仍能恢复正常生命周期。
- 影响：极老且已淘汰 tombstone 的迟到事件不再保证本地抑制，属于资源与历史事件窗口之间的明确折中。
