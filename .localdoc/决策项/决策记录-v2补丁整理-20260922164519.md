## 决策列表
### DEC-001：独立工作树和固定开发基线
- 阶段：方案设计
- 背景：官方 v2 与旧 fork 架构不同，直接合并会恢复过时模块。
- 可选方案：旧分支整体合并；新工作树按需求迁移。
- 最终选择：新 worktree D:\works\thirdparty\opencode-v2，固定 080b7671dea45a693b537c1e358e89ab14463d0d。
- 理由：保留干净对照，减少无用补丁，能精确审查。
- 影响：原工作树不改；后续上游推进不改变本轮基线。

### DEC-002：按功能重做与条件迁移
- 阶段：方案设计/最新基线复核
- 背景：官方已覆盖 Location 缓存、shell 参数、退出输出截止等；最新代码仍有 plugin gate、dispose 等 loading、资源错误升级为 Location 错误、rg PSModulePath 缺口。
- 可选方案：整批 cherry-pick；小补丁加回归场景。
- 最终选择：稳定性、交互、rg、ACL 分组重做，边缘进程/文件补丁以测试证据决定。
- 理由：保留官方新架构，降低升级成本，不引入无证据的复杂防御。
- 影响：官方覆盖项退役，旧测试按新行为重新接线。

### DEC-003：权限临时覆盖
- 阶段：方案设计
- 背景：官方 getter 的 --auto 优先级使设置无法临时关闭自动批准。
- 可选方案：切换写回全局配置；在 TUI 实例持有临时覆盖。
- 最终选择：手动切换临时覆盖初始 CLI/config 值，不写回全局配置，涵盖当前 TUI 标签。
- 理由：满足运行中一键切回手动，避免不同 TUI 相互改配置；deny 引擎不变。
- 影响：新增明确运行时权限模式状态及对应 UI 测试。

### DEC-004：工具链与运行数据隔离
- 阶段：准备
- 背景：系统 Bun 1.3.14，目标需 1.4.2；2.x 可能复用同版本后台服务。
- 可选方案：覆盖系统工具链/沿用日常数据；D 盘并行工具链/隔离运行。
- 最终选择：并行准备 1.4.2，进程内 PATH；独立 config/data/state/cache 与服务注册，验证真实服务身份。
- 理由：避免影响当前使用实例与污染对照结果。
- 影响：依赖安装和测试制品单独落盘，缺少真实终端项目不得虚报通过。

### DEC-005：MCP 已证实 detached orphan 的收容方案
- 阶段：开发
- 背景：平台实测两种 wrapper 退出路径均留下 detached helper；普通 shell 后代存活是官方契约。
- 可选方案：CIM 后代枚举/PID 推测；通用 spawner 杀所有后代；MCP 专属 Windows Job Object。
- 最终选择：仅本地 Windows MCP 标记命令，由系统 PS5.1 宿主先加入 kill-on-close、禁止 breakaway 的 Job 再启动目标，继承字节句柄及原始环境；远程 Environment 和普通 shell 不变。
- 理由：避免先运行后 assign 的窗口和父退出后 PID 树不可追踪；两个真实失败诊断转默认通过回归。
- 影响：新增 Windows MCP 宿主及 parser 边界，PS/.NET 初始化有启动成本；受限企业 Add-Type/nested Job 环境失败不静默降级。须独立测试审查。

### DEC-006：权限宿主与正常 SQLite 生命周期
- 阶段：开发
- 背景：只依赖 pwsh7 会新增系统依赖且启动开销较大；无限等权限子进程违反有界启动目标。
- 可选方案：pwsh7 必装；系统 PS5.1 同等安全创建；事后 chmod 降级。
- 最终选择：默认系统 PS5.1 .NET FileStream 带 FileSecurity 创建，兼容 PS7；单次10秒、64KiB输出上限并响应取消；校验DACL与恢复，不回退不安全写入。
- 理由：不新增pwsh7必装条件，写敏感内容前已有权限；真实耗时样本PS5.1约0.4–0.5秒/次。
- 影响：SQLite驱动覆盖正常WAL创建/重开/侧文件重建，不递归改自定义父目录；手工journal_mode切换和外部writer边界明确记录。

### DEC-007：交互和准备阶段的确定语义
- 阶段：开发
- 可选方案：抢占现有快捷键；使用空闲F4；自动排队未就绪Enter；保持草稿要求再次确认提交。
- 最终选择：permission.mode 默认F4（保留官方Ctrl+Shift+A）；session.timestamps默认关闭；text.permission.autoaccept专用语义token；未就绪Enter保留草稿需再次明确提交，已开始的准备可取消，不中止已发出的durable admission。
- 理由：避免无意迟发、重复发送和快捷键冲突；用户手动改文/导航优先于旧异步结果。
- 影响：各行为有真实按键测试；按键可配置；timestamp通过Settings持久控制。

### DEC-008：local 制品与环境故障修复
- 阶段：开发/基本验证
- 可选方案：自定义channel可能迁移同版默认注册；官方local channel；修改symlink源码适应Windows。
- 最终选择：沿用官方local channel禁自动更新、隔离服务；恢复Git symlink真实工作树形态而不改git配置；冻结force重链接不完整node_modules，锁blob保持不变。
- 理由：避免fork被官方更新覆盖及误连日常服务；环境修复不制造源码补丁。
- 影响：manifest含tracked/untracked逐文件hash、集合hash、binary hash和source.diff；手工激活另行操作。

### DEC-009：审查后关闭SQLite侧文件初生权限窗口
- 阶段：审查修复
- 背景：创建WAL/SHM后chmod不能撤销窗口中已获读取句柄；第一实现不满足敏感数据创建安全。
- 可选方案：后置加固（不满足）；新增SQLite VFS（复杂且双运行时成本高）；明确目录ownership并从出生继承私有DACL。
- 最终选择：默认app拥有的DB目录在open前私有继承，路径不变；显式OPENCODE_DB父目录只验证不修改，要求预先私有；隔离测试自行准备其专用目录。
- 理由：保证正常WAL初生和重建没有开放窗口，不递归修改任意用户目录，不改变数据库格式/事务。
- 影响：Windows自定义DB目录增加明确兼容要求（文档说明）；目录与既有文件一次宿主批处理，真实restricted token检验。历史已获得句柄无法追溯撤销。

### DEC-010：迁移与Effect取消的真实生命周期
- 阶段：审查修复
- 背景：正式目标排他预创建后写失败留下空文件，重试误判已存在；tryPromise中断不等待宿主close。
- 可选方案：删除任意已存在目标；正式目标先写；同卷私有临时文件完整写后no-overwrite发布。
- 最终选择：scoped唯一temp+hardlink原子无覆盖发布；只清本次temp；FileModeEffect callback取消finalizer abort后等待同一宿主pending close。
- 理由：不删并发赢家，失败能重试，Fiber interrupt返回即资源已回收。
- 影响：Windows迁移需同卷hardlink能力（本机NTFS通过）；新增真实失败/并发/Fiber测试。

### DEC-011：原生撤销元数据绑定与有界历史
- 阶段：审查修复
- 背景：可见占位符相同，按文本匹配undo恢复会把A载荷换成B，实际影响后续提交。
- 可选方案：继续加文本匹配规则；按原生编辑步骤成对记录元数据。
- 最终选择：绑定OpenTUI原生编辑/undo/redo操作边界，最近256步有界窗口；重置同步清历史、分支清redo，共享大载荷字符串。
- 理由：不以相同文本猜编辑身份，覆盖直接native操作及剪切；防元数据无界保留。
- 影响：撤销范围明确为最近256原生编辑步，依锁定OpenTUI语义需升级回归。/cd pending以独立请求Symbol finally清理，防旧响应污染新草稿目录。

### DEC-012：Git差异按原始字节交付
- 阶段：审查修复
- 背景：通用execute.trimEnd截掉diff结尾，制品source.diff不可解析。
- 最终选择：executeRaw Uint8Array用于diff；元数据文本仍单独trim；字节对照git --output并git apply --stat/check --reverse验证。
- 理由：保留尾空白、CRLF、binarypatch，不用补换行掩盖信息丢失。
- 影响：旧试验制品废弃为交付候选，最终必须重建。

### DEC-013：R-03 改为应用层 owned undo/redo，并增加字节上限
- 阶段：阶段7回流阶段5；主代理已明确选择 owned 方案并授权继续，无需再向用户确认。
- 背景：锁定 OpenTUI 的 EOF Delete、双 checkpoint、零宽/宽字符及 range 错误分支说明不能把公开 mutator 与内部历史一一对应；公开 API 没有 checkpoint identity/depth。
- 可选方案：fork/rebuild native 增加正式 checkpoint API；继续复刻所有原生分支；由应用层拥有完整逻辑历史。
- 最终选择：不修改依赖/lock，应用层捕获并恢复文本、caret、metadata，原生仅作当次编辑，完全不调用其 undo/redo。DEC-011 的256上限保留，但计量改为应用逻辑步骤。
- 存储子方案：逆 patch 或有界全文快照；选择后者，减少 Unicode/选区逆变换复杂度，另设16 MiB逻辑保留预算。实际字符串引用canonical共享；同文与隐藏大payload不会按步重复复制。字节超额淘汰完整远端条目，保证可连续恢复，不跨缺口撤销。
- 理由：snapshot 直接还原可验收的 text+caret+payload，不依赖 Zig 不可见空步骤；16 MiB+256 双上限防止256份巨文本无上限保留。已补256 KiB文本80次编辑、1 MiB共享metadata256步、超预算单条和超过1 MiB读取上限测试。
- 影响：普通forward Delete为1逻辑步，EOF Delete也记录1次删除意图；其他真正no-op不破坏redo，同文replace保留metadata语义；选择替换仍是delete+insert两步。clear/reset/cleanup清应用历史与字符串池。TS extmarks历史禁用/清理是锁定版本的窄适配点，文档与升级回归明确覆盖；无native fork。
