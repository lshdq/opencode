## 决策列表

### DEC-001: 复用 agent catalog 首位作为默认智能体来源
- 阶段：方案设计
- 背景：服务端已经解析 `default_agent`，并将解析结果放在 agent list 首位；客户端不应重复读取或实现配置合并逻辑。
- 可选方案：客户端自行读取 config；客户端继续使用固定 build 回退；客户端使用现有 location-scoped agent list 首位。
- 最终选择：使用现有 agent list 首位。
- 选择理由：避免新增请求和配置解析重复，保持 TUI、App 与服务端默认解析一致。
- 影响：需要修正客户端未指定智能体时的回退和新草稿状态清理逻辑。

### DEC-002: 只重置新会话状态，不改变已有会话状态
- 阶段：方案设计
- 背景：旧智能体来自客户端全局/草稿状态，新会话需要默认值，但已有会话仍应保留会话级选择。
- 可选方案：每次切换页面都重置；仅创建新会话时重置；服务端忽略客户端智能体。
- 最终选择：仅在新会话入口或新草稿 ID 变化时重置。
- 选择理由：范围最小，保留已有会话和新会话草稿内手动选择，避免破坏恢复与分叉语义。
- 影响：TUI 需要显式新会话重置入口，App 需要隔离新草稿状态。

### DEC-003: 区分草稿默认值和手动选择
- 阶段：审查修复
- 背景：App 把 catalog 首位写成固定选择后，后续 catalog 刷新不能跟随新的默认值；模型写入也可能固定旧 agent。
- 可选方案：每次刷新强制改首位；仅记录草稿手动选择，默认值随 catalog 解析。
- 最终选择：按 draft ID 记录手动选择与默认状态，未手动选择时跟随 catalog 首位。
- 选择理由：既符合当前 default_agent，又不会覆盖用户在草稿中的主动选择。
- 影响：草稿 agent 解析需要区分状态，已有 session 与模型继承逻辑保持。

### DEC-004: TUI 兼顾路由目标和 Home location 覆盖
- 阶段：审查修复
- 背景：直接取 home 路由目标无法反映 `/cd`，直接取 location.ref 又可能在路由切换时读取旧会话 location。
- 可选方案：始终取 route location；始终取 location.ref；按 home route key 管理目标与 location 覆盖。
- 最终选择：按 home route key 初始化目标，Home 应用目标后接受后续 location.ref 覆盖。
- 选择理由：覆盖真实 `/cd` 行为，并避免新路由尚未应用时继承旧目录默认智能体。
- 影响：需要测试实际 LocationProvider/route 时序及提交边界。

### DEC-005: 新会话 location 切换不继承旧会话全局 agent
- 阶段：最终审查修复
- 背景：TUI 的全局 `agentStore.current` 可能来自旧会话；新 Home location 应使用目标 catalog 默认值，只有当前新草稿中的显式选择才能跨 location 覆盖保留。
- 可选方案：继续复用全局 current；新会话仅保留 `newSession.agent` 与显式启动 agent；每次 location 变化都强制清空所有选择。
- 最终选择：新会话 location 状态只保留当前草稿的显式选择或启动参数，不回退旧会话全局 current。
- 选择理由：隔离已有会话状态，同时保留新草稿内手动选择和显式参数语义。
- 影响：需要补充“旧会话手选 agent → 新 location 新会话”回归测试。

### DEC-006: 保留已有会话缺省 agent 的兼容回退
- 阶段：最终审查修复
- 背景：把 `resolveAgent(undefined)` 改为列表首位会影响已有 session 缺少 agent 的历史/兼容数据；新默认行为只属于新草稿。
- 可选方案：全局改变未指定回退；恢复原有 `build` 回退并在 draft 分支使用首位；由服务端补全所有历史 session。
- 最终选择：恢复 `resolveAgent` 的原有回退语义，新草稿通过专用解析逻辑使用列表首位。
- 选择理由：最小化兼容风险，严格隔离新会话需求与已有会话行为。
- 影响：需要补充无 agent session 的回归测试。
