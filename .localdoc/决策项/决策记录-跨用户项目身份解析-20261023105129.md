## 决策列表

### DEC-001: 缓存文件方案优于改 git 调用或解析 .git/config
- 阶段：方案设计（阶段 2，补录）
- 背景：需要让 git 子进程失败（dubious ownership/权限/不可用）的用户仍解析出与属主相同的 Project ID
- 可选方案：A) `.git/opencode` 缓存文件写+读回退；B) git 调用注入 `-c safe.directory`；C) 直接文本解析 `.git/config` 的 remote url
- 最终选择：A
- 选择理由：B 改变全局 git 调用语义风险高且仍依赖 git 存在；C 需重复 ini 解析且遇 `insteadOf` 重写时与 git 实际结果不一致；A 复用现有 `cached()` 概念与文件语义，纯文件读写，git 完全不可用时也有效
- 影响：需新增"成功解析后写缓存"行为；`.git` 内新增惰性文件（对 git 无副作用）

### DEC-002: 缓存写入策略为"内容不同才写、失败静默"
- 阶段：方案设计（阶段 2，补录）
- 背景：每次 resolve 都写会产生不必要 IO；只读 `.git` 场景写失败不应阻断解析
- 可选方案：每次覆盖写 / 仅内容不同才写 / 不写仅读
- 最终选择：仅内容不同才写；写失败按静默处理不中断
- 选择理由：幂等、低 IO；解析正确性不依赖写入成功（属主下次还能重试）
- 影响：`persist()` 增加一次受保护的文件比对与写入

### DEC-003: linked worktree（.git 为文件）本期不纳入回退
- 阶段：方案设计（阶段 2，补录）
- 背景：worktree 需解析 gitdir 指针与 commondir 文件才能定位缓存，复杂度与收益不匹配
- 可选方案：包含 worktree 解析 / 仅标准 `.git` 目录
- 最终选择：仅标准 `.git` 目录（读取自然失败即回退现状）
- 选择理由：MVP 覆盖主场景（主检出目录跨用户共享）；worktree 场景维持现状，无回归
- 影响：linked worktree 的跨用户身份一致性留待后续需求

### DEC-004: 缓存命中时以 vcs=git 持久化，防止 upsert 降级
- 阶段：方案设计（阶段 2，补录）
- 背景：`upsertProject` 在 vcs 为 undefined 时会把已有行的 vcs 从 git 改写为 null，损坏属主用户创建的 project 行
- 可选方案：命中时传 `vcs: { type: "git", store: marker }` / 传 undefined 并改 upsert 语义
- 最终选择：命中时传 vcs git（store = `.git` 标记路径，标准仓库即 commonDirectory）
- 选择理由：不改共享 upsert 语义，风险最小；marker 存在且缓存由历史成功解析写入，判定为 git 仓库是诚实的
- 影响：另一用户命中缓存后写入的 project 行保持 vcs=git，与属主一致

### DEC-005: 审查应改项修复方案——storeCached 入口守卫 + cached() 格式校验，不做原子写
- 阶段：阶段 7 审查修复
- 背景：审查发现退化身份 `ID.global`（无 remote 且零提交的 git 仓库、hg 不可用/空 `.hg`）会被写入 `<store>/opencode` 并经 `previous ??` 链永久短路 rootCommit/hgRoot，相关仓库无法收敛到真实身份（可触发回归）；另有可选项：缓存内容格式校验、tmp+rename 原子写、消除 double-read
- 可选方案：A) 仅加 global 守卫；B) global 守卫 + cached() 单行 token 校验；C) 守卫 + 校验 + 原子写 + 复用 previous 消除 double-read
- 最终选择：B
- 选择理由：守卫一行覆盖 git/hg 全部退化路径且恢复自愈（hg 此前无自愈路径）；token 校验单行成本直接封死"损坏内容成为 project ID"的孤儿行风险；原子写针对的是需要"ID 迁移瞬间多进程并发写同一文件"的极小概率交错且可自愈，复杂度（临时文件清理）不值；double-read 为页缓存级读取且重读在并发窗口更安全
- 影响：`storeCached` 跳过 `ID.global`；`cached()` 对非法内容返回 undefined（合法 ID 均为 hex/token，兼容既有缓存文件）；需补回归测试（空仓库不写缓存、提交后收敛 rootCommit、非法缓存内容被忽略）
