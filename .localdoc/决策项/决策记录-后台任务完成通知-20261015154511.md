## 决策列表

### DEC-001: 在通知层修复完成时机
- 阶段：方案设计
- 背景：完成事件表示单个 session execution 结束，但后台子智能体或 shell 可能仍在运行。
- 可选方案：修改执行引擎使主会话延迟发出完成事件；在 App/TUI 通知层根据任务状态延迟通知；只修改界面任务栏状态。
- 最终选择：在 App/TUI 通知层分别根据现有 session/shell 状态延迟完成通知。
- 选择理由：不改变核心执行协议和公开事件语义，变更范围小，兼容现有通知去重逻辑，能同时覆盖系统通知和 TUI 通知。
- 影响：通知层需要维护延迟中的主会话，并响应子智能体与 shell 生命周期事件。

### DEC-002: 为后台 shell 保存任务归属快照
- 阶段：代码审查修复
- 背景：子会话可能在 shell 结束前被删除或尚未完成客户端 hydration，仅依赖当前 session parent 链会丢失后代关系。
- 可选方案：修改核心 shell 元数据协议；仅依赖当前 session 列表；在通知层按 shell ID 保存 owner 及创建时的祖先关系。
- 最终选择：在通知层保存 shell owner/祖先关系，并在 shell 结束或删除时清理；延迟通知最终发送前再次检查后台任务。
- 选择理由：不改变核心协议，覆盖 session 删除、异步 hydration 和事件顺序边界，状态生命周期与 shell 生命周期一致。
- 影响：App/TUI 通知层增加短生命周期 shell 归属索引和相应边界测试。
