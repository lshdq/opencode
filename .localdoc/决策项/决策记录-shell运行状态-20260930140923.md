## 决策列表

### DEC-001: 以客户端事件状态维护活跃 shell

- 阶段：方案设计
- 背景：session execution 可以先于后台 shell 结束，现有无条件 idle 转换会覆盖真实 shell 活跃状态。
- 可选方案：
  1. 新增服务端聚合状态或协议字段；
  2. 让 prompt queue 等待所有后台 shell 结束；
  3. 使用已有 shell started/ended 事件在 TUI 内维护活跃 shell状态，并让 footer idle 收尾尊重该状态。
- 最终选择：方案 3。
- 选择理由：无需改变公共协议和服务端生命周期，避免阻塞用户继续输入，同时能覆盖重连 hydration、多个 shell 和事件乱序边界。
- 影响：变更集中在 mini transport/footer 状态流和对应测试，需要确保 prompt queue 的收尾事件不会覆盖仍活跃的 shell。

### DEC-002: 使用明确的 footer shell 状态并在重建时对账

- 阶段：代码审查后的修复
- 背景：仅用 footer 当前 status 文本判断 shell 是否活跃会被 prompt、blocker、重连和异常路径覆盖；仅从有限 session message 分页重建也可能丢失长期运行 shell。
- 可选方案：
  1. 继续通过 status 文本和最近消息推断，增加更多字符串判断；
  2. 让 prompt queue 等待 shell 结束；
  3. 在 footer 状态中保存明确的活跃 shell 数量，并在 hydration/reconnect/resize 时使用现有 shell inventory 对账，事件仍负责实时增删。
- 最终选择：方案 3。
- 选择理由：状态语义独立于展示文本，允许用户继续输入，不受消息分页限制，并可在断线或 resize 后从服务端现有 shell inventory 恢复真实生命周期。
- 影响：需要扩展 mini 内部 FooterState/FooterPatch，补充 shell inventory 测试桩及重复/乱序、重建和异常路径测试；不改变公共协议。

### DEC-003: 以前台 HTTP 成功和有界 inventory 对账闭合生命周期

- 阶段：第二轮代码审查后的修复
- 背景：前台 `session.shell` HTTP 成功本身表示服务端命令已完成，ended 事件可能丢失；inventory 失败或迟到 started 也不能让旧 shell 永久保持 running。
- 可选方案：
  1. 永远等待 ended 事件；
  2. 以前台 HTTP 成功作为终态确认，并用独立 tombstone 防止迟到 started；inventory 失败时从本轮 projected 状态重建；
  3. 发生事件丢失时直接关闭 footer 状态而不保留 shell 输出生命周期。
- 最终选择：方案 2。
- 选择理由：利用已有 HTTP 完成语义避免前台命令永久挂起，同时保留迟到 ended 的输出补全能力；重建失败采用明确的 projected fallback，并为可选 inventory 设置有界等待。
- 影响：需要区分生命周期终态 tombstone 与 ended 输出去重状态，并增加异常/重建测试；不改变服务端协议。

### DEC-004: 仅保留必要且有界的生命周期 tombstone

- 阶段：第三轮代码审查后的修复
- 背景：正常前台 shell 已观察到 started/ended 后不需要按 event ID 保留 tombstone；长期 session 也不能让每个已结束 shell 永久占用新的集合空间。
- 可选方案：
  1. 所有 shell 永久保留 settled ID；
  2. 仅对 inventory 对账差集和 HTTP success 前未观察到 started 的 shell保留 tombstone，正常 ended/started 去重继续使用既有集合，并对异常 tombstone 设置容量边界；
  3. 删除所有 tombstone，依赖事件顺序。
- 最终选择：方案 2。
- 选择理由：覆盖事件丢失和迟到 started，同时避免正常路径的确定性集合泄漏，并保留异常场景的有限保护。
- 影响：需要调整 shell 生命周期集合的加入/清理条件，并增加 projected/inventory、正常前台 success 和 timeout signal 测试。

### DEC-005: 跨 resize 保留已确认终态

- 阶段：终审后的修复
- 背景：resize 会重建 transcript 去重集合；若普通 ended shell不进入生命周期 tombstone，迟到 started 会在 resize 后重新激活。
- 可选方案：
  1. resize 后继续依赖有限 transcript 去重集合；
  2. 所有确认 ended/completed 的 shell写入已有有界 `shellSettled`，resize 仅清理渲染去重集合；同时删除已结束 shell的 command 长驻引用；
  3. resize 时永久保留全部 started/ended 集合。
- 最终选择：方案 2。
- 选择理由：跨 resize 保留必要的生命周期事实，同时将内存限制在有界 tombstone 和当前/近期渲染去重数据内，不永久保留完整命令映射。
- 影响：正常 ended/completed 会使用有限 tombstone；超过上限的极旧异常事件仍按既定有界降级策略处理，并增加跨 resize 回归测试。

### DEC-006: 分离生命周期事实与 transcript 渲染去重

- 阶段：终审后的修复
- 背景：生命周期集合必须跨 resize 保留以阻止迟到 started，但初始 hydration 的 shell commit 不一定进入 local replay rows；若同一集合同时承担渲染去重，resize 会丢失 shell transcript。
- 可选方案：
  1. resize 时清空全部 shell 集合并接受迟到事件复活；
  2. 分离生命周期集合与当前 transcript 的 rendered-start/rendered-end 集合；resize 根据 local rows 恢复 rendered 标记，再重放 projected shell；
  3. 为每条 hydration shell 强制写入 local rows，扩大 replay 缓存。
- 最终选择：方案 2。
- 选择理由：同时保留跨 resize 的终态事实和完整 transcript 重建能力，不改变 replay 缓存上限，也不允许旧事件复活。
- 影响：新增内部渲染去重集合及 resize 的 local-row seed 逻辑；需要补充初始 completed/running hydration 后 resize 的回归测试。

### DEC-007: 对账终态清理命令引用并合并 resize shell phases

- 阶段：最终审查后的修复
- 背景：inventory 对账确认 shell 已结束后仍保留完整 command 字符串；resize 中 local rows 的 start 与 projection 的 completed terminal 也需要按 shell ID 合并顺序。
- 可选方案：
  1. 保留 command 映射并继续按两个 rendered Set 追加 projection；
  2. 对账终态立即删除 command 映射，并在 resize 中先恢复 local shell rows，再只补充 projection 缺失的 terminal phase；
  3. 让服务端为 transcript 重建提供新的聚合接口。
- 最终选择：方案 2。
- 选择理由：不增加公共协议，释放不可再用于生命周期判断的长命令引用，并确保 shell transcript 始终按 start→terminal 顺序恢复。
- 影响：resize replay 需要暂存/合并 projected shell commits；测试需验证 local-only start、projected completed 和 duplicate started 的真实事件收敛。

### DEC-008: 尊重 Location 范围并隔离 Session 生命周期

- 阶段：最终审查后的修复
- 背景：shell inventory 只覆盖一个 Location；Session 移动后原 Location 的运行 shell 仍由原环境负责完成。旧 Session 的 activeShells 也不能影响新 Session 的 queue idle。
- 可选方案：
  1. 继续把当前 Location inventory 当作 Session 全量状态；
  2. 记录 shell 来源 Location，仅对能确认属于当前 inventory Location 的 shell做缺失结算；Session 切换时显式清零 activeShells；
  3. 为 inventory 增加跨 Location 聚合 API。
- 最终选择：方案 2。
- 选择理由：不改变公共协议，遵循现有 Location-scoped shell API，并避免旧 Session 状态污染新 Session；来源未知的 shell采用保守保活，等待 ended 或后续对账收敛。
- 影响：需要维护轻量 shell Location 线索、增加 Session 移动/新 Session 状态测试；极少数来源未知的丢失事件可能暂时保持 running，这是比错误 idle 更安全的降级。

### DEC-009: 失败回退保留本地事实并丢弃过期对账

- 阶段：最终审查后的修复
- 背景：inventory 失败不应无条件结算旧 Location shell；hydration 中途失败不能丢失本地 active shell；Location 移动期间返回的旧 inventory 不能覆盖新范围。
- 最终选择：以局部候选状态完成 hydration，只有全部必要数据成功且 inventory 仍对应当前 Location 时才替换共享生命周期；失败时恢复原 active 集合并对未知/旧 Location shell 保守保活。新 Session 创建失败时保留旧 transport 的运行状态，只显示失败信息。
- 选择理由：不改变公共协议，以错误保持 running 替代错误显示 idle，避免用户误判仍在运行的 shell 已结束；过期 inventory 直接丢弃，等待下一次有界对账。
- 影响：需要补充 inventory failure/timeout、hydration partial failure、move race 和 new-session failure 回归测试；resize transcript 需要按原始 row/message 顺序合并，而非批量追加 shell rows。

### DEC-010: 将 local-only shell 按 transcript 锚点插入

- 阶段：最终终审后的修复
- 背景：resize 合并时，若 local shell 不在 projected history 中，先追加到 projected 列表会把它固定到 transcript 尾部，随后失去按 local row 位置插入的机会。
- 最终选择：local-only shell 不参与 projected anchor 建立；与普通 local row 一样根据前后可识别 projected anchor 插入，只有没有任何 anchor 时才追加到末尾。补强 hydration 部分失败测试，使其在生命周期已部分更新后验证 command/location 仍保留。
- 选择理由：保持现有 projected 顺序，同时保留 local transcript 的相对位置，不改变协议或扩大 replay 缓存。
- 影响：需要调整 resize merge 的 local shell 分支并增加 local-only shell 前后锚点回归；测试需证明失败后的旧 Location 对账仍保守保活。

### DEC-011: 投影 shell 来源保守推断并保持根执行状态

- 阶段：最终终审后的修复
- 背景：新连接的 projected shell message 本身不携带启动 Location；将当前 inventory Location 直接写入来源会把旧 Location shell 错误结算。另一个问题是前台 HTTP 成功只应结算自身 shell，不能清除仍活跃的根 execution。
- 最终选择：投影 shell 仅在已有 location-switched 历史上下文中记录来源，无法确认时保持未知并保守保活；前台 HTTP 成功后按剩余 shell、root execution 和等待状态选择 running/idle patch，不修改仍活跃的 root 状态。
- 选择理由：避免错误 idle 优先于少量未知 shell暂时保活；不改变公共协议，保持前台 shell 的完成语义与根执行状态独立。
- 影响：需补新连接旧 Location 投影 shell、根执行活跃时前台 HTTP success、真实 desc/reverse projected 顺序和跨行 shell transcript 回归测试。

### DEC-012: 以本轮 projected 终态优先并恢复失败前 transcript

- 阶段：最终终审后的修复
- 背景：hydration 前的 active 快照不能覆盖本轮 projected completed 终态；projected terminal 补齐必须排在同一 shell 之间的 local rows 之后；真实 scrollback reset 后 hydration 失败仍需恢复本地 transcript；inventory 返回校验后还需在 reconcile 前再次校验 token。
- 最终选择：reconcile 时排除本轮已 settled 的 projected shell；为 inventory 结果携带 Location/generation token 并在应用前复核；失败重放统一调用 local-row merge 恢复快照；projected terminal 使用稳定的 local-row 序位插入。
- 选择理由：让最新的 projected 事实优先，避免过期快照复活；失败路径恢复用户已看到的内容；不改变公共协议并将移动竞态限制在本地同步边界内。
- 影响：需要补 projected completed reconnect、混合 terminal 补齐、真实 reset failure 和 response/reconcile race 测试。
