## 缺陷与证据

### F-01 / P1：命令目录 pending 被当成空目录，提前 Enter 误发普通模型请求

- 需求依据：需求第 2 项“提交只等待必需依赖”，TC-005 提前 Enter 保留草稿、资源晚到不自动发送；交互开发记录要求保留 server command 独立端点及语义。
- 持久回归：`packages/tui/test/startup-stability.test.tsx:195-245`，`early Enter never misroutes a server command (pending command catalog: %s)`，**pending=true**。
- 步骤：启动已有 Session；agent/model/provider 正常响应，`GET /api/command` 持有未释放 Promise；输入 `/review captured`，退出自动补全、按 Enter 并泵完原生 double-defer。
- 预期：目录未就绪不能断定它不是 server command，应保持草稿且不发送；目录到达后仍需用户明确再次提交。
- 实际：`expect(sends).toEqual([])` 收到 `["prompt"]`，发生在目录 gate 释放之前。pending=false 的对照参数（即目录已就绪）收到 `["command"]`，证明 HTTP fixture 与 command 路径有效。
- 对应生产逻辑：`packages/tui/src/component/prompt/index.tsx:1180-1183` 将 `data.location.command.list(...)` 的 undefined 以 `?? []` 当作确定空目录；`1344` 只有 isCommand=true 才进入 command，其余进入 `1366` 后的普通 prompt admission。模型可用性检查不替代 slash 命令分类所必需的目录就绪检查。
- 影响：慢启动/慢 Location 命令目录下，把本应展开模板/采用命令覆盖的文本直接交给模型，可触发意外模型执行和费用，并提前清除草稿。不能以四项 UI 或类型检查通过代替此路径验收。
- 最小复现命令：E；完整组合：D。最终两者都失败。**尚未做固定基线加载对照，不断言该问题一定由本次补丁新引入；它是当前需求下可重现的未闭环行为。**
- 修复：本测试代理未做，交回父流程；后续应复跑失败回归和 D 组合，不得 skip。
- 其他已确认生产缺陷：**无**。
