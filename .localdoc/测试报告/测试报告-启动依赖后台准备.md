## 新增 12 条测试

### preparation.test.ts：6 条直接测试真实 createPreparation

1. 一个等待者取消不取消共享工作，也不影响另一个等待者。
2. 准备任务完成时注册的新任务仍纳入等待屏障。
3. 存在其他未完成工作时，fatal 失败立即释放当前和后续等待者，成功完成其他工作不清除失败状态。
4. 非 fatal 失败传播给当前等待者，但不永久污染后续准备。
5. dispose 终止所有等待者、可重复调用，迟到失败不更新错误状态；dispose 后不能再次成功等待。
6. 已取消的请求不能穿过空且就绪的屏障。

### app-startup.test.tsx：6 条真实渲染宿主测试

1. 等待中取消，修改草稿后重新提交，只发送修改后的文本一次。
2. 准备期间权限切换两次显式回到手动，迟到的 auto_approve=true 不能覆盖。
3. Escape 取消后插件替换输入框，草稿保留且不复活自动发送；用户重新 Enter 可以发送。
4. config 可用而 command discovery 未完成时仍不能发送，完成后只发送一次。
5. 自动 continue/fork 的 HTTP 失败保留草稿、出现失败反馈、释放等待，不向新建兜底会话发送。
6. fork HTTP 已发出时用户导航，迟到返回不能恢复旧目标或发送旧草稿。

测试使用真实实现，不复制 submit 或 preparation 算法；既有 `prompt-submit-race.test.ts` 是旧镜像实现测试，本轮未将其当作生产行为覆盖证据，也未修改它。
