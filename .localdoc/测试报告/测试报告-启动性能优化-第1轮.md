`test/cli/acp/*` 三个子进程用例（stdin EOF / initialize / config option）在高负载下超时（7-17 秒量级）。已做 A/B 验证：**还原 acp.ts 到基线后同样抖动**（lifecycle 基线 3 次中 1 挂；带改动空闲时 3/3 过）。结论：既有环境敏感抖动（Windows 子进程生成慢 + 测试机负载），非本次改动回归。

## 根因分析：TC-002 未达 250ms

- 优化前编译产物 `--version` ≈ 440ms（安静），其中模块求值约 400ms
- T2 下沉后 A/B 净收益 ~140-160ms：bun --compile + splitting 下动态导入本就生成独立 chunk，静态图求值占比小于 dev 模式（dev 模式 3.8s→2.4s 的收益主要来自免转译）
- 剩余地板（~340ms）主要是 Bun 运行时初始化 + 23 个命令定义 + effect 子集 + 137MB 二进制加载
- 进一步压缩需重构 index.ts 命令注册为懒注册（yargs async command modules），风险与收益比欠佳，建议列为后续可选项
