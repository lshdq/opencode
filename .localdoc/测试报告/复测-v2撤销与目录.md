## 本轮确认缺陷 F-02 / P1

### 占位符展开后撤销恢复标签，却不恢复隐藏内容

- 持久化测试：`packages/tui/test/prompt-review-regressions.test.ts:184` 起的 `independent: repeated paste expansion can undo back to a payload-bearing placeholder (%s)`，参数 `native` 和 `keyboard`。最终断言在第 203 行。
- 前置：Home 的真实 Prompt，`prompt.paste=compact`。
- 操作：
  1. bracketed paste `AAA1\nAAA2\nAAA3`，得到 `[Pasted ~3 lines] `。
  2. 在末尾再次 bracketed paste 完全相同内容，生产逻辑将该占位符展开为真实三行文本。
  3. 两次撤销选择替换的 native 步骤（先撤销插入，再撤销删除）；分别使用 `input.undo()` 和真实 `mockInput.pressKey("z", { ctrl: true })` 派发。
  4. 可见文本确实回到原标签；调用生产 `Selection.copy`，清选区后真实 Enter 提交，捕获 HTTP POST /prompt body。
- 预期：复制值与请求 text 都是 `AAA1\nAAA2\nAAA3 `。
- 实际：**二者都是 `[Pasted ~3 lines] `**。并非仅 helper/内部 snapshot 断言失败，也不是 HTTP 超时；实际请求已经收到。

```text
copied: "[Pasted ~3 lines] "
submission: {
  agents: [], delivery: "steer", files: [],
  text: "[Pasted ~3 lines] "
}
```

### 定位依据与建议交回点

- `prompt/index.tsx:1472-1482` 的 `expandPastedText` 在 `input.insertText(part.text)` 前先执行 `input.extmarks.delete(extmarkId)`。
- 新绑定器在真实 native mutation 前调用 capture；`index.tsx:1851-1861` 的 capture 先执行 `syncExtmarksWithPromptParts()`。
- `syncExtmarksWithPromptParts`（837-905）仅根据尚存在的 extmark 重建 pasted 列表。因此占位符的隐藏内容在首次 native 编辑快照形成前已经被删除，undo 栈无法恢复它。
- 同文 paste 展开和鼠标展开共享此函数；本轮**实际验证的是同文 paste**，没有把代码上的共享入口当作已执行鼠标测试。
- 交回父流程：让展开操作删除 extmark 与编辑步骤之间保留正确的展开前元数据边界，再原样重跑这两个红测。测试职责内不提供生产修改。
- 没有运行旧固定基线对照来判断此展开缺陷最早引入时间；报告为当前修复工作树中仍存在的验收缺口，不声称已证明是最新补丁首次引入。
