## 失败与测试修正说明

### 1. 未解决：官方 ripgrep 隐藏配置目录匹配

- 文件/行：`packages/core/test/ripgrep.test.ts:132`。
- 场景：临时目录下同时放置 `.opencode/config` 和 `.git/config`，内容均为 `needle`；`find` 前面的断言通过，调用 `ripgrep.grep({ cwd, pattern: "needle", include: "config", limit: 10 })` 返回空数组。
- 预期包含 `.opencode/config`，实际 `[]`。第一轮和单独重跑同样失败，无并行依赖才失败的证据。
- 只读核对：`packages/core/src/ripgrep.ts` 与该测试相对固定 base 均无 diff；ZIP binary 改动限定提取分支，普通 spawner 的新增行为受 MCP own gate 限定。这些是定位线索，**不是干净 base 实际运行证明，也不足以直接断言“与本补丁无关”**。
- Shell 无 `rg` 命令；没有为诊断下载、覆盖或清理全局缓存。实际选中 rg 的版本、环境影响及根因待父流程处理。
- 没有修改生产、跳过该用例或放宽断言。此项阻止本会话给出“所有相关测试通过”。

### 2. 已修正：新增环境测试的错误比较前提

- 首次新增大环境测试同时要求 wrapper 不继承 PATH、又要求与未包装 Bun spawner 的完整输出一致，但没有提供 PATH 键。
- 实测未包装 Bun 目标自动获得 controller PATH，而 Job 目标按原 env block 没有 PATH；因此“完全相等”前提与“不得继承”预期冲突，并非该输出证明 wrapper 丢失了配置值。
- 测试改为**显式配置空 PATH**，保持“不继承父 PATH”的严格断言，并继续比较整个大型输出。随后新增 3 例及完整 MCP 五文件套件均通过。没有改生产代码。
- 未配置 PATH 时两条运行路径的差异保留为运行时兼容性观察，不宣称已对所有调用者证明零影响。
