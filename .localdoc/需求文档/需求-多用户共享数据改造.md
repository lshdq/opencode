# 需求：多用户共享数据改造

## 背景与目标

Windows 适配时引入了单用户安全加固：通过 PowerShell 将 `data` 目录与 `opencode.db` 及其 sidecar 文件的 DACL 重写为"仅当前用户 SID"（owner-only），导致多个 Windows 账户无法共用同一份配置、会话、缓存等数据。

目标部署形态：**多 Windows 账户 + 共享根目录**（所有用户的 `XDG_DATA_HOME / XDG_CACHE_HOME / XDG_CONFIG_HOME / XDG_STATE_HOME` 统一指向共享位置，如 `D:\Program\opencode\data`）。

本任务彻底去除该加固，使目录/文件 ACL 一律继承父目录；同时消除勘察中发现的两个多用户竞态，并输出部署前置约束。

## 功能描述

### 核心功能

1. **删除 Windows DACL 加固运行时代码**（方案 A：彻底删除）：
   - 删除 `packages/core/src/database/sqlite-permissions.ts`
   - `packages/core/src/database/sqlite.bun.ts` / `sqlite.node.ts`：删除 `privateFile` 分支与 `prepareDatabase`、`FileModeEffect` 引用
   - `packages/core/src/database/database.ts`：删除 `Options.privateDirectory` 字段及向 `sqliteLayer` 的传参
   - `packages/core/src/database/sqlite.ts`：删除 Config 的 `privateDirectory`
   - `packages/cli/src/database-path.ts`：删除 `databaseOptions` 的 `privateDirectory`
   - 删除 `packages/util/src/file-mode.ts`、`file-mode-windows.ts`、`file-mode-effect.ts`（删除前确认无其他引用）
   - `packages/util/src/fs-util.ts`：`writeJson/writeWithDirs` 的 Windows FileMode 分支删除，收敛为 `if (mode) yield* fs.chmod(path, mode)`
   - `packages/cli/src/services/service-registration.ts`、`service-config.ts`：删除所有 `FileMode`/`FileModeEffect` 调用（`{ mode: 0o600 }` 参数保留）
   - `packages/sdk` 测试中 `privateDirectory` 用法删除（SDK 公开选项直接删除，接受 breaking change）
2. **rg.exe 下载加锁**（`packages/core/src/ripgrep/binary.ts`）：下载→解压→copyFile 全程用 Flock 串行化（锁位于共享 `state/locks`，跨用户生效），消除多用户首次并发竞态。
3. **service-config 写入 temp 唯一化**（`service-config.ts` 的 `write`）：固定 `configFile + ".tmp"` 改为带随机后缀，消除并发覆盖窗口。（`service-registration.ts` 的 temp 已带服务实例 id，无需改。）
4. **测试调整**：删除/改写引用被删模块的测试与 fixture（详见测试用例文档）。
5. **部署前置文档**：见附录 A。

### 边界与约束

- **Unix 平台行为不变**：`database.ts` 的 `restrictToOwner`（chmod 0o600）保留；各处 `{ mode: 0o600 }` 参数保留。
- 不改变目录布局与 XDG 解析逻辑（`global.ts` / `global-roots.ts` 不动）。
- 不实现 per-user 命名空间拆分；共享即全部共享（会话、凭证、KV、缓存）。
- 多用户运维约束（版本统一、禁用自动更新、本地磁盘、一次性 ACL 授权）作为部署文档输出，**不在代码内强制**。
- 工作区既有未提交改动（auto-login、server auth/fetch/cors 相关，基线见 `.localdoc/审查记录/基线快照-多用户共享数据改造-20261022145041.patch`）必须完整保留，不得回退、覆盖。

## 输入输出

- 输入：现有单用户加固代码库（v2 分支，基线 commit `69d12f0441e4afe3a29a659db219834c683aa2de`）。
- 输出：去除加固后的代码库 + 调整后的测试 + 部署前置文档。行为变化：
  - Windows 上新建目录/文件 ACL 继承父目录；
  - 自定义 `OPENCODE_DB` 指向共享目录不再报 "Unsafe custom SQLite directory"。

## 非功能需求（性能/安全/兼容性）

- 安全：去除 owner-only DACL 后，共享根内数据对授权用户组全部可见/可写（含服务密码、API 凭证）——这是"共用"语义的既定接受项，由部署侧通过共享根 ACL 限定授权范围。
- 兼容性：SDK `privateDirectory` 选项删除为 breaking change（本 fork 接受）；历史已被收紧 ACL 的目录需一次性解锁（部署文档）。
- SQLite 多进程：依赖 WAL + busy_timeout=5000 + 迁移事务（后到者失败重试可恢复），不引入额外锁层。

## 依赖

- 既有模块：Flock（`packages/util/src/flock.ts`，锁根 `state/locks`）、ripgrep 下载器、service-config 写入路径。
- 无新增第三方依赖。

## 验收标准

1. `bun run check`（仓库根）通过。
2. `packages/core`、`packages/util`、`packages/cli`、`packages/sdk` 的 `bun test` 通过（删除/改写后的测试集）。
3. 代码中不再存在 `FileMode`、`sqlite-permissions`、`privateDirectory` 的运行时引用（除本任务新增测试外）。
4. 新增/保留测试覆盖：共享 data 根双进程并发启动成功；非 Unix chmod 0o600 行为不变。
5. 基线快照中的既有改动（auto-login 等）完整保留。

## 附录 A：部署前置（多 Windows 账户 + 共享根）

1. **共享根一次性授权**（管理员）：
   `icacls D:\Program\opencode\data /grant "<用户组>:(OI)(CI)M" /T`
   必须含"修改"（含删除子项），否则 Flock stale 锁清理会失败卡到超时。
2. **历史已收紧目录解锁**（旧版本重写过 owner-only DACL 的目录/文件）：
   `icacls <共享根>\opencode /reset /T /C`（恢复继承；或迁移数据后重建）。
3. **全机统一 opencode 版本**：共享 DB 的 schema 由最先启动的版本决定，版本混用会导致 schema 不匹配。
4. **共享部署禁用自动更新**（`update: disable` 或 `OPENCODE_DISABLE_AUTOUPDATE=1`）：自更新器在共享安装目录上会竞争替换二进制，由管理员手动统一更新。
5. **托管服务进程归属**：共享 `state/service.json` = 全机一个托管服务，宿主用户注销即停止；建议沿用 start-task.ps1 的 per-user `--standalone` 模式，或以计划任务常驻。
6. **DB 必须在本地磁盘**：SMB/网络盘上 SQLite WAL 共享内存失效。
