# 需求：启动网络健壮性（IPv6 环境启动卡死修复）

## 背景与目标

在配有公网 IPv6 的 Windows 机器上，开启 IPv6 后 opencode 启动长时间卡死（未登录 opencode 账号）。经代码调查与本机试验定位根因：

1. **启动关键路径存在联网等待**：`packages/core/src/models-dev.ts` 的 `populate` 在无本地缓存时必须联网拉取 `https://models.opencode.ai/api.json`，失败经 `Effect.orDie` 变为致命缺陷；legacy Provider 状态初始化（`packages/opencode/src/provider/provider.ts:1404`）会 await 它，导致 TUI 卡死/崩溃。
2. **Bun fetch 无 IPv6 回退**：本机试验（Bun 1.3.14 / Windows）证明 `fetch` 不遵循 `dns.setDefaultResultOrder("ipv4first")`（default/ipv4first/verbatim 三种模式均选择 IPv6），且 IPv6 黑洞（TCP 接受连接但不响应）时 fetch 无限挂起（120s 超时无输出）——无 Happy Eyeballs 回退。`models.opencode.ai`、`api.opencode.ai` 均为 Cloudflare 双栈域名，IPv6 路由不通的机器上启动即挂死。
3. **升级检查无超时**：`packages/opencode/src/installation/index.ts` 的 `latest()` 对 GitHub/npm 等版本源拉取无超时（虽为后台 fire-and-forget，但会挂住 fiber 与连接）。

**目标**：外网不可达（含 IPv6 选路黑洞、DNS 异常）时 opencode 仍能正常启动——启动关键路径零联网等待；后台联网任务有界（超时）且成功后自动补全数据。

## 功能描述

### 核心功能

1. **ModelsDev populate 去网络化**（`packages/core/src/models-dev.ts`）：
   - `populate` 只走三级降级：磁盘缓存 → 内置快照（`OPENCODE_MODELS_DEV`）→ `{}`，永不联网等待；
   - 移除 populate 路径上的 `Effect.orDie` 致命语义（降级时输出 warning 日志）；
   - 联网拉取完全交给既有的后台 `refresh()`（layer 初始化时 fork + 每 60 分钟定时，已存在），后台拉取保留现有 10s 超时与重试。
2. **legacy Provider 状态在模型目录刷新后重建**（`packages/opencode/src/provider/provider.ts`）：
   - Provider 的 `InstanceState` 订阅 `ModelsDev.Event.Refreshed` 事件，事件到达时使自身缓存条目失效（`InstanceState.invalidate`），下次访问用新目录重建；订阅生命周期与状态条目绑定（失效/释放时自动取消，无泄漏、无重复订阅）。
   - V2 插件路径（`packages/core/src/plugin/models-dev.ts`）已有 Refreshed → catalog.reload() 反应式重建，无需改动；httpapi provider 路由每次请求直接 `get()`（上游 invalidate 后自动取新），无需改动。
3. **升级检查超时**（`packages/opencode/src/installation/index.ts`）：
   - `latest()` 中所有 HTTP 版本源拉取（GitHub、npm registry、scoop、choco、brew formulae API）加 10s 超时。

### 边界与约束

- **不改动** `config.ts` 中 wellknown 远程配置与账户 console config/token 拉取（用户选择最小范围；未登录场景不触发）。
- **不实现** `OPENCODE_FORCE_IPV4` 开关：本机试验证明 Bun 1.3.14 fetch 不遵循 `dns.setDefaultResultOrder`，开关无效（记录为已知限制）。
- 正常网络环境行为不变：有缓存时启动路径本就无网络调用；无缓存时首次目录由后台拉取补全。
- 改动最小化、对上游合并友好（win-adapt 分支定期 merge upstream）。
- 遵循仓库 Effect v4 规范与现有代码风格。

## 输入输出

- 输入：环境变量 `OPENCODE_MODELS_URL`（默认 `https://models.opencode.ai`）、`OPENCODE_MODELS_PATH`、`OPENCODE_DISABLE_MODELS_FETCH`（行为保持不变）。
- 输出：
  - `ModelsDev.get()`：同步降级数据（磁盘/快照/空目录），失败路径输出 warning 日志而非缺陷；
  - `ModelsDev.Event.Refreshed` 事件（已有）驱动 legacy Provider 状态重建；
  - `Installation.latest()`：超时（10s）后失败，不再无限挂起。

## 非功能需求（性能/安全/兼容性）

- 启动关键路径（TUI 渲染前）零联网等待：外网完全不可达时启动耗时与纯本地启动一致。
- 后台拉取失败不产生致命缺陷、不崩溃进程；成功后目录自动补全，无需重启。
- 订阅/失效无资源泄漏（失效条目时订阅随条目 scope 释放）。
- 兼容性：`ModelsDev.Service` 接口签名不变；`OPENCODE_MODELS_PATH`/`OPENCODE_DISABLE_MODELS_FETCH` 语义不变。

## 依赖

- 既有机制：`Effect.cachedInvalidateWithTTL`（models-dev 缓存）、`EventV2`（`packages/core/src/event.ts`，`subscribe` 返回 `Stream`）、`InstanceState`（ScopedCache，含 `invalidate`）、后台 `refresh()` 定时任务。
- 参考实现：`packages/core/src/plugin/models-dev.ts:178-181`（Refreshed 订阅 → reload 模式）。

## 验收标准

1. `OPENCODE_MODELS_URL` 指向不可达地址且无本地缓存时：`ModelsDev.get()` 立即返回降级数据（`{}`），进程不崩溃、不长时间阻塞；Provider/TUI 可正常初始化。
2. 本地缓存存在时：`get()` 返回缓存内容且启动路径无网络调用。
3. 后台拉取成功后：发布 `Refreshed`，legacy Provider 状态在下次访问时以新目录重建（单测验证失效重建）。
4. 版本源 HTTP 拉取挂起时 `latest()` 在 10s 内失败返回，不无限挂起。
5. 正常网络下行为与现状一致（既有测试全部通过）。
6. `bun typecheck` 在 `packages/core`、`packages/opencode` 通过。
