# 需求：新会话默认智能体

## 背景与目标

当前 TUI 与 Web/Desktop App 在创建新会话时可能沿用进入新会话前的智能体，导致配置中的 `default_agent` 未生效。新会话应以当前工作区解析出的默认智能体作为初始智能体。

## 功能描述

### 核心功能

- TUI 与 Web/Desktop App 创建新会话时，初始智能体使用当前 location 的 `default_agent`。
- 服务端现有的智能体列表顺序作为默认智能体来源：解析后的默认智能体位于可选智能体列表首位。
- 用户在当前新会话草稿中手动选择智能体后，保留该选择并用于提交。

### 边界与约束

- 已存在会话的智能体选择和会话级记忆不变。
- 恢复、继续、分叉会话的既有智能体语义不变。
- 模型的继承、回退和手动选择逻辑不变。
- 显式启动参数的既有语义不变。

## 输入输出

- 输入：当前 location 的 agent catalog、配置中的 `default_agent`、当前会话/草稿状态。
- 输出：新会话创建请求携带默认智能体，或在新会话草稿 UI 中显示默认智能体。

## 非功能需求（性能/安全/兼容性）

- 不新增网络请求；复用已有 agent catalog。
- 不改变已有会话持久化数据格式。
- 保持 TUI 与 Web/Desktop App 的现有交互和模型行为。

## 依赖

- Core/Server 已将解析后的 `default_agent` 排在 agent list 首位。
- TUI location-scoped data 与 App location-scoped model selection。

## 验收标准

1. 配置 `default_agent: "reviewer"` 时，从已有非 reviewer 会话创建新会话，初始智能体为 reviewer。
2. TUI 和 Web/Desktop App 均满足上述行为。
3. 新会话草稿内手动切换智能体后，提交使用手动选择。
4. 已有会话切换智能体、模型选择及恢复/分叉行为无回归。
5. 相关单元测试、TUI 测试、类型检查和代码审查通过。
