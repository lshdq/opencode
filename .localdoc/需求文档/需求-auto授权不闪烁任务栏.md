# 需求：auto授权不闪烁任务栏

## 背景与目标

当前全局 TUI 插件 `C:\Users\lshdq\.config\opencode\plugins\taskbar-flash.ts` 会在收到 `permission.asked` 事件时直接调用 `FlashWindowEx`。当 TUI 处于 auto 权限模式时，同一请求会被自动批准，不需要用户介入，但插件仍会闪烁任务栏图标。

目标是在不修改 OpenCode 仓库生产源码和内置通知的前提下，使插件只为真正进入人工待确认队列的权限请求闪烁。

## 功能描述

### 核心功能

- 收到 `permission.asked` 后，查询 `api.state.session.permission(sessionID)`。
- 仅当当前请求存在于该会话的人工待确认权限队列时闪烁任务栏图标。
- auto 模式接管且未进入人工待确认队列的权限请求不闪烁。
- 初始 auto 配置和运行时 auto/normal 模式切换均按实时状态生效。
- 为被跳过的 auto 权限请求写入诊断日志。

### 边界与约束

- 只修改全局 `taskbar-flash` 插件，不修改仓库生产源码或 TUI 插件 API。
- 任务完成、问题确认、会话错误和普通模式权限请求的闪烁行为保持不变。
- 子代理不闪烁、事件去重和前台激活后停止闪烁的现有行为保持不变。
- 判定依赖当前 TUI 事件处理顺序：内部同步层先更新权限队列，随后 TUI 插件处理同一事件。
- auto 回复失败后的人工接管不在本次范围内；当前 TUI 本身尚未将失败请求恢复到人工队列。

## 输入输出

- 输入：TUI `permission.asked` 事件、对应会话的实时人工权限队列。
- 输出：需要人工授权时调用任务栏闪烁；auto 自动授权时跳过闪烁并记录日志。

## 非功能需求（性能/安全/兼容性）

- 每次权限事件仅对当前会话权限数组进行一次 ID 查询，不引入网络请求或定时等待。
- 不改变 Windows FFI 参数、窗口句柄捕获和停止闪烁逻辑。
- 修改插件后需要完全退出并重启 OpenCode 才能生效。

## 依赖

- TUI 插件 API：`api.state.session.permission(sessionID)`。
- TUI 同步层在插件事件监听器之前同步维护人工权限队列。
- Bun 运行时和现有 `bun:ffi` Windows 调用。

## 验收标准

- `auto_approve: true` 启动后，自动批准权限请求时任务栏不闪烁。
- 运行时切换到 auto 后，新的自动批准权限请求不闪烁。
- 运行时切换到 normal 后，新的人工权限请求正常闪烁。
- 问题确认、任务完成和会话错误仍正常闪烁。
- 子代理事件仍不触发闪烁。
- 日志能够区分被 auto 跳过的权限请求和触发闪烁的人工权限请求。
