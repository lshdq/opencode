# 需求：跨用户项目身份解析

## 背景与目标

本机将 `XDG_DATA_HOME` 等目录配置为机器级环境变量（指向 `D:\Program\opencode\data\*`），多个 Windows 用户（如 `lshdq` 与 runas 启动的 `aiRunner`）共用同一个 `opencode.db` 与服务注册目录。

V2 的会话列表按 Project ID 过滤。`Project.resolve`（`packages/core/src/project.ts`）对 git 仓库的项目身份解析依赖 `git rev-parse` / `git remote get-url` 子进程：

- 非 git 目录：Project ID = 绝对路径哈希，与用户无关 → 多用户解析一致，会话互通。
- git 仓库：Project ID = remote URL 哈希（需 git 子进程成功）。非仓库属主用户运行 git 会因 dubious ownership（或权限不足、git 不可用）失败，`Git.repo.discover` 返回 undefined，回退为路径哈希 ID → 同一仓库在不同用户下解析成两个 project，会话互相不可见。

实测证据：共享库中 `D:/works/thirdparty/opencode` 同时存在 project `18fbf414`（vcs=git，616+36 会话，属主用户）与 `0bc63334`（vcs=null，0 会话，另一用户回退产生）；`D:/temp/aitemp`（无 .git）两用户共用同一 project `aed4c336`。

目标：`.git` 标记存在但 git 子进程失败时，通过纯文件读取 `<.git>/opencode` 缓存获得稳定项目身份，使同一仓库在任何用户/受限权限下解析出同一 Project ID。

## 功能描述

### 核心功能

1. **写缓存**：`persist()` 内，git 项目成功解析后，把最终 Project ID 写入 `<vcs.store>/opencode`（`vcs.store` 即 git commonDirectory，通常为 `.git` 目录）。仅当文件不存在或内容不同才写；写失败不影响解析流程。
2. **读回退**：`resolve()` 内，当 `fs.up` 找到 `.git` 标记但 `Git.repo.discover` 失败时，复用现有 `cached()` 读取 `<marker>/opencode`：
   - 命中 → 以缓存 ID 作为项目 ID 持久化；`directory`/`canonical` = 标记所在目录（`path.dirname(marker)`）；`vcs = { type: "git", store: marker }`（保证 upsert 不把已有行的 vcs 降级为 null）。
   - 未命中（含 `.git` 为文件即 linked worktree 的场景，路径拼接后读取自然失败）→ 维持现状：路径哈希回退，`vcs: undefined`。

### 边界与约束

- `.git` 为文件（linked worktree）的场景**不在本期范围**，维持现状路径哈希回退。
- 不清理历史脏数据（如共享库中已存在的空 project `0bc63334`）。
- 不修改 git 调用方式（不注入 safe.directory、不改 Git 服务）。
- 行为保持：无 `.git` 的目录、git 正常可用的仓库，解析结果与现状完全一致。
- 信任边界不变：现有代码在 discover 成功时已信任 `.git/opencode`（作为 `previous`，无 remote 时直接作为 ID），本次不引入新信任面。

## 输入输出

- 输入：`Project.resolve` 的目录绝对路径（不变）。
- 输出：`Resolved`（id/directory/canonical/vcs），git 失败场景下 id 从缓存文件获得。
- 副作用：git 仓库成功解析后 `.git/opencode` 文件包含最终 Project ID（纯文本、trim 语义与现有 `cached()` 读取一致）。

## 非功能需求（性能/安全/兼容性）

- 性能：每次成功解析最多一次文件内容比对与按需写入；读回退仅在 git 失败路径上多一次文件读取。无额外子进程。
- 安全：`.git/opencode` 为本地惰性文件，对 git 无副作用；内容为 bare ID 字符串（trim）。
- 兼容性：`.git/opencode` 旧内容（如旧版本写入的 ID）天然兼容——首次由属主用户成功解析后按需刷新为当前 ID。
- 数据兼容：project_id 分桶不变（正常路径 ID 完全一致）；新能力仅让受限用户命中同一 ID。

## 依赖

- 仅依赖现有模块：`FSUtil.Service`（文件读写）、`Git.Service`（不变）、`ProjectTable` upsert 语义。
- 无第三方新增依赖。

## 验收标准

1. git 仓库（含 remote）成功解析后，`.git/opencode` 存在且内容为最终 Project ID（remote 哈希 ID）。
2. git 子进程失败（discover 返回 undefined）且缓存存在时，`resolve` 返回缓存 ID，而非路径哈希 ID；返回的 `vcs.type === "git"`。
3. git 失败且无缓存 / `.git` 为文件时，维持现状路径哈希回退。
4. 无 `.git` 目录的解析行为与现状一致。
5. `packages/core` 通过 `bun typecheck` 与新增/既有 `bun test test/project.test.ts`；仓库根 `bun run check` 通过。
