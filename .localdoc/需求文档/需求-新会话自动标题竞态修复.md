# 需求：新会话自动标题竞态修复

## 背景与目标

新会话首次收到任务后，服务端会并发生成会话标题和首轮模型响应。当前自动改名可能因首轮响应事件先提交而被丢弃，导致会话长期显示 `New session...` 默认标题。

目标是在不覆盖用户手动改名的前提下，确保正常的事件并发不会丢失自动标题。

## 功能描述

### 核心功能

- 首轮模型响应与标题生成并发发生时，自动标题提交发生序号冲突后可安全重试。
- 重试复用已生成的标题，不重复调用标题模型。
- 标题已经被用户或插件修改时，自动标题必须放弃，不能覆盖显式标题。

### 边界与约束

- 仅修复新会话自动标题，不批量修改历史会话。
- 保留标题模型失败、标题 agent 不可用等现有失败行为。
- 重试必须有界，不能因为持续事件流造成无限循环。
- 不改变 Web/Desktop/TUI 的默认标题展示策略。

## 输入输出

- 输入：新会话首条用户消息、标题模型生成结果、会话事件序列及当前持久化标题。
- 输出：成功时持久化 `session.renamed` 事件和生成标题；显式改名或不可恢复失败时保持当前标题。

## 非功能需求（性能/安全/兼容性）

- 不增加标题模型调用次数；仅在持久化序号冲突时重试改名事件。
- 保持事件序列乐观并发保护，避免覆盖并发的手动改名。
- 兼容现有未命名会话和历史时间戳 fallback 标题。

## 依赖

- `packages/core/src/session/title.ts`
- `packages/core/src/session/runner/llm.ts`
- `packages/core/test/session-runner.test.ts`
- Effect Bus 持久化事件序列和 SessionStore。

## 验收标准

1. 首轮助手事件在自动标题提交前后并发发生时，最终会话标题为模型生成标题。
2. 首轮事件持续产生时，自动标题不会无限重试或重复调用标题模型。
3. 自动标题生成期间发生手动改名时，最终标题保持手动标题。
4. 标题模型失败时，既有重试和默认标题行为不回归。
5. core 定向测试、项目检查和独立代码审查通过。
