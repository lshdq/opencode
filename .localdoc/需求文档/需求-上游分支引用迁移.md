# 需求：上游分支引用迁移

## 背景与目标

官方上游的长期分支已从 `v2` 调整为 `dev`，仓库中仍有部分活动代码、CI、技能和构建文档引用 `upstream/v2`。目标是将这些有效引用统一迁移到 `upstream/dev`，避免构建和同步流程继续依赖已变更的上游分支。

## 功能描述

### 核心功能

- Windows CI 从官方上游 `dev` 分支准备 `upstream/dev` 引用。
- Windows 构建运行时、测试 fixture 和文档使用 `upstream/dev` 作为上游基线。
- fork-development 与 windows-build 技能说明使用 `upstream/dev`。
- 上游差异查看命令使用 `upstream/dev`。

### 边界与约束

- 保留 fork 自身长期分支 `v2` 及 `origin/v2`。
- 保留产品/API 路径、版本标签、主题变量和普通 Git 测试 fixture 中的 `v2`。
- 不改写未跟踪的 `.localdoc` 历史需求、测试、审查和交付记录。
- 不改变“取 `HEAD` 与已合入上游基线共同祖先版本”的构建语义。

## 输入输出

- 输入：当前 fork 工作区、官方 `upstream/dev` 分支引用。
- 输出：有效文件中不再存在指向上游 `v2` 分支的活动引用；构建、测试和文档改用 `upstream/dev`。

## 非功能需求（性能/安全/兼容性）

- 不新增网络操作；CI 仍只在已有预检步骤中 fetch 官方上游。
- 不改变构建产物命名中的产品版本语义。
- 保持 Windows 构建测试和仓库类型检查通过。

## 依赖

- Git 远程 `upstream` 指向 `https://github.com/anomalyco/opencode.git`。
- Bun 及仓库现有测试/检查命令。

## 验收标准

1. Windows CI fetch `refs/heads/dev` 到 `refs/remotes/upstream/dev`，并使用该引用计算 merge-base。
2. CLI 构建运行时与测试 fixture 使用 `upstream/dev`。
3. 活动技能、构建文档和上游差异 story 使用 `upstream/dev`。
4. 有效文件中不存在 `upstream/v2` 或 `refs/remotes/upstream/v2` 的活动引用。
5. `packages/cli` 专项测试和根目录 `bun run check` 通过。
