# 需求：Shell任务状态与完成通知

## 背景与目标

修复桌面 App 中后台 shell 运行状态显示和完成通知过早触发的问题，避免用户误以为任务已完成，以及 Windows 任务栏因错误完成通知而闪烁。

## 功能描述

### 核心功能

1. 主任务已结束、但其后台 shell 仍在运行时，相关会话标签页继续显示运行中的进度指示器。
2. 主任务收到完成事件时，如果仍有子任务或后台 shell 运行，不发送完成通知。
3. 所有子任务和后台 shell 均结束后，才发送一次根任务完成通知。
4. 保持现有错误通知、通知去重、跨窗口协调和会话点击跳转行为。

### 边界与约束

- 只影响 App/桌面通知和会话状态显示，不改变服务端任务执行语义。
- 运行中的 shell 通过 shell 元数据中的 `sessionID` 归属会话。
- 子任务包含根会话的后代会话，通知只针对根会话。
- 重复完成事件不得重复触发通知。
- 不增加每个标签页的高频轮询；优先使用现有数据层事件和缓存。

## 输入输出

- 输入：会话执行生命周期事件、shell 创建/退出/删除事件、会话状态和 shell 缓存。
- 输出：会话标签页运行进度指示器，以及平台系统通知/声音。

## 非功能需求（性能/安全/兼容性）

- 保持现有 SolidJS 响应式模型和数据层缓存策略。
- 不影响 Windows、macOS、Linux 和 Web 平台的既有通知接口。
- 不引入未经必要验证的全量轮询或重复网络请求。

## 依赖

- `@opencode/client/solid` 会话、shell 数据层。
- App 通知协调器和平台通知接口。
- 现有 App tabs 回归测试及通知状态单元测试。

## 验收标准

1. 仅后台 shell 运行时，根会话标签页的 `session-progress-indicator-v2` 可见；shell 退出后消失。
2. 根会话完成事件先到、子任务或 shell 仍运行时，不产生系统完成通知。
3. 最后一个子任务或 shell 退出后，产生一次完成通知。
4. 重复生命周期事件、失败事件和已有的打开标签页限制行为保持正确。
5. 相关单元测试、回归测试、类型检查和项目检查通过。
