# 需求：Kimi启动模型修复

## 背景与目标
旧供应商 kimi-for-coding 已从当前 models.opencode.ai 目录移除。中国站新标识为 kimi-code-plan-cn，接口仍为 https://api.kimi.com/coding/v1。恢复 opencodeKimi.cmd 启动与 K3 调用。

## 功能描述
### 核心功能
- 启动模型为 kimi-code-plan-cn/k3。
- 将已有旧供应商 API 凭据关联至新中国站供应商，保留旧条目。
- dev-fast/dev-standard/dev-deep 使用同一 K3，档位分别 low/high/max。
### 边界与约束
- 保留其他凭据和配置，不记录或输出密钥。
- 执行开始时脚本已由外部改为新标识，应视为既有状态。
- 使用现有安装版本 1.18.31.w2 验证；仅在验证发现明确缺陷时调整方案。

## 输入输出
输入：D:\Program\opencode\opencodeKimi.cmd；用户数据目录的 auth.json。
输出：可识别并调用的新供应商 K3，以及验证报告。

## 非功能需求（性能/安全/兼容性）
凭据处理限定本机，不输出凭据内容，不写入版本库；保留无关 auth 条目。新版目录采用 OpenAI-compatible 协议，需以实际调用验证。

## 依赖
本机 opencode.exe、现有 Kimi API 凭据、模型目录及 Kimi 中国站网络。

## 已批准方案
用户确认中国站方案及 Auto 模式：修改启动模型、复制关联已有凭据，检查模型目录和三个子智能体的解析结果，执行一次最小模型请求；独立测试及审查。2026-09-20 执行前发现启动脚本已正确，因此保留该既有修改，仅补齐缺失凭据关联。

## 验收标准
1. 脚本模型标识正确且参数透传不受影响。
2. 新供应商凭据与旧供应商一致，旧凭据和其他条目保持不变。
3. 安装版可以解析 kimi-code-plan-cn/k3 和 low/high/max。
4. 启动环境中的三个开发子智能体使用预期模型与档位。
5. 一次最小真实请求成功；若有网络或配额阻塞，明确记录，不将静态检查等同完整调用通过。
