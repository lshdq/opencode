# 需求：Windows构建使用工作区版本

## 背景与目标

当前 Windows 构建将合入上游基线版本作为产物版本，导致当前工作区 `package.json` 为 `2.0.32` 时仍生成 `2.0.26`。构建应使用当前工作区声明的版本。

## 功能描述
### 核心功能

- 从当前工作区根目录 `package.json` 读取并校验构建版本。
- 使用该版本设置 `OPENCODE_VERSION`、构建目录标识、构建元数据和部署文件名。
- 保留上游基线提交信息用于构建追溯。

### 边界与约束

- 版本必须是标准三段式语义版本。
- `packageManager` 仍必须为 `bun@1.4.2`。
- 不猜测版本、不硬编码版本、不改变上游基线提交记录。

## 输入输出

- 输入：当前工作区根目录 `package.json`。
- 输出：版本与工作区一致的 Windows x64 executable 及构建元数据。

## 非功能需求（性能/安全/兼容性）

- 保持现有冻结依赖、源码哈希、隔离 smoke 和部署冲突保护。
- 无新增运行时依赖。
- 无持久化格式变更。

## 依赖

- Bun 1.4.2。
- 当前工作区根目录 `package.json`。
- 既有 Windows 构建脚本和上游基线追溯逻辑。

## 验收标准

- 工作区版本为 `2.0.32` 时，构建产物 `--version` 和部署文件名均为 `2.0.32`。
- 上游基线信息仍写入 `build-metadata.json`。
- 版本来源回归测试通过。
- Windows x64 构建、隔离 smoke 和部署验证通过。
