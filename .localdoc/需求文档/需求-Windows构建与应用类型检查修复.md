# 需求：Windows构建与应用类型检查修复

## 背景与目标

Windows x64 构建入口因仓库当前不包含 enterprise 包的符号链接而提前失败；同时 `packages/app` 类型检查存在两个迁移 schema 类型错误。修复后应恢复构建流程，并使仓库类型检查通过。

## 功能描述
### 核心功能

- Windows 链接修复逻辑只校验仓库实际跟踪的链接文件；当前仓库保留并恢复 app 链接。
- 修正应用持久化迁移转换的字面量类型推断，不改变存储格式或运行时迁移行为。

### 边界与约束

- 不绕过已跟踪文件的符号链接安全校验。
- 不修改用户配置、应用服务或日常 executable 激活状态。
- 保持 Windows x64、Bun 1.4.2 构建契约。

## 输入输出

- 输入：当前 Git 工作区及持久化历史数据。
- 输出：通过类型检查的源码，以及可继续执行构建契约的 Windows 链接修复逻辑。

## 非功能需求（性能/安全/兼容性）

- 维持对已跟踪符号链接和被修改占位文件的保护。
- 迁移逻辑兼容现有字符串及对象格式。
- 不引入额外运行时依赖。

## 依赖

- Bun 1.4.2。
- Effect Schema 与现有 Persistence schema。
- Git Windows 符号链接支持。

## 验收标准

- `packages/cli` Windows 构建专项测试通过。
- `packages/app` 类型检查通过。
- `bun run check` 通过。
- Windows x64 构建契约可完成构建、隔离 smoke，并按契约部署（若环境满足）。
