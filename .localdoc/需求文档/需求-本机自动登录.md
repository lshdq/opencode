# 需求：本机自动登录

## 背景与目标

当前 OpenCode Web UI 首次访问需要通过 `/auth/connect/<一次性代码>` 建立浏览器会话。为方便本机浏览器和 SSH 本地端口转发场景使用，增加显式启用的自动登录能力。

## 功能描述

### 核心功能

- 增加显式 `--auto-login` 启动参数。
- `opencode serve --auto-login` 支持前台服务启用自动登录。
- 后台共享服务支持持久化 `auto-login` 配置，使 `opencode pair` 使用的服务也能启用该能力。
- 自动登录启用后，本机直连和 SSH 隧道转发到服务端回环地址的 Web UI/API 请求无需 `/auth/connect/...`。

### 边界与约束

- 默认关闭，未指定参数或配置时保持现有认证行为。
- 只有服务实际监听地址严格为 `127.0.0.1` 时允许启用。
- OpenTunnel/远程访问启用时禁止自动登录。
- 监听 `0.0.0.0`、`::`、局域网 IP 或其他地址时，启用自动登录必须失败并给出明确错误。
- 自动登录的信任边界是服务端回环端口；因此本机其他进程和通过 SSH/本地隧道转发的客户端也会被视为可信。

## 输入输出

- 输入：`serve` 命令的 `--auto-login`；后台服务配置 `auto-login true/false`。
- 输出：满足安全约束时服务正常启动并允许未认证访问；不满足时启动失败。
- 现有密码、配对链接和远程访问功能保持兼容。

## 非功能需求（性能/安全/兼容性）

- 自动登录必须显式开启，默认不改变现有安全行为。
- 安全校验必须 fail-closed，不能在不满足绑定地址或远程访问约束时静默放行。
- 旧版服务配置文件可正常读取，缺少 `auto-login` 时按关闭处理。
- 类型检查、相关单元测试和 CLI 测试应通过。

## 依赖

- CLI 服务配置与命令参数。
- ServerOptions、服务启动流程和认证中间件。
- 现有服务生命周期、配对和远程隧道实现。

## 验收标准

1. `serve --auto-login --hostname 127.0.0.1` 可以启动并允许本机/SSH 转发访问。
2. `serve --auto-login --hostname 0.0.0.0`、IPv6 通配地址或局域网地址启动失败。
3. 启用远程访问时自动登录启动失败。
4. 未启用自动登录时，现有 `/auth/connect/...` 配对流程和认证行为不变。
5. 后台服务配置可以持久化、读取并在服务启动时生效。
6. 相关测试和类型检查通过。
