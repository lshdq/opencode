# 需求：dev-workflow 执行模式优化

## 背景与目标

现有 dev-workflow 在阶段 2 确认后统一连续执行，无法让用户选择自主执行或保留交互决策。需要在方案确认时同时选择后续执行模式，并为 Auto 模式提供不中断执行和决策留痕能力。

## 功能描述
### 核心功能

- 阶段 2 完成后，通过一次选择同时确认方案和选择后续执行模式。
- 提供 `Auto 模式` 和 `交互决策模式` 两种后续执行模式。
- 选择 Auto 模式后立即提醒用户开启客户端的自动接受权限，不依赖 agent 是否切换。
- Auto 模式下，阶段 3-7 除硬阻塞外连续执行至任务完成。
- Auto 模式遇到需要决策的事项时，由 AI 选择最优方案并记录决策，不暂停询问用户。
- 交互决策模式下，遇到需要用户决策的事项时暂停并询问用户，保持原有交互行为。
- Auto 模式生成需求文档和测试用例后直接继续；交互决策模式保留文档审核环节。
- Auto 模式的决策记录统一写入 `.localdoc/决策项/决策记录-<功能名称>-<yyyyMMddHHmmss>.md`。

### 边界与约束

- 阶段 1 的需求确认保持不变。
- 阶段 2 的选项为“确认并使用 Auto 模式”“确认并使用交互决策模式”“不通过，继续修改方案”。
- 三选一必须为单选；工具允许时关闭自定义答案，自定义、取消或空回答均不得视为批准。
- `plan_exit` 的内置 Yes/No 无法承载三选一；三选一由 question 工具或普通对话完成，`plan_exit` 仅用于获批后的 agent 切换。
- 时间戳在阶段 3 创建决策记录时生成一次，同一工作流中的后续决策追加到同一个文件；文件以仅当不存在时创建的原子或排他语义创建，冲突时逐秒递增并重试。
- 是否需要切换 agent 按完成任务所需的工具能力判断，不只按 agent 名称判断。
- 权限不足、必要外部环境不可用、需求存在无法自主消解的矛盾，以及其他导致工作无法继续的情况属于硬阻塞。
- 局部测试或外部环境受阻时，先完成不依赖该条件的测试和代码审查，最后汇报未验证项。
- plan_exit 被拒绝后若方案发生实质修改，原批准和模式选择失效，必须重新三选一确认。

## 输入输出

- 输入：阶段 2 技术方案以及用户选择的确认结果和执行模式。
- 输出：明确的后续执行规则；Auto 模式额外输出一份持续追加的决策记录。

## 非功能需求（性能/安全/兼容性）

- 保持没有 `question` 或 `plan_exit` 工具时的降级能力。
- 不改变阶段 3-7 的文档、开发、独立测试和独立代码审查职责。
- 规则表述必须避免重复确认和模式语义歧义。
- 与全局 AGENTS.md 的开发流程入口规则保持一致。

## 依赖

- OpenCode `question` 工具。
- plan agent 使用的 `plan_exit` 工具。
- 客户端自动接受权限功能。

## 验收标准

- SKILL.md 明确定义两种执行模式及三选一确认流程。
- Auto 模式包含切换提醒、连续执行、自主决策、决策记录和硬阻塞规则。
- 交互决策模式保留阶段 3 文档审核，并在新增实质决策点询问用户。
- 决策记录文件名只使用功能名称和 `yyyyMMddHHmmss` 时间戳，不使用会话 ID。
- 决策记录覆盖 Auto 模式生命周期内的 AI 实质决策，并排除用户选择、唯一修复路径和普通编码细节。
- 测试失败自动形成报告并交回主流程，不由独立子智能体询问用户是否继续。
- 独立测试子智能体不得修改生产代码，但覆盖不足时允许并应当持久化补充测试代码。
- dev-workflow 与 test-workflow 统一使用“框架代码 / 业务代码 / 通用 / 文档验证”四种测试场景。
- 文档验证直接执行只读文档检查，不进入单元测试和集成测试流程。
- 独立测试子智能体不直接询问部署或环境前置条件，记录后返回父流程处理。
- 独立测试产生的全部测试代码变更必须在报告中列出并纳入阶段 7 审查。
- 交互决策模式的文档反馈若实质改变已批准方案，必须返回需求澄清或方案设计并重新三选一确认。
- 测试或审查问题必须修复，但修复方案构成实质决策时仍按所选模式处理。
- 审查修复后必须重新执行受影响的基本验证、独立测试和独立审查，直至测试与审查同时收敛。
- 业务测试部署仅限已批准的非生产环境，部署决策按 Auto/交互决策模式处理，部署后重新执行未完成测试。
- 阶段 6 持久化补测属于父 dev-workflow 的内部步骤，不递归启动新的 dev-workflow。
- 业务代码修复影响部署组件时，重新构建并部署当前修复制品，校验版本和就绪后再执行接口复测。
- 独立审查接收已批准方案、决策记录或摘要、基本验证结果、测试报告和累计精确变更范围。
- 开发前记录各仓库初始状态并持续维护本工作流累计变更范围，避免误审既有改动或遗漏多轮、外部及忽略文件变更。
- 基本验证最终失败时仍进入独立测试和代码审查，完成所有不依赖失败项的工作。
- SKILL.md 中不存在把非 Auto 模式称为“当前模式”的表述。
