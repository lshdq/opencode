# 需求：启动依赖后台准备

## 背景与目标
用户已批准 Auto 模式：OpenCode TUI 启动时依赖安装不拖住界面，界面先显示、可操作和输入；发送消息时若插件尚未就绪，等待就绪后继续。

## 功能描述
### 核心功能
- 安装和插件初始化在后台继续，主页及输入框不等待全部插件。
- 服务端数据到达后补齐；已有服务端依赖的数据允许显示加载状态。
- 手动发送及启动参数自动发送统一等待必要的启动准备完成；展示非阻塞准备提示。
- 等待期间保留草稿、支持取消，连续回车不重复提交；退出后不得迟到提交或复活已销毁界面。
- 失败给予明确反馈，保留草稿，不能永久悬挂待发送操作。
### 边界与约束
- 保留依赖安装、插件加载、插件配置钩子及相关服务初始化的既有顺序。
- 认证、模型、工具及配置不能以半初始化状态用于消息执行。
- 正确应用配置的 auto_approve；CLI 显式 auto 优先；后台到达的配置不能覆盖用户已主动切换的权限模式。
- 默认启动、attach、恢复会话、--continue/--fork/--prompt 和插件路由需保持兼容。
- 复用已有 npm 安装和缓存机制。无需新增公共 Server/Protocol API。

## 输入输出
输入：启动参数、TUI 配置、服务端配置、插件声明、缓存和安装完成/失败信号。
输出：先可交互的界面、准备状态、就绪后一次性的消息提交或取消/失败反馈。

## 非功能需求（性能/安全/兼容性）
- 安装耗时不会成为首屏和输入框渲染的前置等待。
- 并发调用复用初始化，不重复安装；保持生命周期清理和错误处理。
- 不改变权限、工具和插件钩子的执行语义。

## 依赖
packages/opencode CLI 与旧插件宿主；packages/tui 启动、同步、权限、输入和插件运行时。

## 已批准方案
1. 将 CLI 渲染前的服务端配置获取移至后台，自动批准配置在首次发送前完成应用。
2. 主页、会话基础布局与全部 TUI 插件 ready 解耦，插件页面/扩展在就绪后开放。
3. 使用共享就绪检查协调后台配置和插件准备；消息提交等待就绪，支持取消、错误和销毁处理。
4. 服务端保留现有完整初始化屏障，不直接删除等待或在初始化一半时公开 hooks。
5. 受影响包 typecheck、针对性测试、独立测试及代码审查。

## 验收标准
- 人为阻止安装/插件初始化完成时，界面和输入仍可用。
- 提前提交不会调用模型，准备完成后恰好发送一次；取消/退出后不发送。
- 失败可见、草稿保留，无未处理 rejection 或永久提交锁。
- 缓存命中正常启动，恢复会话和自动发送正确。
- 配置自动批准和用户手动权限切换正确；相关 typecheck 和测试通过，或准确记录可证实的基线阻塞。

## 第二轮复审澄清（R-005/R-006）
- workspace 的 directory、SDK 请求目标、config/provider/agent/command 与权限作为完整执行上下文准备；不能以 connected 状态代替配置就绪。
- 采用候选完整准备后统一发布：准备失败/取消时保留此前已就绪上下文，返回 Home 可以使用它工作，不需等待已放弃的 IO。
- 当前路由必要准备失败必须持续阻止提交，包括重复回车；显示错误并保留草稿。离开失效路由可以解除局部失败，重新进入时可重新准备。
- A→B→C、同 workspace 重入、回 local、配置失败后的权限事件必须保持请求来源一致；不覆盖 CLI 和用户主动权限选择。详细理由见 DEC-008/009，用例见 TC-015～020。

## 第四轮修复补充（R-010/R-011）
- 候选取消后回退仅适用于原上下文仍有效。已成功删除的 workspace 是独立失效事实，不随路由 owner 取消而清除；发现列表、迟到配置或旧 Session 读取不能使其重新可执行。
- 两个删除入口均须记录删除事实，Home 重复 New session/导航后重新建立必要的完整 local 准备。local 失败重提不可绕过，切到有效 C 不等待旧 local IO；删除其它 workspace 不应禁用有效当前上下文。
- Restore/普通 warp 的整个异步链受路由与对话框生命周期约束，包括 reminder、刷新、最后 Session 读取及完成/错误回调；关闭但不导航也不得复活窗口、清除新窗口或覆盖新数据。未取消操作正常完成，远端已接受操作不撤销。

## 第五轮修复补充（R-012）
- 实例disposed通知是有workspace/directory来源的刷新，不是新的导航意图。旧committed实例事件不能抢占有效新候选，也不能用内部取消制造持续Startup failed。
- 有效候选的实例失效在同一准备任务中刷新完整快照；过期读取不发布，发送继续等待最新配置。重复事件合并，真正的新失效不遗漏；只重复必要只读准备，不自动重试provider连接、模型、shell或其它业务操作。
- 新候选期间旧实例的刷新需求保留：成功离开旧实例则不再刷新，候选失败不覆盖其失败，取消回退且旧实例仍有效时补刷新；不等待已放弃的IO，删除事实及退出生命周期优先。

## 第六轮修复补充（R-013/R-014）
- Provider API key、OAuth code/auto 的认证、dispose、完整刷新及错误/完成回调，均区分远端认证事实与本地窗口所有权。关闭、替换或导航后旧链不能替换/清除新窗口或显示旧局部错误；成功认证仍可刷新共享配置，不能重复认证。共享刷新失败不通过默认fatal路径退出整个TUI。
- 粘贴摘要命令标题与首次toggle使用同一有效值：显式KV优先，否则最新配置的反应性默认值。用户未选择时不把默认值写入KV，用户主动切换不被迟到配置覆盖。
