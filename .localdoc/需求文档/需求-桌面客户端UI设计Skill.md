# 需求：桌面客户端 UI 设计 Skill

## 背景与目标

创建一个全局 `desktop-ui-design` Skill，用于指导 PC 桌面客户端界面设计，统一多文档布局、窗口结构、交互状态和设计验收标准。

## 功能描述

### 核心功能

1. 默认优先采用多文档模式。
2. 多文档通过顶部 Tab 管理，Tab 样式参考 Chrome：活动标签白色背景，非活动标签灰蓝色背景。
3. 顶部窗口栏从左到右依次包含：菜单按钮、文档 Tab、最小化/最大化/关闭按钮。
4. 菜单按钮支持下拉菜单及多级菜单。
5. 顶部窗口栏下方为工具栏。
6. 工具栏下方为主内容区。
7. 窗口底部为状态栏。
8. Skill 补充完整设计流程：页面结构、组件规划、交互状态、响应式适配、可访问性和验收清单。

### 边界与约束

- 目标平台为 PC 桌面客户端，不规定具体 UI 框架或编程语言。
- Skill 提供设计规则和流程，不实现具体业务页面。
- 不强制所有页面都使用多文档；单文档页面应说明不采用 Tab 的原因。
- 视觉颜色应使用项目主题 token 或语义化颜色，不能只依赖固定色值。
- 窗口控制按钮须符合宿主操作系统习惯，并提供悬停、按下、禁用和焦点状态。

## 输入输出

- 输入：产品目标、文档类型、窗口能力、平台约束、主题规范和交互需求。
- 输出：页面区域结构、组件与状态说明、Tab/菜单/工具栏交互方案、适配与可访问性说明、验收清单。

## 非功能需求（性能/安全/兼容性）

- 多文档切换不应改变未保存文档状态；关闭前应有未保存提示或恢复机制。
- Tab 较多时应支持溢出处理、滚动或文档列表入口，不得挤压窗口控制按钮。
- 键盘操作应覆盖菜单、Tab、工具栏、内容区和状态栏中的可操作元素。
- 设计应适配常见 PC 窗口尺寸、缩放比例、浅色/深色主题和高对比度场景。
- 菜单、Tab 和窗口控制按钮应具备可辨识的焦点、悬停、按下、禁用和错误状态。

## 依赖

- 全局 OpenCode Skill 加载机制。
- 使用方项目的主题 token、图标规范、窗口管理 API 和组件库（如有）。

## 验收标准

- 全局目录存在 `desktop-ui-design/SKILL.md`，且包含有效 frontmatter。
- Skill 明确描述多文档 Tab 的位置、活动/非活动状态和溢出处理。
- Skill 明确描述菜单、文档 Tab、窗口控制按钮、工具栏、内容区和状态栏的层级关系。
- Skill 提供完整设计流程和可执行验收清单。
- 文档结构清晰，设计规则不会与平台窗口行为、键盘操作和主题系统冲突。
