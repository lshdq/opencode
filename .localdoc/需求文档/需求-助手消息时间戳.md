# 需求：助手消息时间戳

## 背景与目标

opencode TUI 已有 `/timestamps` 开关（持久化到本地 kv.json），开启后**仅用户消息**下方显示时间；助手消息 footer（`▣ agent · 模型 · 耗时`）始终不显示时间。用户希望开启开关后，助手消息也能显示时间，便于追溯每条 AI 回复的发生时刻。

## 功能描述

### 核心功能

- 在 TUI 会话页的助手消息 footer 中，当 `/timestamps` 开关处于 show 状态时，追加显示该消息的时间。
- 显示内容：`Locale.todayTimeOrDateTime(props.message.time.created)`——当天消息显示时间（如 `14:32`），跨天消息显示 `时间 · 日期`，与用户消息时间格式完全一致。
- 显示位置：footer 文本中 agent 之后、模型之前，以 ` · ` 分隔，颜色使用 `theme.textMuted`。
- 开关关闭（hide，默认）时不显示，行为与现状一致。

### 边界与约束

- 不新增配置项，复用现有 `ctx.showTimestamps()` 开关。
- 不改动用户消息已有的时间戳逻辑。
- 不改动 Desktop/Web App（`packages/app`、`packages/session-ui`）。
- 时间语义使用 `time.created`（助手消息创建/开始时间），不使用 `time.completed`，与用户消息时间语义保持一致。
- 仅修改 `packages/tui/src/routes/session/index.tsx` 中 AssistantMessage 组件的 footer 一处。

## 输入输出

- 输入：助手消息对象自带的 `time.created`（epoch 毫秒，SDK 类型已存在，无需改数据结构）。
- 输出：TUI 渲染的 footer 文本中新增一段 ` · HH:mm`（或跨天时 ` · HH:mm · 日期`）。

## 非功能需求（性能/安全/兼容性）

- 性能：仅在渲染时多一次格式化调用，可忽略。
- 兼容性：不改变消息数据结构、不改变开关的持久化格式；默认关闭，对现有用户无影响。
- 代码风格：遵循仓库 AGENTS.md（避免 else、复用现有组件与工具函数）。

## 依赖

- `packages/tui/src/util/locale.ts` 的 `Locale.todayTimeOrDateTime`（已存在）。
- 会话页 context 的 `ctx.showTimestamps()`（已存在，index.tsx L1168 已传入）。

## 验收标准

1. 默认（开关关闭）时，助手消息 footer 与现状完全一致：`▣ Build · model · 12s`。
2. 执行 `/timestamps` 开启后，助手消息 footer 显示时间，形如：`▣ Build · 14:32 · model · 12s`。
3. 再次执行 `/timestamps` 关闭后，助手消息 footer 恢复不显示时间。
4. 重启 TUI 后开关状态仍生效（kv.json 持久化），助手消息时间随开关一致显隐。
5. 跨天的历史会话中，助手消息显示 `时间 · 日期` 格式。
6. `bun typecheck`（packages/tui）通过。
