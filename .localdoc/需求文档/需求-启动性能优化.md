# 需求：启动性能优化

## 背景与目标

opencode（Windows 直装二进制，137.8MB）TUI 从启动到可交互实测约 5.5~7s，用户期望"秒开"。
经测量定位（报告：`D:\temp\systemp\opencode\startup-measure\启动性能测量报告.md`），构成如下：

| 段 | 耗时 | 根因 |
|---|---|---|
| 模块图求值 | ~400ms/次 | `src/index.ts` 静态导入 23 个命令模块的重依赖 |
| TuiConfig.get + 串行 import | ~650ms+ | `tui.ts` 启动序列串行 |
| git 生成风暴 | ~3.7s | `agent.ts` Agent.state 为解析 references 编译整套 30 服务 location bundle（含 snapshot/watcher/skill 的 40+ 次 git.exe） |
| 双份 location bundle | ~1.5s | 主目录 + worktree 两套 |

**目标**：TUI 从启动到可交互 <1.5s（Windows 热启动），全部行为保持不变，实现符合可上游 PR 标准。

## 功能描述

### 核心功能

1. **命令懒加载**：23 个 CLI 命令模块的重依赖（MCP SDK、ACP SDK、session 生态、drizzle 等）从顶层静态导入下沉到 handler 内动态导入；`opencode --version` 热启动从 ~440ms 降到 ~250ms 以内。
2. **tui.ts 流水线并行化**：Worker 创建后立即预取 TUI layer/effect/plugin-runtime/sdk 动态导入（不 await）；`input()` 与 `TuiConfig.get()` 并行。
3. **git 调用合并**：`core/src/git.ts` 的 `repo.discover` 将三次 `rev-parse`（--show-toplevel / --git-dir / --git-common-dir）合并为单次调用，保持现有失败语义（gitDir/commonDir 失败→undefined；topLevel 失败→回退 cwd）。
4. **references 解耦（核心）**：`agent.ts` Agent.state 中为获取 reference 目录而触发的整套 location bundle 编译（`locations.get(ref)`），替换为共享纯函数直接从 config 文档推导引用绝对路径；纯函数由 `core/config-reference` 插件与 agent 共用（单一事实来源）。
5. **location bundle 预热**：从启动关键路径移除后，Agent.state 完成即 fork 后台编译主 location bundle（与 TUI 渲染并行，worker 线程执行），保证首个 prompt 性能不退化；worktree location 不预热，首次会话自然编译。

### 边界与约束

- **行为不变**：agents 列表、reference 目录权限白名单（external_directory allow）、snapshot track/revert、插件加载顺序与时机语义、主题探测、sync 阻塞结构均不改变。
- **不做**：TUI 插件后台激活、主题探测缓存/降超时（用户已明确拒绝）。
- 实现符合上游代码规范（AGENTS.md 风格：自导出模式、动态导入偏好、无多余注释、Effect v4 规则）。
- 改动落在 win-adapt 分支（基于 ff59e73cea，工作区干净）。

## 输入输出

- 输入：现有 CLI 启动流程、config 文档中的 `references` 配置（local 路径 / git 仓库）、git 仓库探测。
- 输出：行为等价但更快的启动路径；无接口/协议/配置格式变化。

## 非功能需求（性能/安全/兼容性）

- 性能：`debug startup` 热启动 <250ms；无头 TUI 时间线首个 RPC 返回 <1s；可交互 <1.5s。
- 兼容性：git 合并需兼容 worktree、bare repo、submodule 场景（保持现有分支语义）；命令懒加载不得改变 yargs 帮助/补全/参数校验行为。
- 并发：location bundle 预热与首次使用并发时必须去重（LayerMap 同 key 共享），不得双编译。

## 依赖

- 无新增第三方依赖。
- 前提验证（T0）：`core/config-reference` 是 Reference 源的唯一生产者；若不成立则退回复选方案（为 Reference 提供轻量独立 node）。

## 验收标准

1. `opencode --version` 热启动（连续 5 次中位数）<250ms。
2. 无头 TUI 时间线：首个 config.get RPC 返回 <1s（进程启动起算）；启动日志中无 3.7s 空窗阻塞。
3. 回归：agents 列表完整（build/plan/dev-*）；读取 reference 目录（如 `~/.config/opencode/references/**`）不弹权限确认；编辑文件后 snapshot diff/revert 可用；taskbar-flash 插件生效；`--version`/`--help`/主要命令行为不变。
4. `bun typecheck` 在涉及包（core/opencode/tui）全部通过。
5. 新增单元测试通过：references 纯函数路径推导（local/git/相对路径/`~/` 展开/非法别名过滤）、git discover 合并调用（正常/worktree/非 git 目录）。
