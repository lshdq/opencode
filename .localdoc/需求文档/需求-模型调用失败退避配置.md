# 需求：模型调用失败退避配置

## 背景与目标

当前模型调用失败后的指数退避上限固定为 5 分钟，无法按部署环境调整。需要将本地退避上限配置化，并将默认值调整为 30 秒。

## 功能描述

### 核心功能

- 新增顶层配置 `retry.max_delay`，使用非负整数秒数。
- 未配置时默认最大本地退避时间为 30 秒。
- 配置支持运行时热更新。
- 供应商返回的 `retry-after` 优先于本地退避上限，但仍受现有 5 分钟安全硬上限约束。
- 配置值为 0 时，无供应商退避要求的重试立即执行。
- 主模型请求重试和自动压缩请求重试使用同一策略。

### 边界与约束

- 仅调整模型调用失败的会话重试策略，不影响媒体读取、服务启动等其他重试逻辑。
- 保留现有指数增长、抖动、Hook 决策和最小退避行为；仅在配置值为 0 时允许本地退避为 0。
- 非法配置应被配置标准化流程拒绝，并继续使用默认值。

## 输入输出

输入示例：

```jsonc
{
  "retry": {
    "max_delay": 30
  }
}
```

输出行为：重试决策中的 `delay` 使用当前配置和供应商 `retry-after` 计算后的毫秒值。

## 非功能需求（性能/安全/兼容性）

- 配置读取应复用现有 Config 服务和优先级机制，不引入新的持久化格式。
- 配置热更新不需要重启服务。
- 供应商退避值继续受 5 分钟安全上限保护。
- 不改变现有公共事件结构。

## 依赖

- `@opencode/schema` 配置契约。
- `@opencode/core` 配置标准化与会话重试策略。
- Effect 配置服务和现有会话重试测试基础设施。

## 验收标准

1. 默认本地退避上限为 30 秒。
2. `retry.max_delay` 可配置为任意非负整数秒数。
3. 配置修改后，后续重试决策使用新值。
4. `retry-after` 大于配置值时，优先使用 `retry-after`，但不超过 5 分钟。
5. 配置为 0 时，本地重试 delay 为 0。
6. 配置和重试策略相关测试通过。
