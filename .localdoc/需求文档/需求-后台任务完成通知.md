# 需求：后台任务完成通知

## 背景与目标

当主会话执行事件已经结束，但其子智能体或后台 shell 仍在运行时，OpenCode 当前可能提前发送“任务已完成”系统通知。目标是让完成通知代表整个会话任务树已完成，避免与界面仍显示 `subagent working` 或运行中 shell 的状态冲突。

## 功能描述

### 核心功能

- 主会话收到执行完成事件时，检查运行中的子智能体和后台 shell。
- 存在运行中后台任务时延迟主会话完成通知。
- 最后一个子智能体或 shell 结束后发送一次主会话完成通知。
- 保留子智能体自身完成提示及既有错误通知语义。
- App 与 TUI 两个通知入口行为一致。

### 边界与约束

- 不改变会话执行、shell 生命周期或任务栏显示逻辑，只修正完成通知时机。
- 重复的完成、失败、退出事件不得产生重复通知。
- 子智能体嵌套场景和 shell 运行场景均需覆盖。

## 输入输出

- 输入：`session.execution.*`、`session.created/deleted`、`shell.created/exited/deleted` 事件及当前会话/shell 状态。
- 输出：系统完成通知、TUI attention 通知和既有声音提示。

## 非功能需求（性能/安全/兼容性）

- 使用现有内存状态和事件订阅，不引入轮询或持久化数据结构。
- 不改变公开 API、协议或生成客户端代码。
- 保持现有通知去重和断线重连恢复行为。

## 依赖

- App 的 `Data` 会话、消息和 shell 状态。
- TUI 插件 `Context.data` 及 OpenCode 生命周期事件。
- 现有 Bun 单元测试环境。

## 验收标准

1. 主会话完成但子智能体运行时，不发送主会话完成通知。
2. 主会话完成但后台 shell 运行时，不发送主会话完成通知。
3. 所有后台任务结束后，主会话只发送一次完成通知。
4. 子智能体自身完成提示、错误提示及嵌套子智能体行为不回归。
5. 相关测试和类型检查通过。
