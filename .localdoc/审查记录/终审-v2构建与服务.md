## 4. 经复核成立的问题

### R3 [阻塞] 新Windows验证入口只隔离child环境，父进程fetch仍把loopback认证请求发给继承代理

**证据（活动代码与真实调用链）：**

1. `packages/cli/script/windows-build.ts:13-24` 构建env展开`process.env`，仅覆盖构建参数；`82-85`将该env交给`smoke-win.ts`。因此从设置HTTP_PROXY的开发shell执行默认build包装，是直接可达入口，不需要篡改registration或二进制。
2. `packages/cli/script/smoke-win.ts:21-22,47-50`的`isolatedEnvironment(root)`只作为服务child的env；**`81-84,101`在当前harness进程调用全局fetch**，没有代理隔离。Basic头在`78`使用新服务的私有密码构造。
3. `packages/cli/script/compiled-integration-win.ts:30-31,82-86,103-112`和`packages/cli/script/diagnose-source-win.ts:16,44,82-85`有同一问题；二者也有直接命令入口。
4. 累计范围内`packages/cli/test/service.test.ts:251-253,336-339,564-567`的父进程fetch也是同类路径（这一部分为 **pre-existing**）。`serviceEnv`过滤child环境并不改变运行测试的父进程。
5. 修复后的旧`service-smoke.ts:204-234`用node:http直连，仅在该文件内调用。它没有被上面三个新入口复用；本次28项中的compiled诱饵用例调用的是旧`runServiceSmoke`，不是`smoke-win.ts`。

**根因：**将“创建一个无代理的环境对象并传给child”混同于“当前HTTP客户端无代理”。URL/PID/image检查验证逻辑目标及进程身份，不能控制Bun fetch的实际网络下一跳。HTTPS_PROXY/HTTP_PROXY是常见开发shell设置；没有匹配127.0.0.1的NO_PROXY即可触发。

**本机独立复核（Bun1.4.2，未连接真实服务/代理）：**

- 在内存中创建两个`127.0.0.1:0`的Bun HTTP监听器，一个作为目标，一个作为代理诱饵。
- 启动一个仅保留OS执行环境的Bun子harness，为它设置`HTTP_PROXY/HTTPS_PROXY=<诱饵地址>`、`NO_PROXY=""`、禁用transpiler磁盘cache。
- harness导入当前真实`windows-runtime.ts`并调用`isolatedEnvironment`，确认返回的childEnv无proxy；随后按上述三个入口的调用方式，在harness执行带`Authorization: Basic fixture-only`及3s abort的`fetch(target/api/info)`。无source改动、无真实凭据。
- 原始结果：

```json
{"childHasProxy":false,"response":"proxy"}
{"bun":"1.4.2","exit":0,"direct":0,"proxy":1,"credential":true}
```

这是一项**真实运行时语义核验 + 实际入口静态接线确认**，不是声称本轮重新执行了三个完整脚本。两个诱饵均在finally停止。

**触发与影响：**默认Windows构建smoke或文档中的直接脚本命令，在继承代理且未配置loopback bypass时，把自有服务认证头、访问路径及集成请求发送给代理；代理不转发会使健康服务被误判失败，代理转发则可能测试表面成功但仍违反隔离。真实部署前验证链不能保证“无外部服务/代理访问”。没有证据表明日常凭据已经泄漏，也没有声称会误停日常服务。

**严重度理由：**违反本任务TC-015/需求36的严格隔离硬约束，且有确定的认证头外发证据，属于核心安全验收缺失，不能仅列作可选或以重build绕过。

**建议与不修复影响：**本轮统一这些loopback验证入口的HTTP直连边界，可提取现有node:http做法并保留所需status/body/headers、method及取消语义（service CORS测试需要响应headers），或者在执行整个验证harness前隔离其环境并证明所有直接入口也受约束。不要仅为server child加env，也不要以`proxy: ""`未经实际验证的写法作为修复。补持久化诱饵回归，覆盖新smoke、compiled integration、source diagnostic及相关测试父进程：在代理环境下目标收到请求、代理0请求，同时保持身份、认证、stop和失败清理断言。否则旧28项绿测仍无法阻止该遗漏回归。
