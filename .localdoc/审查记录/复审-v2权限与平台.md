## 2. Java 公共模块主业务影响

**不适用：非 Java。** 按通用基线核查资源与失败链路如下：

- ACL 是敏感写入的必需安全依赖，失败阻止写入符合批准的 fail-closed 决策。`execute` 限10秒、64KiB，取消 kill 后等 close；不启动脚本后代。不建议为通过测试改回无保护写入。
- SQLite acquisition 固定一次权限 host、固定最多4个文件；没有每条 SQL 启动进程、逐数据库行扫描或新增连接池。默认 owned 目录首次 DACL 继承可能影响其继承型后代，这是文档已说明的效果；不是声称所有目录首次处理严格 O(1)。已私有目录仅检查，不重复提交目录 DACL。
- migration 的一致性边界是完整临时文件到正式路径的 hardlink 发布；未发布失败不污染正式名，发布后取消不删除赢家。强杀可能留下私有 temp，但不再以空正式目标阻断下次迁移；没有声称崩溃可以运行 scoped 清理。
- MCP 每个 owned root 一 host/Job，无常驻累计 handle 集合；WeakSet 不强持有结束命令。host 正常等待目标符合会话生命周期，连接失败/超时/关闭沿用 MCP/spawner 管理。没有证实无界泄漏。
- rg 候选固定3个，逐候选 scoped；未新增整体提取超时，测试 timeout 不等同生产保证。未取得正常默认工具必现挂起证据，不作为理论阻塞项。
- 本范围没有 Redis/MQ/分布式事务、新异步队列或需要新增缓存的业务模型。不强行提出与需求无关的缓存/异步化。

- **根因**：生产契约已按 DEC-009 收紧，但适配只覆盖新增权限测试及 CLI fixtures，遗漏直接传入文件路径的既有 core 测试。这些测试拥有 fresh mkdtemp root，却仍以未授权、未准备的 custom parent 打开数据库。即使上级临时目录恰好私有，新子目录的 inherited DACL 也不等于 guard 要求的 protected DACL，不能靠运行环境偶然放行。

- **建议**：在实际拥有 mkdtemp 的 fixture/call site 中显式准备其自有数据库目录，或对这几处明确自有的 Database.configured 传入 `privateDirectory:true`；排查相同文件库测试入口并同步。不要全局给未知路径授予 ownership，不要取消 custom guard，不要删/skip 重放断言，也不要给整个系统 TEMP 递归改 ACL。
