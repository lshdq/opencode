# 测试用例：启动网络健壮性（IPv6 环境启动卡死修复）

## 测试范围

- `packages/core/src/models-dev.ts`：populate 去网络化、降级语义、后台 refresh、Refreshed 事件。
- `packages/opencode/src/provider/provider.ts`：InstanceState 订阅 Refreshed 后失效重建。
- `packages/opencode/src/installation/index.ts`：`latest()` 版本源拉取超时。
- 回归：`OPENCODE_MODELS_PATH`、`OPENCODE_DISABLE_MODELS_FETCH`、`OPENCODE_MODELS_URL` 既有语义。

## 用例列表

### TC-001: 无缓存且网络不可达时 populate 降级为空目录
- 前置条件：`OPENCODE_MODELS_URL` 指向本机未监听端口（如 `http://127.0.0.1:1`）；缓存目录无 models.json；未设置 `OPENCODE_MODELS_PATH`/`OPENCODE_DISABLE_MODELS_FETCH`。
- 操作步骤：调用 `ModelsDev.get()`（用测试 layer 提供服务）。
- 预期结果：立即（秒级，远小于既有 10s 超时）返回 `{}`；不抛缺陷、不重试联网；产生 warning 日志。
- 优先级：P0

### TC-002: 有磁盘缓存时 populate 直接返回缓存且不联网
- 前置条件：缓存文件写入有效的最小 models JSON；`OPENCODE_MODELS_URL` 指向不可达地址。
- 操作步骤：调用 `ModelsDev.get()`。
- 预期结果：返回缓存内容；无网络请求。
- 优先级：P0

### TC-003: OPENCODE_MODELS_PATH 指定文件时优先从该文件加载（回归）
- 前置条件：设置 `OPENCODE_MODELS_PATH` 指向测试 fixture 文件。
- 操作步骤：调用 `get()`。
- 预期结果：返回该文件内容（现行为保持）。
- 优先级：P1

### TC-004: OPENCODE_DISABLE_MODELS_FETCH=1 时后台不拉取（回归）
- 前置条件：设置该环境变量。
- 操作步骤：构建服务层，等待后台任务调度窗口。
- 预期结果：不产生任何对 models URL 的请求（现行为保持）。
- 优先级：P1

### TC-005: 后台 refresh 成功后发布 Refreshed 事件并更新 get() 结果
- 前置条件：`OPENCODE_MODELS_URL` 指向本地测试 HTTP 服务（返回最小合法 JSON）。
- 操作步骤：触发 `refresh(true)`，随后调用 `get()`。
- 预期结果：`get()` 返回新数据；`Refreshed` 事件被订阅者收到。
- 优先级：P0

### TC-006: legacy Provider 状态在 Refreshed 后失效重建
- 前置条件：Provider 层可用（测试 layer）；首次 `get()` 时 ModelsDev 返回空目录；随后模拟 refresh 完成并发布 `Refreshed`。
- 操作步骤：发布 `ModelsDev.Event.Refreshed`；再次访问 Provider 状态（list/get）。
- 预期结果：Provider 状态以新目录重建（能看到 models.dev 中的 provider）；旧条目订阅被释放，无重复订阅累积。
- 优先级：P0

### TC-007: Installation.latest 对挂起的版本源 10s 内失败
- 前置条件：构造接受连接但不响应的本地 HTTP 服务（或等效不可达地址）作为版本源。
- 操作步骤：调用 `Installation.latest()`（对应 method 分支）。
- 预期结果：10s 内失败返回（`orDie` 语义由外层 catch 兜底，与现状一致），不无限挂起。
- 优先级：P1

### TC-008: 外网不可达时 TUI/服务可启动（集成）
- 前置条件：清空 models 缓存；`OPENCODE_MODELS_URL` 指向不可达地址。
- 操作步骤：在 `packages/opencode` 启动 TUI（tmux 会话）或以 `bun test` 运行覆盖 Provider 初始化的集成测试。
- 预期结果：初始化完成、不崩溃、不长时间卡顿；模型目录为空（仅本地配置 provider）。
- 优先级：P0

### TC-009: typecheck 通过
- 前置条件：代码改动完成。
- 操作步骤：在 `packages/core`、`packages/opencode` 分别执行 `bun typecheck`。
- 预期结果：无类型错误。
- 优先级：P0

### TC-010: 正常网络下既有测试全部通过（回归）
- 前置条件：不注入不可达地址。
- 操作步骤：运行 `packages/core`、`packages/opencode` 相关既有测试（models-dev、provider、installation 相关文件）。
- 预期结果：全部通过。
- 优先级：P0

## 测试命令

- 单元/集成测试（不得从仓库根目录运行）：
  - `bun test test/models-dev.test.ts`（`packages/core` 目录下，若新增则按实际文件名）
  - `bun test`（`packages/core`、`packages/opencode` 目录下按需运行相关文件）
- 类型检查：`bun typecheck`（分别在 `packages/core`、`packages/opencode`）
- TUI 集成验证（可选）：在 `packages/opencode` 下 `tmux new-session -d -s opencode-dev 'bun dev'` 后 `tmux capture-pane -pt opencode-dev`
