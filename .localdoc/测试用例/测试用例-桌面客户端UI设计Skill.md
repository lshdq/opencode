# 测试用例：桌面客户端 UI 设计 Skill

## 测试范围

验证全局 Skill 文件的路径、frontmatter、核心布局约束、完整设计流程和验收清单；不执行应用运行时测试。

## 用例列表

### TC-001: 全局 Skill 文件存在且格式有效
- 前置条件：全局 Skill 目录可访问。
- 操作步骤：读取 `D:\Program\opencode\data\config\opencode\skills\desktop-ui-design\SKILL.md`，检查 frontmatter 的 `name` 和 `description`。
- 预期结果：文件存在；`name` 为 `desktop-ui-design`；description 非空且描述 PC 客户端 UI 设计用途。
- 优先级：P0

### TC-002: 多文档 Tab 规范完整
- 前置条件：Skill 文件存在。
- 操作步骤：检索多文档、Tab、顶部、活动标签、非活动标签、溢出和未保存状态相关内容。
- 预期结果：明确优先多文档模式；Tab 位于顶部；活动标签为白色背景；非活动标签为灰蓝色背景；定义溢出和未保存文档处理。
- 优先级：P0

### TC-003: PC 客户端窗口层级完整
- 前置条件：Skill 文件存在。
- 操作步骤：检查菜单按钮、多级菜单、工具栏、内容区、状态栏以及最小化/最大化/关闭按钮的描述。
- 预期结果：明确顶部窗口栏的左右布局、第二栏工具栏、中间内容区和底部状态栏。
- 优先级：P0

### TC-004: 完整设计流程和状态规范存在
- 前置条件：Skill 文件存在。
- 操作步骤：检查页面结构、组件规划、交互状态、响应式适配、可访问性和验收清单章节。
- 预期结果：Skill 为设计任务提供可按步骤执行的流程，并覆盖键盘、焦点、主题、缩放和窗口尺寸适配。
- 优先级：P1

### TC-005: 文档验证无冲突表述
- 前置条件：需求文档和 Skill 文件均可读取。
- 操作步骤：逐项对照需求文档中的验收标准，检查 Skill 内容是否遗漏或引入与需求冲突的硬性约束。
- 预期结果：所有验收标准均可在 Skill 中定位到对应章节；无强制具体框架或业务实现的越界要求。
- 优先级：P1

## 测试命令

文档验证命令：使用 PowerShell 读取文件并通过关键词与结构检查；无需运行单元测试或集成测试。
