# 测试用例：auto授权不闪烁任务栏

## 测试范围

验证全局 `taskbar-flash` 插件对权限请求的人工介入判定，以及既有问题、完成、错误和子代理行为不发生回归。

## 用例列表

### TC-001: Auto模式自动授权不闪烁
- 前置条件：权限模式为 auto，对应权限请求未进入 `api.state.session.permission` 队列。
- 操作步骤：向插件发送主会话 `permission.asked` 事件。
- 预期结果：不调用任务栏闪烁；写入 auto 跳过日志。
- 优先级：P0

### TC-002: Normal模式人工授权正常闪烁
- 前置条件：权限模式为 normal，对应权限请求已进入人工权限队列。
- 操作步骤：向插件发送主会话 `permission.asked` 事件。
- 预期结果：调用任务栏闪烁；写入人工权限事件日志。
- 优先级：P0

### TC-003: 运行时切换权限模式
- 前置条件：同一 TUI 实例可在 auto 和 normal 间切换。
- 操作步骤：分别在队列无请求、队列存在请求时发送不同 ID 的 `permission.asked` 事件。
- 预期结果：auto 场景不闪烁，normal 场景闪烁，无需重启切换模式。
- 优先级：P0

### TC-004: 权限事件去重
- 前置条件：人工权限队列包含目标请求。
- 操作步骤：连续发送两次相同 ID 的 `permission.asked`，发送 `permission.replied` 后再次发送。
- 预期结果：解决前只闪烁一次；解决后再次出现可重新闪烁。
- 优先级：P1

### TC-005: 问题确认保持闪烁
- 前置条件：主会话存在。
- 操作步骤：发送 `question.asked` 事件。
- 预期结果：任务栏正常闪烁。
- 优先级：P1

### TC-006: 任务完成和错误保持闪烁
- 前置条件：主会话先进入 busy 状态。
- 操作步骤：分别触发正常 idle 和 `session.error`。
- 预期结果：正常完成或错误按原行为闪烁，错误后的 idle 不重复闪烁。
- 优先级：P1

### TC-007: 子代理保持不闪烁
- 前置条件：会话存在 `parentID`。
- 操作步骤：发送子代理权限、问题、完成或错误事件。
- 预期结果：均不触发任务栏闪烁。
- 优先级：P1

### TC-008: 实机Auto与Normal验证
- 前置条件：Windows 原生 OpenCode，插件已重启加载，存在会触发 ask 的操作。
- 操作步骤：在 auto 模式和 normal 模式下分别触发权限请求，并检查任务栏和日志。
- 预期结果：auto 自动批准且不闪烁；normal 等待用户且闪烁；日志与行为一致。
- 优先级：P0

## 测试命令

```powershell
bun test test/taskbar-flash.test.ts
```

实机验证需完全退出并重启 OpenCode，然后分别在 auto 和 normal 模式触发权限请求。

通用；包含插件单元测试和 Windows 实机交互验证。
