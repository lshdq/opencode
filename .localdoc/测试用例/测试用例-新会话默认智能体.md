# 测试用例：新会话默认智能体

## 测试范围

- TUI 新会话智能体重置与创建请求。
- Web/Desktop App 新会话默认智能体解析与草稿隔离。
- 已有会话智能体选择和模型选择回归。

## 用例列表

### TC-001: TUI 新会话使用 default_agent
- 前置条件：agent catalog 首位为配置的默认智能体，当前已有会话使用其他智能体。
- 操作步骤：从已有会话进入新会话并提交提示。
- 预期结果：新会话创建请求使用 catalog 首位的默认智能体。
- 优先级：P0

### TC-002: Web/Desktop App 新草稿使用 default_agent
- 前置条件：agent catalog 首位为配置的默认智能体，之前会话选择过其他智能体。
- 操作步骤：打开新的会话草稿。
- 预期结果：草稿初始智能体为默认智能体，而非之前会话智能体。
- 优先级：P0

### TC-003: 新会话草稿保留手动智能体选择
- 前置条件：新会话草稿已使用默认智能体初始化。
- 操作步骤：在草稿中手动选择其他主智能体并提交。
- 预期结果：创建请求使用手动选择的智能体。
- 优先级：P1

### TC-004: 已有会话选择隔离
- 前置条件：两个已有会话分别使用不同智能体。
- 操作步骤：在两个会话间切换并查看智能体选择。
- 预期结果：每个会话保留自己的智能体选择，不被新会话默认值覆盖。
- 优先级：P1

### TC-005: 模型选择行为不变
- 前置条件：已有会话和默认智能体配置了可用模型。
- 操作步骤：创建新会话并观察模型初始选择及手动切换。
- 预期结果：模型仍按原有继承/回退逻辑工作，不因本次智能体修复被强制替换。
- 优先级：P1

### TC-006: TUI 新草稿切换目录
- 前置条件：新会话 Home 路由已打开，源目录与目标目录 agent catalog 首位不同。
- 操作步骤：通过 `/cd` 切换到目标目录，再提交新会话。
- 预期结果：最终创建请求使用目标 location 与目标默认智能体；不能沿用 home 路由中的旧目录默认值。
- 优先级：P0

### TC-007: App 默认值随 catalog 刷新
- 前置条件：草稿使用缓存 catalog，用户尚未手动选择智能体。
- 操作步骤：刷新 catalog，使默认智能体变更但旧智能体仍存在；再在同一草稿手动选择并刷新。
- 预期结果：未手选时跟随 catalog 首位；手选后保留仍可用的手动选择。模型选择操作不固定旧智能体默认值。
- 优先级：P1

### TC-008: 真实新建入口创建请求
- 前置条件：已有会话使用非默认智能体。
- 操作步骤：通过真实新建入口进入新会话并输入提示提交；另验证同一草稿内手动选择后提交。
- 预期结果：创建请求的 agent 分别为默认智能体和手选智能体，模型继承不变。
- 优先级：P0

### TC-009: catalog 暂时为空时保留手动选择
- 前置条件：当前草稿已手动选择非默认智能体。
- 操作步骤：catalog 暂时返回空列表，随后恢复包含手选智能体但首位不同的列表；另验证非空 catalog 明确删除手选智能体。
- 预期结果：暂时为空后恢复时仍使用手选值；明确删除时才回退首位，且不保留失效选择。
- 优先级：P1

```text
cd packages/tui && bun typecheck
cd packages/app && bun run typecheck
```
