# 测试用例：跨用户项目身份解析

## 测试范围

`packages/core/src/project.ts` 的 `Project.resolve` / `persist`：
- git 仓库成功解析后写入 `.git/opencode` 缓存
- git 子进程失败时的缓存读回退
- 无缓存 / linked worktree / 无 `.git` 场景维持现状

## 用例列表

### TC-001: git 仓库成功解析写入缓存文件
- 前置条件：临时目录初始化 git 仓库并设置 remote（如 `git@github.com:owner/repo.git`），至少一次提交
- 操作步骤：调用 `Project.resolve(仓库根)`；读取 `<仓库根>/.git/opencode`
- 预期结果：文件内容（trim 后）等于返回的 Project ID（remote 哈希 ID，非路径哈希）；重复 resolve 不产生重复写入副作用
- 优先级：P0

### TC-002: git 失败时命中缓存返回同一 ID
- 前置条件：TC-001 已生成缓存；通过 Git.Service 层替换（或等价 fixture）使 `Git.repo.discover` 失败，模拟 dubious ownership / git 不可用
- 操作步骤：再次调用 `Project.resolve(仓库根)`
- 预期结果：返回 ID 与 TC-001 相同；`vcs?.type === "git"`；`directory`/`canonical` 等于仓库根；不产生新的路径哈希 project 行
- 优先级：P0

### TC-003: git 失败且无缓存维持路径哈希回退
- 前置条件：git 仓库存在但 `.git/opencode` 不存在；`Git.repo.discover` 失败
- 操作步骤：调用 `Project.resolve(仓库根)`
- 预期结果：返回路径哈希 ID（现状行为），`vcs` 为 undefined
- 优先级：P0

### TC-004: linked worktree（.git 为文件）不受影响
- 前置条件：主仓库含缓存文件；创建 linked worktree（`.git` 为文件）
- 操作步骤：`Project.resolve(worktree 目录)`
- 预期结果：git 正常时按现有逻辑解析（remote 哈希 ID）；git 失败时读 `<worktree>/.git/opencode` 自然失败，维持路径哈希回退
- 优先级：P1

### TC-005: 无 .git 目录解析行为不变
- 前置条件：普通目录（无版本控制标记）
- 操作步骤：调用 `Project.resolve(目录)` 与子目录
- 预期结果：与现状一致（确定性路径哈希 ID，父/子目录不同 ID，无 vcs）
- 优先级：P0

### TC-006: 写缓存失败不影响解析
- 前置条件：git 仓库成功解析，但缓存路径不可写（如只读模拟，可行时）
- 操作步骤：调用 `Project.resolve(仓库根)`
- 预期结果：解析正常返回，不因写失败而中断
- 优先级：P2

## 测试命令

在 `packages/core` 目录执行：

```
bun typecheck
bun test test/project.test.ts
```

仓库根目录执行（最终验证）：

```
bun run check
```
