# 测试用例：多用户共享数据改造

## 测试范围

- 删除 Windows DACL 加固后：目录/文件 ACL 继承父目录；自定义 `OPENCODE_DB` 共享路径可用。
- 多用户（以同 data 根多进程为代理）并发启动、并发下载 rg.exe、并发写 service.json 不冲突。
- Unix 平台 chmod 0o600 行为回归。
- 既有 auto-login 等改动（基线快照）不被破坏。

## 用例列表

### TC-001: Windows 默认路径启动不再收紧 ACL
- 前置条件：Windows；干净的 `XDG_DATA_HOME` 指向无限制目录。
- 操作步骤：以默认路径启动 serve；检查 data 目录及 `opencode.db/-wal/-shm` 的 ACL。
- 预期结果：ACL 继承父目录（不再被重写为 owner-only protected DACL）；启动成功。
- 优先级：P0

### TC-002: 自定义 OPENCODE_DB 共享目录可正常启动
- 前置条件：Windows；`OPENCODE_DB` 指向一个普通共享目录（非 owner-only）。
- 操作步骤：启动 serve。
- 预期结果：启动成功，不再报 "Unsafe custom SQLite directory"。
- 优先级：P0

### TC-003: 同 data 根双进程并发启动均成功
- 前置条件：两个进程使用不同 `HOME`/用户目录、相同 `XDG_DATA_HOME`（共享 DB 与 locks）。
- 操作步骤：并发启动两个 serve（stdio、port 0），均等待 ready 并调用 `/api/info`。
- 预期结果：两个进程均就绪；均能读写共享 DB；无启动失败（迁移竞争后到者失败重试后成功也视为通过）。
- 优先级：P0

### TC-004: 非 Windows 平台 chmod 0o600 行为保持不变
- 前置条件：非 Windows 平台（或现有 unix 分支测试）。
- 操作步骤：运行 `packages/core` 的 database 相关测试。
- 预期结果：db/-wal/-shm 仍为 0o600。
- 优先级：P1

### TC-005: rg.exe 并发下载被锁串行化
- 前置条件：共享 `state/locks`；`global.bin` 无 rg；模拟两个并发解析。
- 操作步骤：并发触发 ripgrep 二进制安装（或单测模拟两个安装流程竞争同一 target）。
- 预期结果：最终 target 文件存在且校验通过；无 EPERM/半成品文件；后到者在锁释放后直接复用。
- 优先级：P1

### TC-006: service.json 并发写不互相覆盖 temp
- 前置条件：两个并发 `write()` 流程。
- 操作步骤：单测验证 temp 文件名含唯一后缀；并发写后文件内容为某一次完整写入。
- 预期结果：无 temp 互相覆盖；写入原子（rename）。
- 优先级：P2

### TC-007: 共享 locks 回归（cli.json / npm / repos）
- 前置条件：现有 Flock 相关测试。
- 操作步骤：运行 `packages/cli`、`packages/core`、`packages/util` 相关测试。
- 预期结果：全部通过（锁路径与机制未变）。
- 优先级：P1

### TC-008: 全量静态检查
- 前置条件：改动完成。
- 操作步骤：仓库根 `bun run check`；`packages/core`、`packages/util`、`packages/cli`、`packages/sdk` 分别 `bun test`。
- 预期结果：全部通过；代码中不再有 `FileMode` / `privateDirectory` / `sqlite-permissions` 的运行时引用。
- 优先级：P0

### TC-009: 既有改动保留
- 前置条件：基线快照 `.localdoc/审查记录/基线快照-多用户共享数据改造-20261022145041.patch`。
- 操作步骤：对比最终 diff 与基线快照。
- 预期结果：auto-login、server auth/fetch/cors 等既有改动完整保留。
- 优先级：P0

## 测试命令

- 静态检查（仓库根）：`bun run check`
- 单包测试：`cd packages/<core|util|cli|sdk> && bun test`（禁止从仓库根跑测试）
- Windows 手工验收：TC-001/TC-002/TC-003 用 `bun run dev` 或编译产物 `serve --stdio --port 0`

## 测试场景分类

框架代码（opencode fork 平台层改造），含少量通用验证（部署文档核对）。
