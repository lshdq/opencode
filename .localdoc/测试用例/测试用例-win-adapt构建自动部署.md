# 测试用例：win-adapt构建自动部署

## 测试范围

验证 win-adapt skill 对“构建即安全部署”的指令是否完整、一致且不会自动激活当前可执行文件。本次不执行真实构建或部署。

## 用例列表

### TC-001: 构建触发自动版本化部署
- 前置条件：读取修改后的 win-adapt skill。
- 操作步骤：检查 frontmatter 和“构建与部署”章节。
- 预期结果：构建属于触发语义，且构建成功后必须复制版本化文件。
- 优先级：P0

### TC-002: 使用产物实际版本命名
- 前置条件：部署命令已写入 skill。
- 操作步骤：检查命令中的版本获取和格式校验逻辑。
- 预期结果：通过构建产物 `--version` 获取版本，并只接受 `<semver>.w<N>` 格式。
- 优先级：P0

### TC-003: 构建失败不部署
- 前置条件：用嵌套 PowerShell 脚本块模拟构建脚本末尾的原生命令返回非零退出码，不运行真实构建或部署。
- 操作步骤：确认 skill 在当前 PowerShell 会话调用构建脚本并立即检查 `$LASTEXITCODE`；执行合成退出码传播验证。
- 预期结果：调用方保留原生命令的非零退出码并进入失败分支，复制步骤不会执行。
- 优先级：P0

### TC-004: 不自动激活当前版本
- 前置条件：安装目录存在当前 `opencode.exe`。
- 操作步骤：检查部署目标及安全约束。
- 预期结果：仅写入 `opencode.exe.<版本号>`，不覆盖 `opencode.exe`。
- 优先级：P0

### TC-005: 部署结果校验
- 前置条件：构建和复制成功。
- 操作步骤：检查部署后验证逻辑。
- 预期结果：确认目标文件存在并报告最终部署路径。
- 优先级：P1

### TC-006: 流程描述一致
- 前置条件：skill 修改完成。
- 操作步骤：检查“构建与部署”和“改造流程/验证”章节。
- 预期结果：两处都规定构建后自动执行版本化部署，无矛盾描述。
- 优先级：P1

## 测试命令

文档验证：读取 `.opencode/skills/win-adapt/SKILL.md`，逐项核对 TC-001 至 TC-006；TC-003 使用内存脚本块执行无文件副作用的 PowerShell 退出码传播验证；不执行真实构建或部署。
