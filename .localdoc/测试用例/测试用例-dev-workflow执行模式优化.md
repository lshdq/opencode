# 测试用例：dev-workflow 执行模式优化

## 测试范围

验证 dev-workflow SKILL.md 的阶段 2 确认、执行模式分支、Auto 连续执行、交互决策、决策记录命名和降级规则。

## 用例列表

### TC-001: 阶段 2 一次选择包含确认和模式
- 前置条件：已完成阶段 2 技术方案。
- 操作步骤：检查阶段 2 的确认规则和选项。
- 预期结果：包含 Auto、交互决策、不通过三种选择，确认方案与选择模式在同一次单选中完成；工具支持时设置 `custom: false`。
- 优先级：P0

### TC-002: Auto 模式切换提醒
- 前置条件：用户选择确认方案并使用 Auto 模式，当前 agent 分别为 build 和具备完整能力的自定义 agent。
- 操作步骤：检查两种路径获批后的处理规则。
- 预期结果：两种路径都立即提醒用户开启客户端自动接受权限，不依赖 agent 切换。
- 优先级：P0

### TC-003: Auto 模式连续执行
- 前置条件：已进入 Auto 模式。
- 操作步骤：检查阶段 3-7 和强制规则。
- 预期结果：除硬阻塞外持续执行至任务完成，不因普通决策点暂停。
- 优先级：P0

### TC-004: Auto 模式自主决策并记录
- 前置条件：Auto 模式执行中出现已确认方案未覆盖的决策点。
- 操作步骤：检查决策处理和记录模板。
- 预期结果：AI 比较可行方案、选择最优解，并记录阶段、背景、选项、选择、理由和影响。
- 优先级：P0

### TC-005: 决策记录时间戳命名
- 前置条件：Auto 模式进入阶段 3。
- 操作步骤：检查决策记录路径和命名规则。
- 预期结果：路径为 `.localdoc/决策项/决策记录-<功能名称>-<yyyyMMddHHmmss>.md`，不包含会话 ID，同一工作流只生成一次时间戳；以仅当不存在时创建的原子或排他语义创建，并发冲突时逐秒递增后重试。
- 优先级：P0

### TC-006: 交互决策模式行为
- 前置条件：用户选择确认方案并使用交互决策模式。
- 操作步骤：检查后续决策处理规则。
- 预期结果：阶段 3 等待用户审核文档；后续遇到已确认内容未覆盖的实质决策点时暂停并询问用户。
- 优先级：P0

### TC-007: 硬阻塞边界
- 前置条件：Auto 模式执行中遇到权限、环境或需求矛盾问题。
- 操作步骤：检查硬阻塞定义和处理规则。
- 预期结果：仅在无法继续执行时询问用户；可自主解决的问题不视为硬阻塞。
- 优先级：P1

### TC-008: plan_exit 与降级流程
- 前置条件：分别模拟 plan_exit 可用、不可用和 question 不可用。
- 操作步骤：检查模式处理规则。
- 预期结果：三选一优先由 question 完成；plan_exit 只负责切换；工具不可用时可用普通对话完成，不跳过确认。
- 优先级：P1

### TC-009: 无效确认结果
- 前置条件：阶段 2 使用 question 确认。
- 操作步骤：分别检查自定义答案、取消和空回答的处理规则。
- 预期结果：三种情况均视为未批准并停留在阶段 2，不得进入开发。
- 优先级：P0

### TC-010: plan_exit 拒绝切换
- 前置条件：三选一已经批准方案，但 plan agent 的 plan_exit 返回 No。
- 操作步骤：分别检查方案未修改后重试切换，以及方案发生实质修改后的处理规则。
- 预期结果：保持 plan agent 并等待用户，不进入阶段 3；尚未进入阶段 3 时，方案未修改可直接重试 plan_exit，方案实质修改后必须重新三选一确认；进入阶段 3 后的新实质决策只按所选模式处理，不自动使批准失效。
- 优先级：P1

### TC-011: 自定义可编辑 agent
- 前置条件：当前 agent 名称不是 build，但具备编辑、命令、子智能体和验证能力。
- 操作步骤：检查模式处理规则。
- 预期结果：阶段 2 获批后直接进入阶段 3，不产生虚假的手动切换硬阻塞。
- 优先级：P1

### TC-012: 基本验证失败重试
- 前置条件：lint、typecheck 或 build 首次失败。
- 操作步骤：分别检查修复成功和最终无法修复的处理规则。
- 预期结果：主智能体自主定位、修复并重试，不询问用户是否修复；最终无法修复时记录原因，仍进入独立测试和代码审查并完成所有不依赖失败项的工作。
- 优先级：P0

### TC-013: 局部测试环境不可用
- 前置条件：接口测试依赖的外部环境不可用，但代码审查和其他测试仍可执行。
- 操作步骤：检查阶段 6 结果处理和硬阻塞规则。
- 预期结果：记录未执行项，继续其他测试和代码审查，最后才汇报验收硬阻塞。
- 优先级：P0

### TC-014: 决策生命周期和排除项
- 前置条件：Auto 模式包含阶段 2 已批准的 AI 技术选型、用户明确选择、唯一修复路径和普通编码细节。
- 操作步骤：检查决策记录规则。
- 预期结果：补录阶段 2 的 AI 实质决策并追加后续 AI 实质决策；不记录用户选择、唯一修复路径或普通编码细节。
- 优先级：P0

### TC-015: 独立测试失败返回主流程
- 前置条件：独立测试子智能体发现失败用例，分别模拟 question 可用和不可用。
- 操作步骤：检查 dev-workflow prompt、test-workflow 被调用分支和结果处理规则。
- 预期结果：两种情况下子智能体都不询问用户，完成仍可行的测试和报告并返回，由主智能体修复和复测。
- 优先级：P0

### TC-016: 全局开发流程一致性
- 前置条件：读取全局 AGENTS.md 和 dev-workflow SKILL.md。
- 操作步骤：比较阶段 3 审核和后续模式规则。
- 预期结果：全局规则委托 dev-workflow 按 Auto/交互决策模式确定是否审核，不与 Auto 连续执行冲突。
- 优先级：P0

### TC-017: 独立测试补充测试代码
- 前置条件：独立测试子智能体发现现有测试覆盖不足。
- 操作步骤：比较 dev-workflow 子智能体 prompt 与 test-workflow 的持久化测试规则。
- 预期结果：子智能体不得修改生产代码，但允许并应当补充或修改可持久化测试代码，不因父流程约束跳过补测。
- 优先级：P0

### TC-018: 测试场景枚举一致性
- 前置条件：读取 dev-workflow 的测试用例模板、子智能体参数和 test-workflow 输入说明。
- 操作步骤：比较各处测试场景枚举。
- 预期结果：各处统一支持“框架代码 / 业务代码 / 通用 / 文档验证”四种场景。
- 优先级：P1

### TC-019: 文档验证场景路由
- 前置条件：测试场景为文档验证且测试命令为空。
- 操作步骤：检查 test-workflow 的场景路由和阶段执行条件。
- 预期结果：跳过单元测试和框架/业务/通用集成测试，只执行只读文档验证并输出报告。
- 优先级：P0

### TC-020: 业务测试部署前置处理
- 前置条件：父流程调用独立测试子智能体，目标服务部署状态未知或环境不可用。
- 操作步骤：检查业务代码场景和父流程调用规则。
- 预期结果：子智能体不直接询问用户，记录未执行项及原因，完成其他可执行测试后返回父流程。
- 优先级：P0

### TC-021: 测试代码变更纳入审查
- 前置条件：独立测试在当前项目或外部测试仓库新增、修改了测试代码。
- 操作步骤：检查测试报告模板、强制规则和阶段 7 审查范围。
- 预期结果：报告列出全部测试文件及所属仓库，主智能体维护跨轮次累计变更并全部纳入代码审查，必要时按仓库分别审查；任务开始前已有改动被可靠排除。
- 优先级：P0

### TC-022: 文档审核实质反馈
- 前置条件：交互决策模式的阶段 3 文档审核反馈改变功能范围、架构、兼容策略或验收标准。
- 操作步骤：检查阶段 3 审核处理规则。
- 预期结果：原批准和模式选择失效，返回阶段 1 或阶段 2，并重新执行三选一确认；只有非实质文字修订留在阶段 3。
- 优先级：P0

### TC-023: 审查修复后的质量收敛
- 前置条件：独立审查发现阻塞或应改项，主智能体完成修复。
- 操作步骤：检查阶段 7 结果处理流程。
- 预期结果：重新执行受影响的基本验证、独立测试和独立审查；测试产生的新变更继续纳入审查，直至测试和审查同时通过。
- 优先级：P0

### TC-024: 修复方案的模式处理
- 前置条件：测试或审查问题必须修复，且存在多个会实质影响架构、兼容性或范围的修复方案。
- 操作步骤：分别检查 Auto 模式和交互决策模式。
- 预期结果：不询问是否修复；Auto 模式自主选择并记录具体方案，交互决策模式询问用户选择具体方案。
- 优先级：P0

### TC-025: 业务部署与测试闭环
- 前置条件：业务接口测试需要部署，分别处于 Auto 模式和交互决策模式。
- 操作步骤：检查部署环境限制、模式分支和部署后处理。
- 预期结果：只使用已批准的非生产环境；Auto 自主选择并记录，交互模式对未批准决策询问；部署当前修复制品并校验版本与就绪后重新测试，后续修复影响部署组件时重新构建、部署和复测。
- 优先级：P0

### TC-026: 审查上下文和文档测试报告
- 前置条件：阶段 6 完成文档验证或修改了测试代码。
- 操作步骤：检查测试报告模板和阶段 7 子智能体 prompt。
- 预期结果：报告包含文档验证结果、测试环境/制品和测试代码变更；审查 prompt 包含需求、测试用例、批准方案、决策、基本验证、最近测试报告和累计精确审查范围。
- 优先级：P1

### TC-027: 父流程补测不递归
- 前置条件：阶段 6 独立测试子智能体需要新增或修改持久化测试代码。
- 操作步骤：检查全局开发流程与父流程内补测例外。
- 预期结果：测试代码修改作为当前 dev-workflow 的组成部分直接执行，不递归启动 dev-workflow；生产缺陷交回主智能体。
- 优先级：P0

### TC-028: 业务修复版本复测
- 前置条件：已部署业务接口测试失败，主智能体修复了影响部署组件的生产代码。
- 操作步骤：检查修复后的收敛循环和测试报告制品信息。
- 预期结果：构建并部署当前修复制品，校验预期与实际制品标识和就绪状态后，再由独立测试智能体执行接口复测。
- 优先级：P0

### TC-029: 脏工作区与累计审查范围
- 前置条件：任务开始前存在用户未提交改动，且多轮测试修改当前或外部仓库中的跟踪、未跟踪或忽略文件。
- 操作步骤：检查阶段 4 基线记录、累计变更维护和阶段 7 审查范围。
- 预期结果：准确排除既有改动，累计纳入本流程各轮次和各仓库的全部变更；普通 diff 无法隔离时提供精确文件/hunk 范围。
- 优先级：P0

## 测试命令

文档规则验证，无自动化构建命令；通过逐项读取和关键词检查验证。
