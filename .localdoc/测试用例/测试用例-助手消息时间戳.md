# 测试用例：助手消息时间戳

## 测试范围

- TUI 会话页 AssistantMessage footer 的时间戳显隐行为。
- 不覆盖：用户消息时间戳（已有逻辑）、Desktop/Web App、配置系统。

## 用例列表

### TC-001: 开关关闭时不显示助手消息时间（默认行为回归）
- 前置条件：kv.json 中 timestamps 为 hide（默认或已关闭）。
- 操作步骤：启动 TUI，进入一个含助手消息的会话。
- 预期结果：助手消息 footer 为 `▣ <Agent> · <model> · <duration>`，无时间。
- 优先级：P0

### TC-002: 开启开关后助手消息显示时间
- 前置条件：TUI 会话中有至少一条助手消息。
- 操作步骤：输入 `/timestamps` 开启，观察助手消息 footer。
- 预期结果：footer 变为 `▣ <Agent> · HH:mm · <model> · <duration>`，颜色为 textMuted；用户消息时间同时显示（原有行为）。
- 优先级：P0

### TC-003: 关闭开关后助手消息时间隐藏
- 前置条件：开关处于 show 状态。
- 操作步骤：再次输入 `/timestamps`。
- 预期结果：助手消息 footer 恢复无时间；用户消息时间同时隐藏。
- 优先级：P0

### TC-004: 重启后开关状态持久化
- 前置条件：开关已开启。
- 操作步骤：退出 TUI 再重新启动，进入同一会话。
- 预期结果：助手消息仍显示时间（kv.json 持久化生效）。
- 优先级：P1

### TC-005: 跨天消息显示日期
- 前置条件：会话中包含昨天或更早的助手消息，开关开启。
- 操作步骤：滚动到历史助手消息。
- 预期结果：footer 时间部分显示 `HH:mm · <日期>` 格式（Locale.todayTimeOrDateTime 行为）。
- 优先级：P1

### TC-006: 中断/错误消息 footer 兼容
- 前置条件：存在 MessageAbortedError 的助手消息，开关开启。
- 操作步骤：观察该消息 footer。
- 预期结果：时间与 ` · interrupted` 均正常显示，布局不破坏。
- 优先级：P1

### TC-007: typecheck 通过
- 前置条件：改动已合入工作区。
- 操作步骤：在 `packages/tui` 下执行 `bun typecheck`。
- 预期结果：无类型错误。
- 优先级：P0

## 测试命令

```bash
# 类型检查（必须在包目录下执行，不能在仓库根目录）
cd packages/tui && bun typecheck
```

UI 行为用例（TC-001~006）为 TUI 交互验证，无现成自动化测试框架覆盖该组件；以 typecheck + 代码静态审查 + 手动场景核对（对照实现代码确认显隐逻辑与格式）为主。
