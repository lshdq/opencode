# 测试用例：后台任务完成通知

## 测试范围

覆盖 App 系统通知和 TUI attention 通知在子智能体、嵌套子智能体、后台 shell 尚未完成时的延迟与去重行为。

## 用例列表

### TC-001: 子智能体运行时延迟主会话通知
- 前置条件：主会话存在一个正在运行的子智能体。
- 操作步骤：先发送主会话执行完成事件，再发送子智能体完成事件。
- 预期结果：主会话完成事件后无完成通知；子智能体结束后主会话收到一次完成通知。
- 优先级：P0

### TC-002: 后台 shell 运行时延迟主会话通知
- 前置条件：主会话关联一个正在运行的后台 shell。
- 操作步骤：先发送主会话执行完成事件，再发送 shell 退出事件。
- 预期结果：shell 退出前无主会话完成通知；shell 退出后主会话收到一次完成通知。
- 优先级：P0

### TC-003: 多个后台任务只触发一次主会话通知
- 前置条件：主会话存在多个子智能体或 shell。
- 操作步骤：主会话完成后依次结束后台任务，并重复发送一个结束事件。
- 预期结果：所有后台任务结束后主会话仅收到一次完成通知。
- 优先级：P1

### TC-004: 嵌套子智能体完成顺序正确
- 前置条件：子智能体下存在正在运行的嵌套子智能体。
- 操作步骤：依次结束主会话、父子智能体和嵌套子智能体。
- 预期结果：主会话通知等待整个后代任务树完成，既有子智能体提示保持不变。
- 优先级：P1
