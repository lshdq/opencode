# 测试用例：新会话自动标题竞态修复

## 测试范围

覆盖服务端新会话标题生成、事件序列竞态、手动改名保护和标题模型失败行为。测试 owner 为 `packages/core/test/session-runner.test.ts` 中已有 SessionRunnerLLM 标题场景。

## 用例列表

### TC-001: 首轮响应事件抢先提交后仍能完成自动改名
- 前置条件：新建未命名根会话，标题 agent 可用。
- 操作步骤：提交首条用户消息；让标题模型返回标题；在第一次自动改名提交尝试前提交首轮助手事件；等待会话处理完成。
- 预期结果：会话最终标题为模型生成标题，不是 `New session...`；标题模型只调用一次。
- 优先级：P0

### TC-002: 连续首轮事件不会造成无限改名重试
- 前置条件：新建未命名根会话，首轮响应持续产生事件。
- 操作步骤：触发标题生成并制造多个事件序号变化；等待标题提交完成。
- 预期结果：改名重试次数有界，最终成功或安全保持默认标题；无重复标题模型请求。
- 优先级：P1

### TC-003: 手动改名优先于自动标题
- 前置条件：标题模型请求已开始但尚未提交。
- 操作步骤：手动将会话改名，随后释放标题模型响应。
- 预期结果：最终标题保持手动标题，自动标题不覆盖。
- 优先级：P0

### TC-004: 标题模型失败保持现有行为
- 前置条件：标题 agent 可用但标题模型返回 provider/transport 错误。
- 操作步骤：执行首次标题生成，再按现有入口触发后续重试。
- 预期结果：失败时保持默认标题；后续可再次尝试并在恢复后生成标题。
- 优先级：P1
