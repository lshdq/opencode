# opencode 1.18.11.w4 版本说明

- **版本**：`1.18.11.w4`（基准版本 `1.18.11` + 适配号 `4`）
- **基准**：upstream/dev v1.18.11（与 w3 相同 fork 点，未合并新的上游提交）
- **日期**：2026-08-04
- **状态**：改动完成，已构建冒烟通过

## 概述

修复 ripgrep 二进制供给在 Windows 上的失败链。该失败导致 **skill 加载多次失败**（skill 工具依赖 ripgrep 列举 skill 文件），同时波及 grep/glob 等一切依赖 ripgrep 的功能。

## 根因

1. 本机 PATH 与 `~/.cache/opencode/bin` 均无 `rg.exe`，触发自动供给：下载 zip 后用 PowerShell `Expand-Archive` 解压（`packages/core/src/ripgrep/binary.ts`）。
2. 解压优先选 `powershell.exe`（5.1）。opencode 进程从 pwsh 7 启动，继承了 pwsh7 的 `PSModulePath`（含 pwsh7 模块目录 `...\Microsoft.PowerShell_7.6.4.0_x64__8wekyb3d8bbwe\Modules`）。
3. powershell 5.1 按该路径**先找到 PS7 版 `Microsoft.PowerShell.Archive`（v1.2.5），5.1 无法加载**，报 `CouldNotAutoloadMatchingModule`，解压失败。
4. `Effect.cached` 缓存该失败，进程内后续所有 ripgrep 调用全部失败；每个新进程重试又失败，表现为"多次出现 skill 加载失败"。
5. 交互式 pwsh 会话无法复现：pwsh7 派生 powershell.exe 时会重置 PSModulePath 为 5.1 默认值；bun/node 派生则原样透传。

## 修复

### S1 ｜ ripgrep zip 解压改用 tar.exe 优先（binary.ts）

- **方案**：zip 解压优先用 Windows 10+ 自带的 `tar.exe`（bsdtar 支持 zip），完全绕开 PowerShell；无 tar 时兜底顺序改为 `pwsh.exe` → `powershell.exe`，选用 5.1 时从子进程 env 剥离 `PSModulePath` 并在命令中强制 UTF-8 输出（错误日志不再乱码）。
- **附带**：已下载的 zip 复用（不重复下载）；解压失败时删除 zip，下次自动重下。
- **文件**：`packages/core/src/ripgrep/binary.ts`
- **验证**：tar 路径与"5.1 + 剥离 PSModulePath"兜底路径均端到端解压成功（后者即原先失败场景）。

### S2 ｜ archive.ts 同款加固

- **方案**：LSP/自更新用的 `extractZip` 同样加 tar.exe 优先分支；5.1 兜底时把 `PSModulePath` 钉死为 5.1 系统模块目录，命令强制 UTF-8 输出。
- **文件**：`packages/opencode/src/util/archive.ts`

### S3 ｜ skill 工具对 ripgrep 失败降级

- **方案**：skill 工具列举 skill 文件失败时降级为空列表（中止信号除外），不再阻断 skill 正文加载——文件列表只是补充信息。
- **文件**：`packages/opencode/src/tool/skill.ts`
- **验证**：新增测试（`LayerNode.compile` replacements + `Layer.mock` 使 ripgrep 失败），断言 skill 内容正常返回、无文件列表；`test/tool/skill.test.ts` 3 个用例全部通过。

## 部署注意

- 已部署版本化文件 `D:\Program\opencode\opencode.exe.1.18.11.w4`；激活（替换 `opencode.exe`）需退出所有 opencode 实例后执行。
- 已手动将 `rg.exe` 放入 `~/.cache/opencode/bin`（立即止血，新进程直接命中，不再走解压路径）。
- 旧进程内 `Effect.cached` 缓存了供给失败，重启后才会生效。
