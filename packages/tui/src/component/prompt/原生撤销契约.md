# Prompt 应用层撤销契约与 OpenTUI 适配边界

## 当前方案：owned undo/redo，不再配对原生 checkpoint

主代理在 Auto 模式选择应用层拥有历史，拒绝扩展到 OpenTUI native fork。以下为当前实现，不再沿用“每个 Zig checkpoint 配一个 metadata 快照”的旧设计：

1. 包装全部原有 `editBuffer` 编辑方法及 `editorView.deleteSelectedText`；快捷键、剪切、粘贴展开、autocomplete 和直接 TS API 调用使用同一入口。
2. 在受控操作前捕获完整文本、逻辑光标、纯数据 metadata 快照和纵向导航信息，原生方法只负责当次编辑；操作后立即清原生历史，不读取/比较 depth，不调用原生 undo/redo。
3. 每次有效受控调用是一个逻辑步骤。普通 forward Delete **是一**步，不再暴露内部双 checkpoint；EOF/零宽 forward Delete 也记录一个显式删除意图，避免下一次 Ctrl+Z 越过该意图撤掉前一次粘贴。
4. 其他同时不改变文本与光标的空操作不记步、不清 redo；包括空 insert、BOF backspace、空/无效 range、无 selection。若 TS 包装错误移动了 mark，立即恢复本次捕获的当前 metadata，而非复活更旧的历史。宽字符内部删除即便文本相同，若改变光标仍可撤销。
5. 同文 replace 仍是逻辑步骤，因为它会清除原 metadata。选择替换保留 deleteSelectedText + insert 两个公开调用边界，原 F-02 两次 undo 契约不变。
6. undo/redo 从应用栈选取明确的状态，使用保存的底层 `setText` 恢复文本，清选区和旧 marks，再恢复 metadata 与光标。离开当前状态前重新捕获 metadata，覆盖插入返回后才附加的 payload 和纯 metadata 移除，不按标签或文本相等查找历史。
7. Prompt restore 复制可变 part/mention/source 位置，避免将保留快照直接作为 Solid store 的可变 backing object。不可变字符串共享。
8. `setText/setTextOwned/clear/clearHistory` 丢弃 owned undo/redo；前三个也清 marks，clearHistory 保留当前 payload。clear 显式调用底层 setText("")，不再依赖 native clear 的历史语义。

### 光标与选区

- 捕获的是 native 逻辑行/显示列，不是 JS 字符串下标；恢复不使用会跳过虚拟标记的 setCursorByOffset。
- 撤销/重做清除过期选区，保持 Ctrl+Z 的非选区恢复语义；选择替换恢复删除前的 caret，redo 恢复插入后的 caret。
- 记录连续逻辑/视觉纵向导航的起点和有效行差，恢复时重放非文本导航，使长行→短行后的 desired-column 在下一次上下移动时保留。显式定位、横向移动、鼠标局部选区终止旧导航链。
- 显式定位也可能发生在一次纵向移动**内部**（例如 extmarks 把 caret 吸附到虚拟标记边界）。`navigate` 增加导航修订号，外层 `vertical` 发现修订变化即保留这次失效，不覆盖回调用前的anchor；下一次纵向移动从吸附后的实际位置重新锚定。即使此前没有导航链也必须识别，不能仅比较旧/新navigation是否同为undefined，更不能跨此边界只累计净行差。
- 重排/改变宽度后如果原导航路径不再落到保存位置，以保存的逻辑 caret 为准，不把光标留在错误位置。

### 256 步 + 16 MiB 有界产品契约

- 上限从“256 个 native checkpoint”调整为 **最多 256 个应用逻辑步骤**；undo/redo 两栈共享此上限。
- 另设 **16 MiB 逻辑保留预算**，覆盖历史两端文本、metadata（含隐藏粘贴/data URL）和结构估算。字符串按 UTF-16 两字节/码元计费、对象按固定结构开销估算；不是 JS heap/RSS 或原生内存的精确测量。
- 对相同的不可变字符串，不仅预算去重，还通过有界字符串池共享实际引用；池随淘汰/reset/cleanup 清理，不能变成额外的无界缓存。
- 当前使用有界全文快照而非逆 patch：每步读取文本 O(n)，不同大草稿会更快触及字节上限。超额从 undo 最旧端淘汰完整条目；若只剩 redo，则从远端裁剪，保留可连续恢复的近端，绝不跨缺口撤销。单个条目超预算时丢弃该条目及此前不可连续到达的历史，当前草稿不截断。
- 提交/清空及组件 cleanup 释放应用快照/字符串池。原生文本 buffer 的当前编辑存储由 OpenTUI 自己管理，不声称整个 renderer 内存被限制为 16 MiB。
- 读取历史文本使用公开 RenderLib 的 byteSize + getText，而非有 1 MiB 输出上限的 EditBuffer.getText，防止 restore 截断大草稿。这个修复不宣称消除了其他 OpenTUI 调用方既有的读取上限。

### TS extmarks 适配

OpenTUI 0.5.10 没有公开的 extmarks-history reset/disable。因此仅在此版本的 TS 控制器边界，清 `history` 并临时禁用 `saveSnapshot`；保留实时 mark 跟随编辑的包装，不使用其 undo/redo 快照。cleanup 清 history 并恢复方法。这里依赖两个 TS 成员名称，**不读取原生私有结构/内存偏移，不改 node_modules 或 lock**。升级时必须核查或替换此适配点。测试直接证明 native 与 extmarks 的 undo/redo 历史始终为空。

## 已核对的原生规则（历史根因资料，不再用于生产配对）

| 操作 | checkpoint 规则（不是可见文本变化次数） | 源码 |
|---|---|---|
| insertChar / insertText | 空输入 0，非空 1（包括零宽字符） | edit-buffer:375-435；FFI insertChar 同样调用 insertText |
| deleteRange | u32 转换后两坐标相同 0；不同 1。坐标有效性验证在 checkpoint 之后 | edit-buffer:438-473 |
| deleteChar / forward | 先无条件存 1；若继续调用 deleteRange，再存 1。EOF/空文本为 1，普通字符/跨行通常 2；零宽单位可能提前结束，仅 1 | edit-buffer:503-528 |
| forward 虚拟标记 | 无 selection 且位于虚拟标记起点时，TS 改走原始 deleteRange，只存 1；有 selection 时此特例不生效 | lib/extmarks.ts wrapDeletion |
| deleteCharBackward | BOF/原生 previous width=0 时为 0；否则 deleteRange 为 1，宽字符中间列可不变文本但仍存 1 | edit-buffer:475-501 |
| backward 虚拟标记 | 标记末端且无 selection 时走原始 deleteRange，1 | lib/extmarks.ts wrapDeletion |
| newLine | 插入非空换行，1 | lib.zig editBufferNewLine / edit-buffer insertText |
| deleteLine | 空单行 0；非空单行、多行中的有效行 1 | edit-buffer:654-691 |
| editorView.deleteSelectedText | 无 selection 或坐标转换失败为 0；否则走 deleteRange，非空范围 1 | editor-view:770-796 |
| replaceText / replaceTextOwned | 相同文本也存 1 | edit-buffer:634-648 |
| setText / setTextOwned | 清 native history | edit-buffer:615-631 |
| clearHistory | 清 native history，但不删除当前文本/metadata | edit-buffer:794-796 |
| clear | **原生不清历史**。Prompt 若要把 clear 定为重置，须同时显式 clearHistory，而非只清平行栈 | edit-buffer:798-802 |

`rope.zig` 的 `store_undo` 每次 push，不按相同文本/root 合并。一次 forward 的两个 checkpoint 都位于删除之前；旧 binder 因此错位。当前 owned 层有意定义为一个逻辑步骤，并清除这两个原生 checkpoint。

## 原生 API 限制（为何不再配对）

- 公开接口只有 `canUndo/canRedo` 布尔值，无 depth、checkpoint identity、begin/end group。
- undo 返回 `cursor:<row>:<col>:<desired_col>` 是光标 metadata，不是操作 ID；相同位置可以重复，不能作为唯一键。
- TS extmarks 自有 snapshots 也不等于 Zig checkpoint 数量，不能作为 oracle。
- `content-changed` 原生事件并非在 mutator 返回前同步通知，不能据同步事件数确定分支。
- forward 的第二个 checkpoint 依赖 `text-buffer-iterators.zig:getCursorUnitBoundsAt/getGraphemeWidthAt`，不能仅用 col < EOL 判断。字符宽度模式、chunk 边界、零宽字符、宽字符中间列都影响分支。
- 生产代码中不执行探测性 undo/redo，也不移动真实光标探测宽度/步数。恢复快照中的纵向导航只用于恢复真实 caret 状态。
- 内存分配失败等被 FFI 吞掉的 native error 不提供完整成功结果；owned 层记录调用前后实际状态，但自动测试不覆盖原生 OOM。

## 持久化验证入口

在 `packages/tui` 运行（App 测试须隔离 XDG / OPENCODE_TEST_HOME）：

```text
bun test test/prompt-native-history-contract.test.ts
bun test --timeout 30000 test/prompt-delete-history.test.ts test/prompt-owned-history.test.ts
```

- native oracle 和 bound 各自运行同一组 54 个输入场景。raw 的 checkpoint 期望原样保留；bound 按新的逻辑步数，额外验证完整文本与 caret 恢复，不能再要求其匹配 Zig 数量。
- fixture 先生成已有 undo，再创建 redo 分支；直接设置 editorView selection，避免未聚焦/未布局的 selectAll 导致准备步骤未发生。
- App 回归覆盖 Ctrl+D EOF、连续 EOF、已有 redo、字符/换行，以及全部 54 个 mutator 输入场景的 undo/redo/branch/reset；同时检查生产 Selection.copy 和真实 Client HTTP POST，而非只看标签文本。
- owned-history 覆盖字节预算裁剪、1 MiB 共享 payload、超预算单条边界、超过 getText 上限的文本恢复、native/extmarks 零历史、caret/desired-column、cleanup。
- `prompt-navigation-history.test.ts` 用真实Prompt默认方向键建立不中断导航对照；正/反向跨virtual mark、首次移动吸附、纯长短行及显式buffer/view定位分别验证undo/redo之后的下一次方向键落列，并检查实际copy/POST。该矩阵覆盖R-04，不能用“恢复瞬间caret相同”替代后续desired-column验证。
